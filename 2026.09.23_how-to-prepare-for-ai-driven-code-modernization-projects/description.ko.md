## 이 글이 뭔가요
Anthropic 포워드 디플로이드 엔지니어들이 Notes from the Field 시리즈로 쓴 글로, 핵심 시스템과 규제 산업
기업이 에이전트 기반 코드 현대화를 준비하는 방법을 다룹니다. 이제 에이전트가 조직의 리뷰 속도보다 빠르게
변경을 써내기 때문에, 글은 조직 차원의 6단계 준비를 제시합니다. 목표 정의, 인증서 작성, 승격 정책 수립,
사전 준비물 갖추기, 에이전트 워크플로 구축·개선, 현대화 실행이며 토큰 비용에 대한 메모가 덧붙습니다.

## 언제 유용한가요
- 변경 관리·감사·규제를 거치는 시스템의 버전 업, 스택 전환 재작성, 재구축 범위를 정할 때
- 현대화 과정에서 동작을 바꿔도 되는지를 두고 이해관계자 의견이 갈릴 때
- 코드 작성이 아니라 리뷰와 승인이 병목이 되었을 때
- 착수 전에 리더십이 비즈니스 근거나 토큰 비용 추정을 요구할 때

## 핵심 포인트
- 현대화는 세 종류입니다. **업리프트**(같은 스택 버전 업), **트랜스폼**(동작은 고정하고 스택 교체),
  **리이매진**(동작을 바꾸며 재구축, 서면 명세 필요). 선택은 초기에 확정합니다.
- 코드베이스를 매핑하고(code modernization 플러그인의 `assess`, `map`, `extract-rules`) 인터뷰로 빈틈을
  메우며, 프로젝트 근거는 주로 **리스크 감소**로 세웁니다.
- **인증서**는 모든 변경이 충족해야 하는, 사람 없이 자동 확인 가능한 조건의 집합입니다. 테스트, 커버리지,
  성능 범위, 새 컨텍스트에서의 Claude 적대적 리뷰, 출력 동등성, 스테이징 관찰, 보안 스캔 등. 리뷰어와 함께
  작성하고, 부족한 증거는 Claude로 만듭니다.
- **승격 정책**은 영향 범위와 에이전트 신뢰도로 사람 리뷰 깊이를 등급화하고, 반복 플래그는 원인에서 고치며,
  SME 시간은 가장 위험한 변경에 씁니다. 책임을 공유하도록 리더십이 사전에 공표해야 합니다.
- 사전 준비물은 환경, CI/CD, 리뷰 인력, 보안(최소 권한, 비밀값·개인정보 마스킹, PR-트랜스크립트 추적성)에
  걸쳐 있습니다.
- 워크플로는 code modernization 플러그인에서 시작하고, 문제가 생기면 개별 변경이 아니라 워크플로를 고칩니다.
  파티션 하나를 끝까지 시범 적용한 뒤 확장합니다. 업리프트는 파티션 단위로 제자리 현대화가 가능합니다.
- 비용: 파일럿에서 토큰을 측정해 하한을 추정하고, 비싼 검증은 싼 게이트 뒤에 두며, 기계적 작업에는 Sonnet
  같은 모델을 씁니다.
