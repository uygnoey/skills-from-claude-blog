## この記事について
Anthropic のフォワードデプロイドエンジニアによる Notes from the Field シリーズの記事で、基幹システムや規制業種の
企業がエージェント主導のコードモダナイゼーションに備える方法を扱います。エージェントは組織のレビュー速度を
上回るペースで変更を書けるようになったため、記事は組織側の 6 ステップを示します。ターゲットの定義、証明書の作成、
昇格ポリシーの設定、前提条件の整備、エージェントワークフローの構築と改善、モダナイゼーションの実行で、
トークンコストについての補足も付きます。

## どんなときに役立つか
- 変更管理・監査・規制当局を通るシステムのバージョンアップ、スタック移行、再構築の範囲を決めるとき
- モダナイゼーション中に振る舞いを変えてよいかで関係者の意見が割れているとき
- コードを書くことではなく、レビューと承認がボトルネックになっているとき
- 着手前に経営層がビジネス上の根拠やトークンコストの見積もりを求めているとき

## 主なポイント
- モダナイゼーションは 3 種類。**アップリフト**(同一スタックのバージョンアップ)、**トランスフォーム**
  (振る舞いを固定してスタックを変更)、**リイマジン**(振る舞いを変えて再構築、書面の仕様が必要)。選択は早めに確定します。
- コードベースをマッピングし(code modernization プラグインの `assess`、`map`、`extract-rules`)、
  インタビューで補い、主に**リスク低減**でプロジェクトを正当化します。
- **証明書**は、すべての変更が満たすべき、人手なしで自動確認できる条件の集合です。テスト、カバレッジ、性能の上限、
  新しいコンテキストでの Claude による敵対的レビュー、出力の同一性、ステージングでの観察、セキュリティスキャンなど。
  レビュー担当者と一緒に作り、足りない証拠は Claude に作らせます。
- **昇格ポリシー**は影響範囲とエージェントの確信度で人によるレビューを階層化し、繰り返すフラグは原因から直し、
  SME の時間を最もリスクの高い変更に充てます。責任を共有するため、経営層が事前に示すべきです。
- 前提条件は環境、CI/CD、レビュー体制、セキュリティ(最小権限、シークレットと個人情報のマスキング、PR と
  トランスクリプトのトレーサビリティ)に及びます。
- ワークフローは code modernization プラグインから作り、問題が出たら個々の変更ではなくワークフローを直します。
  ひとつのパーティションでエンドツーエンドに試してからスケールします。アップリフトはパーティション単位で
  インプレースのモダナイズも可能です。
- コスト: パイロットでトークンを計測して下限を見積もり、高価なチェックは安価なゲートの後ろに置き、機械的な
  作業には Sonnet などのモデルを使います。
