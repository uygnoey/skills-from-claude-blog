## 이 글이 뭔가요
Anthropic 일본 팀의 BDR(비즈니스 개발 담당자)이 자신의 인바운드 리드 큐를 정리하고, 일본어·영어
고객 이메일 초안을 쓰고, Salesforce를 최신 상태로 유지하는 예약 실행 에이전트 "나카마(Nakama)"
플릿을 설명합니다. 처음에는 Claude에서 각 에이전트를 스킬 + 예약 작업 + 공유 폴더 조합으로
프로토타이핑했고, 이후 플릿 전체를 Claude Managed Agents(베타)로 옮겼습니다. 정해진 루틴을 벗어나는
후속 작업은 Slack의 Claude Tag에 넘깁니다.

## 언제 유용한가요
- 매일 반복되는 업무(리드 라우팅, 자격 판단, 답장 초안, CRM 업데이트, 후속 조치)가 여러 개의
  단일 목적 에이전트로 나눌 만큼 커졌을 때
- Claude에서 프로토타이핑한 에이전트가 많아져서, 열려 있는 아무 대화창에서 스킬을 수정하는 방식으로는
  더 이상 추적이 안 되고, 에이전트를 한 곳에서 한 번만 정의하고 변경 이력을 보고 싶을 때
- 노트북을 닫아둔 동안에도 예약 실행이 돌아가야 하고, 여러 에이전트가 하나의 메모리를 공유하며,
  외부 서비스 자격증명을 범위 제한·취소 가능한 형태로 다뤄야 할 때
- 매일 돌아가는 에이전트의 비용을, 각 에이전트의 업무에 맞는 모델과 추론(effort) 수준으로 통제하고 싶을 때

## 핵심 포인트
- 에이전트 하나당 업무 하나. 플릿은 6개로 구성됩니다. Furiwake(인바운드 큐를 담당자별로 배분),
  Sabaki(저자에게 배정된 리드 자격 판단 + 첫 접촉 이메일 초안), Henji(매시간 받은 편지함을 확인하고
  일본어/영어로 답장 초안 작성), Shoudan(Salesforce에 업데이트 반영), Nokori(퇴근 시점에 회의 요약과
  후속 조치 초안), 그리고 다른 에이전트의 지시문과 공유 지식 베이스를 갱신하는 코디네이터.
- 먼저 Claude에서 프로토타이핑: 에이전트당 스킬 하나, 스킬당 예약 작업 하나, 지식 베이스 역할의 공유
  폴더 하나. 직접 추적하기 힘들 만큼 에이전트가 늘어나면 Managed Agents로 옮깁니다.
- Managed Agents에서는 스킬이 에이전트의 시스템 프롬프트가 되고, 예약 작업은 배포(deployment)의
  스케줄이 되고, 공유 폴더는 메모리 스토어가 됩니다. 지시문 변경은 새 버전으로 저장되고, 작업 중인
  편집본은 예약 실행에 반영되지 않습니다.
- 모든 에이전트가 같은 메모리 스토어를 읽고 씁니다. 초안과 실제로 보낸 메일의 차이를 메모로 저장하므로,
  한 번 고친 내용이 플릿 전체에 퍼집니다.
- 자격증명은 범위가 제한되고 즉시 취소할 수 있는 managed vault에 보관됩니다. 각 배포는 자기 업무에
  필요한 vault만 사용하고, 에이전트가 자격증명 자체를 보지는 않습니다.
- 변경 요청은 플릿 전용 Slack 채널에 평소 말투로 적습니다(지시문 변경 요청은 저자만 가능). 코디네이터가
  약 15분마다 채널을 확인해 반영합니다.
- 루틴을 벗어나는 항목은 Slack의 Claude Tag로 넘깁니다. Claude Tag가 선택지를 정리하고 필요한 초안을
  쓰고, 스스로 재확인 리마인더를 설정하며, 검토·승인이 필요할 때 사람을 태그합니다.
- 비용 통제는 설계와 모델 선택의 조합입니다. 규칙서 기반 에이전트(Furiwake, Shoudan)는 Sonnet,
  판단이 많이 필요한 에이전트(Sabaki, Nokori, 코디네이터)는 Opus에서 돌아갑니다. Henji는 하루 종일
  Sonnet으로 돌면서, 스스로 결정할 수 없을 때 Opus에 조언을 구하는 어드바이저 전략을 씁니다.
  effort 수준은 모델과 별도로 설정합니다.
- 저자가 측정한 결과: 각 작업을 수동으로 했을 때 걸릴 시간으로 환산하면 플릿이 주당 약 60시간 분량의
  일을 처리합니다.
- 교훈: 업무를 한 번만 설명하고 수정 사항을 Claude가 기억하게 할 것, 프롬프트보다 지식 베이스가 더
  중요하다는 것, 그리고 더 많은 일을 더 빨리 에이전트에게 넘길 것.

## 번들 리소스
- Skill: `scheduled-agent-fleet` — 단일 목적 예약 에이전트 플릿을 설계·프로토타이핑·운영하는 방법.
  역할 구성, 공유 메모리와 자격증명, 모델/effort 등급화 레퍼런스와 프로토타입 → Managed Agents 이전
  예시 포함.
- Agents: 글에 명시된 6개 역할(`furiwake-lead-router`, `sabaki-lead-triage`, `henji-reply-drafter`,
  `shoudan-crm-updater`, `nokori-day-closer`, `fleet-coordinator`).
- Guide: "예약 에이전트 플릿 설계" 4개 언어판.
