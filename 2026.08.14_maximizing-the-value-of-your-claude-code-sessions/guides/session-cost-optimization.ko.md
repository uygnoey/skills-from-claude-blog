# Claude Code 세션에서 더 많이 얻어내기

에이전틱 코딩 도구는 좌석이 아니라 토큰 단위로 청구된다. 즉 같은 작업이라도 세션을 어떻게 운영했느냐에
따라 비용이 크게 달라진다. 어떤 세션은 테스트 파일과 구현 파일을 읽고 버그를 고친다. 다른 세션은 먼저
리포지토리를 grep하고 열두 개 파일을 열어본 뒤, 그 파일들과 그날 아침에 읽은 모든 것을 남은 모든 턴에
끌고 다닌다.

글쓴이 Lydia Hallie가 잡아 준 프레임을 기억할 만하다. 토큰을 효율적으로 쓴다는 건 전체 사용량을 줄이는
게 아니라, 실제로 요청한 일에 토큰이 쓰이도록 만드는 것이다.

비용을 결정하는 변수는 둘이다. 토큰 하나의 값, 그리고 세션이 보내는 토큰의 양.

## 1부 — 토큰 하나의 값

### 모델

큰 모델은 입력·출력 토큰 모두에 더 많은 일을 하고 그만큼 비싸다. 문제에 모델을 맞춰라. 정말 어렵거나
모호한 작업에는 큰 모델을, 일상적인 변경에는 작은 모델을.

### 입력 대 출력

모든 턴에는 두 단계가 있다. **프리필**에서 모델은 받은 것을 읽는다 — 시스템 프롬프트, 툴 정의,
`CLAUDE.md`, 지금까지의 대화, 새 메시지. 이것이 입력 토큰이다. **디코드**에서는 응답을 한 토큰씩
써낸다. 이것이 출력 토큰이고, 입력의 약 5배 가격이다.

사고(thinking) 토큰은 출력 토큰이므로, effort 레벨은 비싼 쪽을 직접 조절하는 다이얼이다. 새 세션에서
`/model`과 `/effort`를 한 번 실행해 둘 다 확인해 두는 것이 좋다. 두 설정은 이전 세션에서 그대로
이어지므로, 지금 걸려 있는 값이 의도한 값이 아닐 수 있다. 한 세션 동안 사고를 아예 끄고 싶다면
`MAX_THINKING_TOKENS=0`이 `/effort low`보다 한 단계 아래로 내려간다(Fable 5에는 적용되지 않는다).

### 프롬프트 캐싱

긴 대화가 감당 가능한 이유가 캐싱이다. 캐시 읽기는 입력가의 약 0.1배, 캐시 쓰기는 최대 2배이며 토큰당
한 번만 낸다. 한 번 쓰고, 이후 모든 턴에서 싸게 읽는다.

그래서 캐시 무효화가 비싼 사건이 된다.

| 트리거 | 효과 |
|---|---|
| `/model` | 모델이 바뀌면 캐시도 바뀐다 — 전체 재프리필 |
| `/effort` | 캐시 키의 일부 — 전체 재프리필 |
| Fast 모드 | 역시 캐시 키의 일부 |
| `/compact` | 대화를 교체한다. 시스템 프롬프트는 살아남는다 |
| 시간 | 구독은 1시간, API 키는 5분 후 만료 (`ENABLE_PROMPT_CACHING_1H=1`로 API 키도 1시간) |
| 세션 재개 | 대체로 만료된 상태. 시스템 프롬프트는 시작 시 재구성된다 |

알아둘 만한 예외: `/rewind`는 비용이 없다. 대화 끝을 잘라내고 그 앞은 캐시된 채로 남긴다. 반면
`/compact`는 대화를 다시 쓰므로 항상 비용이 든다. 그래서 자리를 비우기 *전에*, 아직 따뜻할 때 컴팩트
하라는 조언이 나온다. 캐시가 만료된 뒤가 아니라.

## 2부 — 세션이 보내는 토큰의 양

한 번만 보내지는 것은 없다. 읽은 모든 파일과 실행한 모든 명령의 출력은 세션이 끝날 때까지 매 턴 다시
전송된다. 캐시되어 있어 싸지만, 여전히 존재하고 컨텍스트를 차지한다.

### 입력하기 전에 이미 로드된 것

새 세션에서 `/context`를 실행하면 상시 부하가 보인다. 연결된 각 MCP 서버의 툴 정의, 시스템 프롬프트,
`CLAUDE.md`, 시작 항목들. 전부 매 턴 비용을 낸다.

줄이는 방법 두 가지. `CLAUDE.md`를 구체적으로 유지하고, 워크플로 지시는 필요할 때만 로드되는 스킬로
옮긴다. 그리고 쓰지 않는 MCP 서버는 `/mcp`로 끈다.

### 작업하면서 추가되는 것

**파일.** 어떻게 묻느냐가 얼마나 들어오는지를 결정한다. "테스트가 깨져요"는 grep과 여러 번의 읽기를
부른다. 파일을 지정하면 Read 한 번이다. `@`로 멘션하면 아예 없다 — Claude Code가 메시지를 보내기 전에
파일을 첨부하기 때문이다. 파일 자체가 차지하는 공간은 어느 쪽이든 같고, 아끼는 것은 왕복이다. 대화당
한 번만 멘션하라. 다시 멘션하면 사본이 하나 더 붙는다.

**명령 출력.** 파일과 똑같이 덧붙고, 그대로 남는다. 수다스러운 테스트 러너는 수백 줄을 남기고 그것이
하루 종일 다시 전송된다. 대략 3만 자를 넘는 출력은 파일로 쓰이고 대화에는 미리보기만 남는다
(`BASH_MAX_OUTPUT_LENGTH`가 임계값을 정한다). 극단적인 경우는 막아주지만 꾸준한 누적은 막지 못한다.

해법은 하루 종일 쓰는 명령 두세 개를 조용한 플래그까지 포함해 직접 타이핑하듯 `CLAUDE.md`에 적어두는
것이다. 예를 들어 단일 테스트 파일을 `--reporter=dot`으로 돌리는 식이다. 호출 방식을 알아내는 데 쓰는
턴과, 남은 세션 내내 컨텍스트에 앉아 있을 출력을 함께 아낀다.

### 얼마나 오래 남는가

40번째 턴은 앞선 39개 턴을 다시 보낸다. 그래서 하나의 긴 세션이 같은 작업을 짧은 세션 여러 개로 나눈
것보다 비싸다.

- 새 작업을 시작하면 `/clear`. 나중에 다시 볼 것 같으면 먼저 `/rename`.
- 한 덩어리가 끝났지만 그 결론이 필요하면 `/compact`. 무엇을 남길지 말해 주고, 늘 같은 답이라면
  `CLAUDE.md`에 컴팩트 지시 섹션을 둔다.
- 1M 컨텍스트 모델에서는 `/autocompact 200k`로 자동 컴팩트 안전망을 되살린다(Claude Code v2.1.221+).

함정 하나. `/loop`는 그것을 시작한 세션 안에서 전체 턴으로 발화하며 매번 대화 전체를 끌고 간다. 게다가
발화 간격이 한 시간을 넘으면 매번 캐시 미스이기도 하다. 루프는 다른 터미널의 새 세션에서 시작하라.

### 서브에이전트

서브에이전트는 자기만의 컨텍스트를 갖는다 — 시스템 프롬프트, 툴, `CLAUDE.md`. 하지만 당신의 대화는
아니다. 자기 턴을 쓰고, 돌아오는 것은 답변뿐이다. 나머지는 버려진다.

교환은 양방향으로 실재한다. 메인 세션이 이미 가진 것을 다시 읽을 수 있고, 자기 턴 비용도 낸다. 값어치를
하는 경우는 필요 없는 출력이 많이 나오는 작업이고, 로그 분석이 가장 분명한 예다. 로그가 아니라 보고서만
받는다. 반복해서 넘기는 시끄러운 작업이라면 서브에이전트 설정에 더 작은 모델을 고정해 두라. 그렇지
않으면 메인 세션의 모델로 돌아간다.

## 어디부터 볼 것인가

영향이 큰 순서로 대략:

1. **세션 길이** — 매 턴 얼마나 많은 대화가 다시 전송되는가.
2. **명령 출력 크기** — 그 안에 얼마나 많은 잡음이 쌓이는가.
3. **읽은 파일** — 필요한 것을 얼마나 정확히 가리켰는가.
4. **모델과 effort** — 시작할 때 의도적으로 정하고, 도중에 바꾸지 않는다.

보통은 앞의 둘이 마지막 하나보다 중요하다.
