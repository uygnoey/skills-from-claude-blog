## この記事について
同じ作業をする 2 つの Claude Code セッションのコストがなぜ大きく違うのか、そして自分に何が制御できるのかを扱った Lydia Hallie 氏による実践ガイド。エージェンティックなコーディングツールはシート単位ではなくトークン単位で課金されるため、問いは「トークンをどう減らすか」ではない。使うトークンが実際に頼んだ作業へ向かい続けるようにし、無関係なファイルやコマンド出力を毎ターン再送しないようにすることだ。

問題は 2 つの変数に分解される。トークン 1 個の値段（モデル、入力と出力、プロンプトキャッシュ）と、セッションが送るトークンの量（何がコンテキストに入り、どれだけ残るか）。最後に、どこから手を付けるべきかのおおまかな優先順位が示される。

## どんなときに役立つか
- セッションのコストが重く感じられるが、どこに費やされているのか判然としないとき。
- 長い会話が、その朝の無関係な読み込みまで毎ターン引きずっているとき。
- `/clear`、`/compact`、`/rewind` のどれを使うか決めるとき。
- 接続中の MCP サーバーのツール定義や肥大した `CLAUDE.md` が、入力する前からコンテキストを埋めているとき。
- ログ漁りやトレース解析のような騒がしい作業をサブエージェントに任せるべきか判断するとき。
- チームをエージェンティックなコーディングにオンボードし、早い段階で習慣を固めたいとき。

## 主なポイント
- **出力トークンは入力のおよそ 5 倍**で、思考トークンは出力トークンである。したがって effort レベルは高い側を直接動かすダイヤルだ。`MAX_THINKING_TOKENS=0` は 1 セッションのあいだ `/effort low` の一段下に降りる（Fable 5 には適用されない）。
- **キャッシュ読み出しは入力価格のおよそ 0.1 倍、書き込みは最大 2 倍でトークンあたり一度。** キャッシュを守ることが他のたいていの最適化より効く。
- **キャッシュを壊すもの:** `/model`、`/effort`、高速モードはいずれもキャッシュキーの一部で、全体の再プリフィルを強制する。`/compact` は会話を置き換える（システムプロンプトは残る）。キャッシュはサブスクリプションで 1 時間、API キーで 5 分で失効し、`ENABLE_PROMPT_CACHING_1H=1` が後者を延長する。
- **`/rewind` は無料** — 末尾を切り落とし、キャッシュはそのまま残す。`/compact` は必ずコストがかかるので、キャッシュが切れた後ではなく休憩の *前* にコンパクトするのがよい。
- **新しいセッションで `/model` と `/effort` を一度確認する。** どちらも前のセッションから引き継がれるため、今かかっている設定が意図したものとは限らない。
- **一度きりで送られるものはない。** 読んだファイルもコマンド出力も、以降のすべてのターンで再送される。キャッシュされていて安いが、コンテキストは占有する。40 ターン目はそれ以前の 39 ターン分を支払っており、だから 1 本の長いセッションは同じ作業を分割した場合より高くつく。
- **`/context` を一度実行する。** ツール定義、システムプロンプト、`CLAUDE.md`、起動時項目という常設の負荷が見える。`CLAUDE.md` は具体的に保ち、ワークフローの指示は使うときだけ読み込まれるスキルへ移し、使っていない MCP サーバーは `/mcp` で無効化する。
- **ファイルを指し示す。** 曖昧な依頼は grep と大量の読み込みを招き、ファイルを名指しすれば Read は 1 回、`@` メンションなら 0 回になる（メッセージ送信前に添付されるため）。メンションは 1 会話につき 1 回。再度メンションするとコピーがもう 1 つ添付される。
- **コマンドを静かにする。** 出力はファイル読み込みと同じように追記され、セッション中ずっと残る。一日中使うコマンド 2〜3 個を静かにするフラグ込みで `CLAUDE.md` に書いておく。およそ 3 万文字を超える出力はファイルに書き出され、会話にはプレビューが残る（`BASH_MAX_OUTPUT_LENGTH`）。
- **`/loop` は開始したセッションの中で完全なターンとして発火し**、毎回会話全体を引き連れていく。発火の間隔が 1 時間を超えるとキャッシュも外す。ループは別ターミナルの新しいセッションで走らせる。
- **サブエージェントは自分のコンテキストを持つがあなたの会話は持たず**、戻るのは答えだけである。残す必要のない出力が大量に出る作業では割に合う。繰り返し任せる騒がしい作業なら、サブエージェントの設定に小さめのモデルを固定しておく。
- **どこから見るか**は、おおよそ影響順にセッションの長さ、コマンド出力の大きさ、読んだファイル、モデルと effort。
- 1M コンテキストのモデルでは `/autocompact 200k` で自動コンパクトの安全網が戻る（Claude Code v2.1.221+）。
