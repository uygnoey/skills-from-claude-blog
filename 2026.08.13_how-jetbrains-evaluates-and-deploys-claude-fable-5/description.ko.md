## 이 글이 뭔가요
JetBrains Agent Systems CTO Vladislav Tankov와의 인터뷰. 새로 나온 프런티어 모델을 어떻게 평가하고, 자사의 어떤 워크로드를 그 모델로 옮길지 어떻게 정하며, 고객에게 닿기 전에 모델 주변에 어떤 안전장치를 두는지를 다룬다. JetBrains는 활성 사용자 1,250만 명과 Fortune Global 100 중 88개 기업을 고객으로 두고 있어, 배포 판단의 무게가 실제로 크다.

관통하는 논지는 공개 벤치마크 점수가 답이 아니라 가설이라는 것이다. JetBrains는 자사 모노레포를 포함한 비공개 리포지토리에서 대규모 평가 세트를 돌려 모델의 실제 동작이 공개 점수와 맞아떨어지는지 확인하고, 리더보드를 세 개(최고 품질, 최저 태스크당 비용, 최고 속도) 따로 유지해 워크로드마다 다른 승자를 고를 수 있게 한다.

## 언제 유용한가요
- 새 프런티어 모델이 나왔을 때, 리더보드가 아니라 자사 코드에 근거해 "도입해야 하나"에 답해야 할 때.
- 하나의 기본 모델을 정하는 대신 워크로드별로 모델을 나눠 쓸지 판단할 때.
- 완료 태스크당 비용으로 내려야 할 결정을 토큰 단가 비교로 내리고 있을 때.
- 안전성에서 우리 조직의 몫과 모델 공급자에게 합리적으로 기대할 몫을 나눌 때.
- 보안 검토를 통과할 수 있는 데이터 보존 입장이 필요할 때.

## 핵심 포인트
- **비공개 리포지토리에서 평가한다.** 모델이 학습했을 리 없는 작업, 우리 컨벤션과 빌드 시스템을 그대로 안고 있는 태스크로. Tankov의 경고는 어떤 모델은 공개 벤치마크 점수가 잘 나오도록 튜닝되어 있고 실제 작업에서는 무너진다는 것이다.
- **리더보드는 하나가 아니라 셋** — 최고 품질, 최저 태스크당 비용, 최고 속도. 하나로 합치면 작업을 라우팅할 때 필요한 정보가 사라진다.
- **토큰당이 아니라 태스크당 비용.** Claude Fable 5는 토큰 단가는 더 비싸지만 복잡하고 오래 걸리는 작업에서는 단계가 적어 태스크당 비용이 더 낮다.
- **보고된 수치.** Python 통과율 44.3% 대 Opus 4.8의 28.2%, 약 16포인트 차이. 정면 비교에서 Fable 5는 Opus 4.8이 놓친 Python 태스크 18개를 풀고 2개를 잃었다. 해결까지의 단계는 약 22% 적었다.
- **"실행은 되지만 틀린" 비율에 가중치를 둔다.** Fable 5의 코드는 실행됐을 때 테스트를 훨씬 자주 통과했다. 실행되면서 틀린 답을 내는 코드는 잡아내기 가장 비싼 실패다.
- **단계 수는 습관의 신호다.** 어떤 Java 태스크에서 이전 모델은 필요하지도 않은 외부 리소스를 반복해서 끌어오려 했다. Tankov는 이 차이를 더 나은 엔지니어링 습관 전반으로 읽는다.
- **교체가 아니라 라우팅.** Opus는 일꾼으로 남는다 — 일을 해낼 것이라고 꽤 확신할 수 있다. Fable 5는 정말 좋은 추론이 필요할 때, 거의 파트너가 필요한 수준일 때를 위해 남겨둔다. 여러 번 실패했던 리치 텍스트 에디터 컴포넌트, 텍스트와 이미지 명세로부터 IDE 같은 애플리케이션을 구현하거나 기존 앱을 다른 런타임·프레임워크·언어로 다시 쓰는 장시간 에이전틱 실행 같은 일이다.
- **안전은 하네스의 문제다.** JetBrains는 가장 안전한 모델을 직접 만들려 하지 않는다. 공급자의 레드팀 활동이 충분하다고 보고, 자사의 노력은 모델 주변의 안전망 — 체계적 배포, 인프라, 하네스 설계 — 에 쏟는다.
- **모델을 자사 제품에 겨눈다.** 외부 위협 행위자가 같은 급의 모델을 쓸 것이라는 전제 아래, JetBrains 소프트웨어를 대상으로 화이트박스 보안 테스트를 돌린다.
- **데이터 보존 입장을 명시한다.** 선호는 제로 보존이고, 가장 심각한 플래그 사례 조사로 한정한 보존은 공정한 절충으로 받아들인다. 그것 없이는 분류기가 어디서 잘못 동작했는지 알 수 없기 때문이다. 긴장도 명시된다 — 공격적인 분류기는 방어적 보안 작업을 더 어렵게 만든다.
- **다음 단계**는 모델 능력보다 소프트웨어 개발을 위한 콕핏으로 설명된다. 에이전트와 사람이 협업하는 공간, 그리고 거버넌스와 투자수익의 명확성.
