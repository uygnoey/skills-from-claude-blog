# Role-to-credential scenarios

Each scenario sorts a person by **what they do on a Claude engagement**, then names the credential
the program maps that work to. Nothing here changes the program's own definitions — see
the skill's `references/credentials.md` for those.

## 1. The consultant who never opens an editor

A management consultant leads a client workstream on a Claude deployment. They run workshops,
shape the use cases, and use Claude daily to draft, analyze, and summarize.

**Credential: Claude Certified Associate: Foundations.**
The Associate credential validates practical, everyday use of Claude for anyone working on
Claude-related projects, explicitly including consultants and project leads, and spanning both
business and technical expertise.

## 2. The application engineer

An engineer is building an internal service that calls the Claude API, defines tools for it, and
runs an agent loop over them.

**Credential: Claude Certified Developer: Foundations.**
The Developer credential is for engineers building applications with Claude and covers the Claude
API, tool use, and agent development — the three things this person does all day.

## 3. The solution architect on a single system

An architect is designing the agent system for one business unit: which agents exist, how they hand
off, where they read and write.

**Credential: Claude Certified Architect: Foundations.**
This credential is for solution architects who design and build agent systems with Claude.

## 4. The same architect, one deployment larger

The deployment expands across the enterprise. The architect now owns how Claude integrates with the
rest of the estate, how the deployment is governed, and how it is evaluated.

**Credential: Claude Certified Architect: Professional.**
The advanced credential covers integration architecture, governance, and evaluation, built for the
scale of large enterprises. The architect reaches it *after* the foundation level — every path
starts at foundation level and advances to professional.

## 5. A mixed delivery pod

A six-person pod: one project lead, one business analyst, two application engineers, one solution
architect, one enterprise architect.

| Person | Work on the engagement | Credential |
|---|---|---|
| Project lead | Runs the project, uses Claude daily | Associate: Foundations |
| Business analyst | Uses Claude daily, no build work | Associate: Foundations |
| Application engineer ×2 | Claude API, tool use, agent development | Developer: Foundations |
| Solution architect | Designs and builds the agent system | Architect: Foundations |
| Enterprise architect | Integration architecture, governance, evaluation at scale | Architect: Foundations → Architect: Professional |

Five of the six sit a foundation-level exam first. Only the enterprise architect has a reason to
continue to the professional level.

## 6. A firm working backward from a committed number

A boutique consultancy has committed to certifying its entire delivery team. The plan is a mix, not
a single exam:

1. Bucket every person into one of the four roles.
2. Assign each bucket its foundation-level credential.
3. Mark the people who own enterprise-scale integration architecture, governance, and evaluation for
   the professional level.
4. Sequence the cohorts against the next Claude Partner Network tier review, because certified
   practitioner counts feed tier standing — the top tier, Global Premier, requires 1,000 certified
   practitioners alongside 100 customers across three regions and 15 public customer endorsements.

Firms across the network are running exactly this play at very different scales: Accenture has
committed to 50,000 certified professionals across foundational, technical, and specialized tracks;
Ascendion plans to certify its entire 8,000-person engineering team before 2027; Wipro will certify
10,000 front-line delivery experts within 18 months.
