# CRM update proposal

The post: "Claude proposes each Salesforce update with the evidence behind it
and waits for approval." This is a format for that proposal — enough for a rep
to approve or reject without opening four other tabs.

---

## Proposal _[id]_ · _[date]_

**Account:** _[name]_
**Opportunity:** _[name]_
**Owner:** _[rep]_

### Change

| | Current | Proposed |
| --- | --- | --- |
| Stage | | |
| _[other field]_ | | |

### Rule applied

> _[the line from the stage guidance that this change follows]_

### Evidence

1. **_[source — email / call / CRM]_**, _[date]_
   > _[the quoted line or moment that establishes it]_
   _[link or locator]_

2. **_[source]_**, _[date]_
   > _[quote]_

### What would make this wrong

- _[the disqualifying condition from the guidance that a human can see and the
  skill might have missed]_

### Decision

- [ ] Approve
- [ ] Edit → _[what changed]_
- [ ] Reject → **reason:** _[written in the rep's words, recorded back into the skill]_

---

## Notes on use

- **Evidence is quoted, not summarized.** The rep is approving a claim about a
  conversation; they need the conversation.
- **The rule is shown.** If the rule is wrong, the proposal makes that visible.
- **The reason field is not optional.** It is the input that stops the same
  mistake from being proposed again.
