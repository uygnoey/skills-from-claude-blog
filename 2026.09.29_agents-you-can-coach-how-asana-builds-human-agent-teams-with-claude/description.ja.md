## この記事について
Claude の「人間とエージェントのチーム」シリーズ第 3 弾です。Asana の最高製品責任者 Arnab Bose 氏が、Work Graph®
モデルの中で AI エージェント（「AI チームメイト」）を運用する方法を語ります。範囲を絞った役割、指定された人だけが反映
できる共有メモリ、全員が見てコーチできる場所への作業の投稿、そして Claude を使うエージェントに任せた 3 つの業務を
紹介します。

## どんなときに役立つか
- チームのプロジェクト、タスク、チャンネルにエージェントを導入するとき
- エージェントの役割、指示、権限、ガバナンスを定めるとき
- エージェントを訓練する人と、一緒に働くだけの人を決めるとき
- 繰り返し発生する集約業務（Q&A の振り分け、状況ダイジェスト、サイクル計画）をエージェントの仕事にするとき

## 主なポイント
- まず仕事を構造化します。非構造の入力を Claude に持ち込んで議論し、実行項目をエージェントや同僚が拾えるプロジェクトと
  タスクとして記録します。
- エージェントごとに役割、組み込みスキル、連携、プロフィールページ（目的、利用者、管理者、指示、スキル、連携、権限）が
  あります。アクセスは特定のプロジェクト・ドキュメント・アプリに限定され、呼び出した人の権限に制限されます。
- タスクへのフィードバックは誰でもできますが、永続的な共有メモリへの反映・取り消し・削除は管理者と編集者だけです。
  基準（例：ブランドボイス）を持つチームがエージェントを所有します。
- エージェントは共有タスクに計画と手順を投稿するため、レビュアーは依頼とやり取りを確認し、成果物だけでなく指示も修正
  できます。
- 業務例：Slack での製品 Q&A（回答、製品ギャップの登録、繰り返される質問をイネーブルメントへ）、3 区分でまとめグロー
  バル → 地域の順に届ける日次 At-Risk Renewal ダイジェスト、Asana の MCP サーバーでデータを公開する Command での
  エンジニアリングサイクル計画。
