## この記事について
Anthropic は、Claude Code と Claude Cowork を Claude for Government Desktop を通じてパブリックベータで提供すると発表した。FedRAMP High 認証環境を介して配信され、機関は商用顧客と同じリリーススケジュールで機能を受け取る。

発表は四つの領域を扱う。データがどこにあるか(推論は認証環境の内部、会話履歴は機関が管理する端末にローカル保存)、支出をどう抑えるか(標準シートまたはカスタムティア、固定単位での購入と超過不可のハード上限)、管理をどう委譲するか(省庁レベルでのシート割り当て、レート制限・ドル上限・許可モデルを定める SCIM グループマッピング、下位機関のデフォルトを定める階層型構成)、そして監督がどう機能するか(製品内でレビューできるハッシュチェーン監査ログ、Anthropic 側の機微な操作に対する二名承認、メータリングデータのみの使用量エクスポート)。裏づけ文書としては、公開されている FedRAMP Secure Configuration Guide と正式な変更通知、そしてトラストセンターを通じて NDA のもとで入手できるペネトレーションテスト要約がある。デスクトップアプリは標準的な機関の MDM プラットフォームを通じて配布される。

## どんなときに役立つか
- ATO パッケージやセキュリティ審査を準備し、処理がどこで行われ、データがどこに残るのかを記述する必要があるとき。
- 一つの認可のもとで、省庁が複数の下位機関にシートと異なる制限を割り当てなければならないとき。
- 従量課金を歳出予算と整合させる必要が財務部門にあるとき。
- 監察官や監査人が使用状況の数値を求めているが、機微な資料を境界の外に出せないとき。
- やり取りの記録がノート PC 上に残るツールについて、MDM 配布とエンドポイントポリシーを計画するとき。

## 主なポイント
- **FedRAMP High であり、推論も境界の内側で行われる。** Claude for Government Desktop を通じて提供され、現在はパブリックベータ。
- **会話履歴はローカルにある。** 機関が管理する端末上に置かれるため、エンドポイントが審査範囲に入る。ディスク暗号化、バックアップ、保存期間、端末紛失時の手順は、ベンダーの保持ではなく機関のエンドポイントポリシーの問題である。
- **支出はハード上限で抑えられる。** 使用量は固定単位で購入され超過不可の上限がかかる。管理コンソールでユーザー別・モデル別に追跡でき、残高が尽きる前に自動のバーンダウン通知が出る。
- **制限はアイデンティティに紐づく。** SCIM グループマッピングがグループごとのレート制限・ドル上限・許可モデルを定め、階層型構成が、Claude が何に接続できてどの機能が使えるかについての下位機関のデフォルトを定める。
- **監督機能が組み込まれている。** ハッシュチェーンされた監査ログを組織管理者が製品内で直接レビューでき、Anthropic 側の機微な操作には二名承認が必要となる。
- **使用量エクスポートはメータリングデータのみ**であり、機微な資料を動かさずに ATO や IG の照会に答えられる。
- **文書は二段階で提供される。** FedRAMP Secure Configuration Guide と正式な変更通知は公開、ペネトレーションテスト要約はトラストセンター経由で NDA のもと提供。
- **商用顧客と同じリリーススケジュール** — 利点であると同時に変更管理上の義務でもある。
- **請求上の契約当事者は Anthropic** であり、クラウド事業者との別途の契約関係は不要。新規顧客は claude.com/solutions/government からアクセスを申請する。
