## 이 글이 뭔가요
고객 경험(CX) AI 기업 Cresta 가 Claude Agent SDK 위에 만든 Conductor 사례입니다. Conductor 는
운영 환경에 바로 쓸 수 있는 CX 에이전트를 자연어로 만드는 에이전트 빌더로, 사용자가 원하는 것을
설명하면 블루프린트 → 구현 → 평가 → 최적화 순서로 작업을 안내합니다.

## 언제 유용한가요
- 도메인 전문성을 가진 팀이 이를 에이전트 제작 제품으로 만들고 싶을 때.
- 직접 만들 부분과 Claude Agent SDK 에 맡길 부분을 나눌 때.
- 모델 업그레이드 때 개선과 퇴행을 잡아내는 평가 루프를 세울 때.

## 핵심 포인트
- Claude Agent SDK 는 범용 실행 하네스(컨텍스트 수집, 도구 호출, 코드 작성·실행)이고, 그 위에
  Cresta 의 CX 워크플로·도구·도메인 컨텍스트를 얹었습니다. 데이터 프라이버시, 테넌트 구조, 조직
  단위 키 배포, 통제, 관측성을 기준으로 SDK 를 평가했습니다.
- 과거 대화를 분석해 사람이 개입해야 할 곳과 모델이 유연하게 대응해도 되는 곳을 구분합니다.
  특히 규제 산업의 핵심 워크플로는 명시적 규칙으로 고정하고, 그 규칙을 시험하고 고쳐 나갑니다.
- 빌드 작업(에이전트 생성, 테스트 케이스 작성, 기존 에이전트 수정, 근본 원인 분석)을 결과, 실행
  경로, 큐레이션된 기준 대비 품질, 자원 사용으로 채점하고, 새 모델이나 프레임워크 변경 때마다 같은
  방식으로 다시 돌립니다.
- 초기 사용에서 최초 배포 시간이 약 절반으로 줄었다고 합니다. 검증된 패턴은 스킬로 팀에 공유합니다.
- 교훈: 전문 엔지니어 수준이 될 때까지 직접 써 보기, 고유한 강점에만 투자하기, 결정적으로 고정할
  부분 정하기, 첫 구축은 노력의 약 20%이고 나머지 80%는 반복 개선.

## 번들 리소스

  빌드 작업 채점표 템플릿.
