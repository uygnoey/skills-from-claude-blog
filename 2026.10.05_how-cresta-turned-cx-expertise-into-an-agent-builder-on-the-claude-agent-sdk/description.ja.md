## この記事について
カスタマーエクスペリエンス(CX)AI 企業 Cresta が Claude Agent SDK 上に構築した Conductor の事例です。
Conductor は本番運用できる CX エージェントを自然言語で作るエージェントビルダーで、ユーザーが要望を
説明すると、ブループリント → 実装 → 評価 → 最適化の順に作業を導きます。

## どんなときに役立つか
- ドメイン知識を持つチームが、それをエージェント構築プロダクトにしたいとき。
- 自社で作る部分と Claude Agent SDK に任せる部分を切り分けるとき。
- モデル更新時の改善と退行を捉える評価ループを作るとき。

## 主なポイント
- Claude Agent SDK は汎用の実行ハーネス(コンテキスト収集、ツール呼び出し、コードの作成と実行)で、
  その上に Cresta の CX ワークフロー、ツール、ドメインコンテキストを載せています。データプライバシー、
  テナント構成、組織単位の鍵配布、統制、可観測性の観点で SDK を評価しました。
- 過去の会話から、人が関与すべき箇所とモデルが柔軟に対応してよい箇所を見極めます。特に規制業界の
  重要なワークフローは明示的なルールで固定し、そのルールをテストして見直します。
- ビルドタスク(エージェント作成、テストケース作成、既存エージェントの変更、根本原因分析)を、成果、
  実行経路、キュレーション済みリファレンスとの品質比較、リソース使用量で採点し、新モデルや
  フレームワーク変更のたびに同じ方法で再実行します。
- 初期利用では初回デプロイ時間がおよそ半分になったとされます。実証済みのパターンはスキルとして
  チームで共有します。
- 教訓: 熟練エンジニア並みになるまで社内で使う、独自の強みにだけ投資する、決定的にすべき部分を
  決める、初回構築は労力の約 20%、残り 80% は反復改善。
