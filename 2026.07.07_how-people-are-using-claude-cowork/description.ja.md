## この記事について
Anthropic は 2026 年 5 月 11〜31 日に、60 万を超える組織から集まった匿名化・集計済みの Claude Cowork セッション 120 万件をサンプリングし、20 カテゴリの業務分類体系に沿って自動分類した。中心となる発見はこうだ。利用のおよそ半分が「仕事のまわりの仕事(the work around the work)」、つまり非常に多くの職務に共通して存在するが、誰の中核業務でもないタスクだった。

その半分を上位 2 カテゴリが占める。**ビジネスプロセスとオペレーション**が 33.4%。散らばった更新を 1 本のレポートにまとめる、オンボーディングのチェックリストを作る、スプレッドシートを突き合わせる、といった作業だ。**コンテンツ制作とコピーライティング**が 16.4%。ドラフト、スライドデッキ、投稿、提案書のような、統合作業の比重が大きいビジネスコミュニケーションである。どちらも特定の職種のものではなく職種を横断する。財務・人事・管理部門はいずれも前者に手を伸ばし、マーケティング・広報・事業開発・プロジェクト管理はいずれも後者に手を伸ばす。

残りはロングテールだ。ソフトウェア開発 8.7%、DevOps とインフラ 7%、リサーチとインテリジェンス 6.4%、データ分析とビジネスインテリジェンス 5.8%、ドキュメント処理と抽出 4.1%、セールスとレベニューオペレーション 4%、パーソナルアシスタンス 3.8%、教育 2.4%、会議・会話インテリジェンス 1.8%、法務とコンプライアンス 1.3%、カスタマーサポート 0.8%。

記事はこの形を「つなぐ仕事」として読む。「人々は Claude Cowork を、自分の専門性を発揮するために使う情報を集めて構造化するために使っている」。弁護士は書類の書式と提出を渡し、法的判断を手元に残す。採用担当は日程調整と面接フィードバックの統合を渡し、候補者との対話を手元に残す。チームリードは難しい決定を説明するデッキを渡し、その決定自体を手元に残す。これは開発者が職務の中核 — コードを書き、デバッグし、出荷する — に使う Claude Code とは対照的で、Cowork セッションにおけるソフトウェア開発の比率がこれほど小さい理由でもある。

記事は異例なほど明示的な方法論・制約の節で締めくくられる。サンプリングは 1 時間あたりの上限方式なので、すべての数値は絶対量ではなくサンプル内のシェアであること。分類体系にマーケティング・財務・人事の独立カテゴリがないこと。5 月 11 日前後にラベリングパイプラインの変更でシェアが動いたため 3 週間の窓を選んだこと。セッションの約 5% は業務ではなく個人利用であること。そしてラベルは人間ではなく自動分類器が付けたこと。

## どんなときに役立つか
- 自分のどのタスクをエージェントに渡すか決めるとき、推測ではなく実際に人々が何を渡しているかの公開された分布がほしいとき。
- エンジニアリング以外の領域でエージェントツールの導入を社内で説得するとき、非開発者の利用の形が必要なとき。
- 自チームのエージェントセッションを分類したいが、既存の分類体系とレポート形式をそのまま使いたいとき。
- 利用シェアのレポートを読む・書くときに、上限付きサンプリング・自動分類・分類体系の粒度といった但し書きを誠実に添える必要があるとき。
- コード中心のツールとチャット型エージェントが、なぜこれほど違う用途で使われるのかを説明したいとき。

## 主なポイント
- **利用の半分は「仕事のまわりの仕事」。** ビジネスプロセスとオペレーション(33.4%)とコンテンツ制作とコピーライティング(16.4%)を合わせると、サンプルされたセッションのおよそ半分になる。どちらも誰の肩書きでもない。
- **首位カテゴリは 2 位の 2 倍以上。** 33.4% 対 16.4%。他のカテゴリはすべて 9% 未満だ。
- **これはつなぐ仕事だ。** スプレッドシートはばらばらのデータ点を、読み・比べ・追跡できる文脈にまとめる。デッキは文脈の量がまちまちな相手にアイデアや決定を伝える。オンボーディングのチェックリストは新入社員が組織の知識に接続する助けになる。
- **専門性は人に残る。** 渡しているのは判断ではなく、組み立てと構造化だ。法的判断ではなく書式と提出、候補者評価ではなく日程と統合、決定そのものではなくそれを説明するデッキ。
- **Cowork の使われ方は Claude Code の裏返し。** 開発者は職務の中核に Claude Code を使い、ソフトウェアエンジニアリングを含むあらゆる職務を取り巻く、つなぐ・伝えるための仕事に Cowork を使う。だから Cowork セッションにおけるソフトウェア開発は 8.7% にとどまる。
- **Cowork はターミナルが障壁だったから生まれた。** 非技術ユーザーはすでに Claude Code でフォルダを整理し、重複ファイルを取り除き、スプレッドシートの数式を書いていた。しかし他の人にとってターミナルは依然「文字どおりの『ブラックボックス』」であり、だからエージェント機能を人々がすでに使っているチャットインターフェースへ持ち込んだ。
- **総量ではなくシェア。** サンプリングは 1 時間あたり固定上限のため、数値を利用総量や成長として読むことはできず、混み合う時間帯はやや過小に表れる。
- **分類体系は肩書きではなく仕事を分ける。** マーケティング・財務・人事の独立カテゴリがなく、それが「ビジネスプロセスとオペレーション」が全体の 3 分の 1 を吸収した理由の一部だろう。
- **このスナップショットは明示的に暫定的。** 「これは 1 枚のスナップショットにすぎず、Claude Cowork はまだ新しい。その用途は急速に変化している」。Anthropic は利用が変わるにつれてデータの公開を続けるとしている。
