# 仕事のまわりの仕事

Anthropic による 2026 年 5 月の Claude Cowork 利用調査をたどり、その分布の形が、知識労働者
が実際に何を委ねているかについて何を語るのかを読む。

## この調査が生まれた背景

2025 年に Claude Code がリリースされたとき、Anthropic は非技術ユーザーがこれほど多く触り
始めたことに驚いた。ターミナルを一度も開いたことのない人たちが、フォルダを整理し、重複ファイル
を取り除き、スプレッドシートの数式を書くエージェントを作っていた。

一方で他の人にとって、ターミナルは依然としてやや威圧的な場所 — 文字どおりの「ブラックボックス」
だった。Claude Cowork は、Claude Code のエージェント機能を、人々がすでに Claude と話すのに
使っていたチャットインターフェースへ広げるために作られた。

1 月のローンチ以来、Cowork は情報の生成と交換を中心に働く人たち、いわゆる知識労働者にとって
とりわけ強力な道具になった。この調査は、その層がエージェントで実際に何をしているのかを問う。

## データが示すもの

サンプル: 2026 年 5 月 11〜31 日、60 万を超える組織からの匿名化・集計済みセッション 120 万
件。自動分類システムが 20 カテゴリの業務分類体系に沿ってラベリングした。

| カテゴリ | シェア |
| --- | --- |
| ビジネスプロセスとオペレーション | 33.4% |
| コンテンツ制作とコピーライティング | 16.4% |
| ソフトウェア開発 | 8.7% |
| DevOps とインフラ | 7% |
| リサーチとインテリジェンス | 6.4% |
| データ分析とビジネスインテリジェンス | 5.8% |
| ドキュメント処理と抽出 | 4.1% |
| セールスとレベニューオペレーション | 4% |
| パーソナルアシスタンス | 3.8% |
| 教育 | 2.4% |
| 会議・会話インテリジェンス | 1.8% |
| 法務とコンプライアンス | 1.3% |
| カスタマーサポート | 0.8% |

**ビジネスプロセスとオペレーション**が 33.4% で首位。散らばった更新を 1 本のレポートにまとめ、
オンボーディングのチェックリストを作り、スプレッドシートを突き合わせる作業だ。ビジネス
オペレーションの仕事は多くの職種にまたがるので、これは筋が通る。財務・人事・管理の職に就く人は
いずれもこうしたタスクを手にする可能性が高い。

**コンテンツ制作とコピーライティング**が 16.4% で続く。ドラフト、スライドデッキ、投稿、提案書
のような統合作業の比重が大きいビジネスコミュニケーションだ。白紙を前にすることが着手の最初の
壁になることは多く、エージェントは考えと情報を織って粗い草稿にするのに役立つ。これらの
タスクも職種を横断する。マーケティング、広報、事業開発、プロジェクト管理がここに入る。

残りはすべて 9% 未満だ。4% 未満のカテゴリにはパーソナルアシスタンス(3.8%)、教育(2.4%)、
会議インテリジェンス(1.8%)が含まれる。

## 知識労働者は AI をどう使っているか

上位 2 カテゴリが利用全体のおよそ半分を占めることは示唆的だ。どちらも圧倒的に「つなぐ」性質を
持つ。

- スプレッドシートは、ばらばらのデータ点を、読み・比べ・追跡できる文脈にまとめる。
- デッキは、文脈の量がまちまちな広い相手にアイデアや決定を伝える。
- オンボーディングのチェックリストは、新入社員が組織の知識に接続する助けになる。

Anthropic が示す読み方はこうだ。人々は、自分の専門性を発揮するために使う情報を集めて構造化
するために Cowork を使っている。記事にある 3 つの例:

- **弁護士**は書類の書式と提出を渡し、難しい案件に法的判断を注ぐ時間を得る。
- **採用担当**はミーティングの日程調整と面接フィードバックの統合を渡し、候補者との対話や
  ワークサンプルの評価に充てる時間を得る。
- **チームリード**は難しい決定を説明するスライドデッキを渡し、その難しい決定を実際に下すことに
  集中できるようになる。

3 例とも境界は一貫している。組み立てと構造化はエージェントへ移り、専門性は人に残る。

## Claude Code との対比

このパターンは Claude Code の使われ方のほぼ裏返しだ。Claude Code は主にソフトウェア開発者が、
職務の中心である構築・デバッグ・出荷に使う。だから Cowork の利用でソフトウェア開発が 8.7%
という小さな比率にとどまるのは、おそらく驚くことではない。

開発者がコードを書くとき、Cowork より Claude Code を使う可能性のほうがはるかに高い。彼らが
Cowork でしているのは、ソフトウェアエンジニアリングを含むあらゆる職務を取り巻く、つなぐ・
伝えるための仕事だ。

したがってチャット型エージェントでソフトウェア開発のシェアが低いのは、ツールの分化による
当然の結果であり、開発者の導入が弱い証拠ではない。

## 知識労働における AI の広がり

コーディングは今なお — もっともなことに — AI 用途の中で最も注目を集める。しかし日々の業務に
AI を使う流れは広がっており、最も役立つタスクの輪郭が見えてきている。ステータスレポート、
デッキ、トラッカー、そしてチーム間で情報を追跡し伝えるためのその他の仕組みだ。

Anthropic はこれを、新しく急速に進化する製品の 1 枚のスナップショットと位置づけ、AI を日々の
仕事に組み込もうとしている人のための参照点とし、利用が変わるにつれてさらにデータを公開すると
約束している。

## 数字を責任をもって読む

ここでは記事自身の方法論の節が案内役になる。

**測定方法。** 自動システムが 20 カテゴリの分類体系にセッションを分類した。ユーザー情報を
すべて匿名に保つプライバシー保護型の分析ツールを用い、人間のアナリストが個々のセッションを
読むことはなく、カテゴリ単位の集計統計だけを扱った。サンプリングは上限方式 — トラフィックの
一定割合ではなく、1 時間あたり固定の最大セッション数 — だった。

**分類体系の粒度。** 分類体系は、行った人の肩書きではなく行われた仕事でセッションを分ける。
マーケティング・財務・人事の独立カテゴリはなく、それらの機能は「ビジネスプロセスと
オペレーション」に最もよく対応する。それがこのカテゴリが利用の 3 分の 1 を占める理由の一部
だろう。

**シェアと総量。** サンプリングが上限方式であるため、セッション数と組織数は利用総量や成長を
表さず、混み合う時間帯は静かな時間帯に比べてやや過小に現れる。

**期間の選択。** より長い期間ではなく直近の完全な 3 週間を用いたのは、5 月 11 日前後に
カテゴリのシェアが、ユーザー行動の変化ではなくラベリングパイプラインの変更と整合する形で
動いたためだ。報告されたシェアはすべてその変更後に計算されており、どちらの説明の下でも正しい。

**業務利用と個人利用の混在。** サンプルは個人ではなく外部組織での利用を対象とするが、個人利用
も含まれる。パーソナルアシスタンス、趣味、伴走的な会話を合わせるとセッションの約 5% になる。

**自動分類。** ラベルは人間のレビュアーではなく自動システムが付けており、どんな分類器にも誤り
はありうる。セッションが複数のカテゴリにもっともらしく当てはまる場合、結果は分類体系の定義に
左右された。

## ここから持ち帰るもの

- まず組み立てと構造化を委ねる。公開された利用の重心はすでにそこにある。
- 判断は手元に残す。法的判断、候補者の評価、デッキが説明するその決定。
- コード用エージェントとチャット用エージェントが正反対の利用構成を示すのは当然であり、導入の
  失敗と読まない。
- 自社の利用データを報告するときは、シェアと並べて制約も公開する。
