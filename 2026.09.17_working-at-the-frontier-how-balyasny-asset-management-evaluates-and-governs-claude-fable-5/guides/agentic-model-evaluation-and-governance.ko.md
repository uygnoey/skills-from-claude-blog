# 에이전트 업무를 위한 프런티어 모델 평가와 거버넌스

Balyasny Asset Management가 Claude Fable 5 도입 과정을 소개한 글(2026년 9월)의 방법론입니다.

## 1. 켜기 전에 평가한다
- 자기 영역의 검증 가능한 실제 과제 수천 개를 쓴다(BAM: 주식·매크로·원자재).
- 모델 단독으로, **그리고** 사용자와 같은 도구·파일·요구사항을 갖춘 에이전트 하네스 안에서 시험한다.
- 계획, 도구 선택과 사용, 근거 탐색과 분석, 오류 복구, 중간 결과 점검, 근거 있는 산출물을 평가한다.
  수치 오류, 누락된 범위, 근거 없는 결론, 검색 문제를 살핀다.
- BAM 결과: 관련 부분집합에서 Fable 89.4%, 기존 프로덕션 모델 86.1%.

## 2. 의외의 성과는 검증 전까지 의심한다
너무 좋아 보이는 결과는 평가를 다시 돌리고, 과제와 채점 로직을 독립적으로 점검하고, 모델 제공사와 함께
검토한 뒤에 받아들인다.

## 3. 근거로 모델을 라우팅한다
영역별로 결과를 나눠 모델 선택과 라우팅에 쓴다. 효율과 비용을 기준으로 언제 어떤 모델을 쓸지 안내한다.
오류가 뒤로 번지는 계획·분석 단계에는 가장 강한 모델을 둔다.

## 4. 통제는 모델 바깥에 둔다
| 통제 | 목적 |
|---|---|
| 승인된 데이터 경계 | 허가된 데이터만 보게 함 |
| 최소 권한 | 사용자와 과제 범위로 한정 |
| 도구 단위 권한 | 가능한 행동 제한 |
| 로깅과 추적성 | 문제 탐지·추적 |
| 중요한 산출물의 사람 검토 | 검토 없이 의존하지 않음 |
| 에스컬레이션 경로 | 예외 상황을 사람에게 전달 |
| 적대적·실패 시나리오 시험 | 접근 확대 전에 수행 |

능력이 권한을 주지 않는다: 더 나은 모델이라도 접근이 늘지 않고, 스스로 권한을 줄 수도 없다.
투자(업무) 판단은 사람의 몫이다.

## 5. 통제된 플랫폼으로 배포한다
BAMAgent의 에이전트는 계획하고, 승인된 사내 시스템을 쓰고, 분석을 돌리고, 중간 산출물을 점검한 뒤
검토 가능한 결과물을 돌려준다. 하네스(워크플로 설계, 데이터·도구 접근, 검색 컨텍스트, 권한, 모니터링,
사람 검토)와 모델의 추론이 모두 있어야 프로덕션 품질이 나온다.

## 6. 다른 회사에 주는 조언
- 실제·검증 가능한 과제로 된 평가 체계에 일찍 투자하고 모델 선택과 라우팅에 활용한다.
- 사용자가 쓸 것과 같은 환경·도구로 시험한다.
- 안전을 운영 모델의 문제로 보고, 통제는 모델 바깥에 둔다.
- 기업이 정책을 집행하면서도 에이전트 가치를 극대화하는 호스티드 에이전트 전략을 세운다.
- 기존 프로세스 자동화만이 아니라 결과에 이르는 더 나은 방법이 있는지 묻는다.
