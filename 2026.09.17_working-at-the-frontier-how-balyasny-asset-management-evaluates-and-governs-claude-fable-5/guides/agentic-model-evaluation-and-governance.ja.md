# エージェント業務のためのフロンティアモデル評価とガバナンス

Balyasny Asset Management による Claude Fable 5 導入の紹介記事（2026年9月）から整理した方法論です。

## 1. 有効化する前に評価する
- 自社領域の検証可能な実タスクを数千件使う（BAM：株式・マクロ・コモディティ）。
- モデル単体で、**そして**ユーザーと同じツール・ファイル・要件を備えたエージェントハーネス内でテストする。
- 計画、ツールの選択と使用、根拠の探索と分析、エラーからの回復、中間結果の確認、根拠ある成果物を評価する。
  数値ミス、カバー漏れ、根拠のない結論、検索の問題に注意する。
- BAM の結果：該当サブセットで Fable 89.4%、従来の本番モデル 86.1%。

## 2. 意外な好結果は検証まで疑う
良すぎる結果は、評価を再実行し、タスクと採点ロジックを独立に確認し、モデル提供元とレビューしてから受け入れる。

## 3. 根拠に基づいてモデルをルーティングする
結果を領域別に分け、モデル選択とルーティングに使う。効率とコストを基準に、どのモデルをいつ使うかの指針を示す。
誤りが後工程に波及する計画・分析には最も強いモデルを置く。

## 4. 統制はモデルの外側に置く
| 統制 | 目的 |
|---|---|
| 承認済みデータ境界 | 許可されたデータのみ参照 |
| 最小権限 | ユーザーとタスクの範囲に限定 |
| ツール単位の権限 | 可能な操作を制限 |
| ログとトレーサビリティ | 問題の検知と追跡 |
| 重要な成果物の人によるレビュー | 未レビューの成果に依存しない |
| エスカレーション経路 | 例外を人に届ける |
| 敵対的・障害シナリオのテスト | アクセス拡大の前に実施 |

能力は権限を与えない：より良いモデルでもアクセスは広がらず、自ら権限を付与することもできない。
投資（業務）判断は人が担う。

## 5. 統制されたプラットフォームで展開する
BAMAgent のエージェントは計画し、承認済みの社内システムを使い、分析を実行し、中間成果物を確認して、
レビュー可能な成果物を返す。ハーネス（ワークフロー設計、データ・ツールアクセス、検索コンテキスト、権限、
モニタリング、人によるレビュー）とモデルの推論の両方が本番品質に必要とされる。

## 6. 他社へのアドバイス
- 実際の検証可能なタスクに基づく評価体制に早期投資し、モデル選択とルーティングに活用する。
- ユーザーと同じ環境・同じツールでテストする。
- 安全性を運用モデルの問題として扱い、統制はモデルの外側に置く。
- 企業がポリシーを適用しつつエージェントの価値を最大化できるホスト型エージェント戦略を立てる。
- 既存プロセスの自動化だけでなく、成果に至るより良い方法がないかを問う。
