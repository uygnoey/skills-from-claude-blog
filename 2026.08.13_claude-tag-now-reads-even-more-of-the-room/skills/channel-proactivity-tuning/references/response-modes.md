# The four response modes

When a message arrives in a channel the agent is in, it makes one of four choices. The choice is now informed by context from across the channel, together with the agent's memory and the standing instructions it has been given — not by the single message in isolation.

## 1. Reply inline
For short, verifiable answers. The bar is that the answer is brief and that the reader can check it. Inline replies keep the channel readable; they are the wrong mode for anything that needs sourcing or several steps of reasoning.

## 2. Start deeper work in a thread
For complex issues. Threading keeps the channel clean while the work happens, and it produces a record attached to the message that prompted it. Use this for anything that needs multiple sources, several steps, or a caveat.

## 3. Route to an existing workstream
When the message belongs to work that is already underway. Routing avoids starting a parallel effort on something the team is already handling and keeps the history in one place.

## 4. Stay silent
When contributing would not help. This is a deliberate choice, evaluated the same way the other three are — not an absence of a decision. A channel-specific rubric weighs usefulness and confidence, and silence is the correct output when either falls short.

## Choosing between them per channel
The mode mix is a channel-level decision. Some useful questions to answer in the standing instructions:

- What counts as "short and verifiable" in this channel?
- What kinds of question always deserve a thread?
- Which recurring topics already have a workstream to route to?
- What should never draw a proactive response at all?
