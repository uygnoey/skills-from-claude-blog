# Designs that are also their own tools

Four examples from Nate Parrott's own work, and the pattern they share: when the
thing you need is hard to describe or hard to hand-craft, ask for an instrument
instead of a result.

## The intro animation

The animation that plays when you sign up for Claude Design was made in the tool
itself — but not directly. In his words: "I'm not an animator, so I first had
Claude Design build me a bespoke video editor, then used that editor to make the
animation."

The pattern: a missing craft skill is not a reason to prompt harder for the
finished artifact. It is a reason to ask for the tool that lets you make it.

## The subway-times app

A subway-times app with adjustable animation controls, built so the physics of the
motion could be dialed in.

The pattern: motion is a parameter space, and words are a poor interface to a
parameter space. Build the sliders, then feel your way to the value.

## Instagram-style color controls

Rather than describing colors in words, ask for the app's color scheme to be
tweakable with sliders and presets.

The pattern: replace adjectives with controls. "Warmer" is a negotiation; a
temperature slider is an answer.

## A redesign of the editor itself

Parrott and two teammates, Helen and Andrew, have been riffing on a new design for
the editor, inside the tool. It won't ship as-is — it's how they explore what the
product could become.

The pattern: an artifact whose purpose is exploration doesn't have to be shippable
to be worth making. Its job is to be looked at together.

## Why this matters

From Bret Victor's talk "Stop Drawing Dead Fish", which the post cites: "Everything
we draw should be alive by default."

Parrott's favorite creations are the ones that don't fit into existing boxes: docs
with interactive simulations, slide decks that talk to you, diagrams that are also
videos, designs that are also their own editors. Code — specifically HTML — is an
amazing medium for creativity, and it is finally somewhat easy for designers to
create with.

## Applying it

When you are about to ask for a static artifact, ask one question first: what would
an interactive version of this show that the static one can't? If the answer is
"nothing", make the static one. If the answer is a parameter you would otherwise
argue about in words, build the control.
