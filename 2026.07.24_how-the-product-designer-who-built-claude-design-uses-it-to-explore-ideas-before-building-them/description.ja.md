## この記事について
Anthropic のプロダクトデザイナー Nate Parrott が、自ら作った道具 — 現在ベータの Claude Design — がどう生まれ、自分がそれを日々どう使っているかを一人称で綴った記事。

出発点はスループットのずれだ。2025 年秋、Parrott は Claude Code for VS Code の唯一のプロダクトデザイナーとして、エンジニア 2 人と組んでいた。9 月末にベータを出し、11 月に Opus 4.5 が届き、チームは速く出荷し始めた。「エンジニアたちは以前よりはるかに多く出荷していたが、自分は相変わらずいつものペースでしか届けられていなかった。追いつく方法を見つける必要があった。」

最初の試みは、ターミナルがすべてをそう扱うように、デザインをテキストとして扱った。出力を Claude に貼り、スクリーンショットを添え、機能をデザインしてほしいと頼む。結果は良くなかった。突破口は、Claude が HTML をとても得意とすること、そして HTML が単なるウェブサイトの形式ではないことに気づいたことだった。「スライドデッキや動画ファイル、PDF で作れるものは何でも、ウェブページで作れる。」彼は Claude に HTML を作らせ、左にチャット・右にライブ出力という分割ビューを与えた。次に、Anthropic のブランド(フォント、カラー、アセット、原則)の本質をプロンプトへ蒸留することに時間を割き、出力がブランドガイドに沿うようにした。デザイナーたちはこの社内プロトタイプを、インタラクティブなプロトタイプ用にすぐ使い始めた。従来のデザインツールでクリックスループロトタイプを作るには、あらゆる画面のあらゆる状態をモックし手で結線しなければならないが、ここではアセットを渡して「動くようにして」と言えばいい。

本物のプロジェクトになった契機は、Anthropic Labs チームのオフサイトでのアイデアピッチだった。「その場の全員がこれでスライドをでっち上げていた。自分の発表順の直前、会議の最中に作ることも多かった。」枠組みはプロダクトのモックアップから、あらゆる視覚コミュニケーション — スライドデッキ、ランディングページ、PDF で印刷する 1 枚もの、メール、アニメーション、SNS 用ビジュアル — へ広がった。Parrott はそれを「プロダクトデザインの一段上」と表現する。

記事は境界も引く。画像モデルがないのでロゴデザインには向かない。すでに持っているロゴとアセットを持ち込むほうがいい。プロダクション用ソフトウェアを出荷するなら Claude Code を使う。両者は往復する。Claude Code で始めたプロトタイプを Claude Design に同期してキャンバス上で反復し、作る準備ができたら Claude Design から Claude Code へ引き渡す。記事の大半は 10 の具体的な実践であり、最後は Bret Victor の講演「Stop Drawing Dead Fish」を引きながら、生きているデザインを作ろうという主張で閉じられる。

## どんなときに役立つか
- エンジニアリングのスループットがデザインのスループットを追い越し、デザイン工程が制約になったとき。
- フィードバックを集めるために 1 つのフローの 15 通りが必要なのに、あらゆる状態をモックして手で結線する従来のクリックスループロトタイピングでは遅すぎるとき。
- ある作業がデザインツール、Claude Design、Claude Code のどこに属するかを判断するとき。
- 生成されるビジュアルがいつも当たり障りのない美学に流れてしまい、方向づけが必要なとき。
- 同じブランド・デッキ・コンポーネント一式があらゆる成果物に登場し、白紙ではなく再利用できる出発点がほしいとき。
- 誰かが実装に着手する前に、方向性への合意が必要なとき。

## 主なポイント
- **HTML は出力形式ではなく媒体だ。** テキスト+スクリーンショットが失敗した後、HTML をデッキ・動画・PDF にできることすべてができる、豊かでインタラクティブな視覚媒体として扱ったことが、デザイン出力を良くした。
- **ブランドはプロンプトに入れる。** フォント・カラー・アセット・原則をプロンプトへ蒸留する作業が、出力を後からの修正ではなく既定でブランド準拠にする。
- **価値は実装より前にある。** 「Claude Code はコーディングのため。Claude Design はデザイン業務のそれ以外の部分 — 初期のアイデア出し、コラボレーション、誰かが実装に着手する前に方向性の合意を得ること — のためだ。」モデルがプロダクション用ソフトウェアを上手に作れるようになるほど、最も重要な仕事は前工程へ移る。良いアイデアを持つこと、全員を揃えること、アイデアがまだ早い段階でフィードバックを集めること。
- **二者択一ではなく往復。** プロトタイプは Claude Code から Claude Design へ同期してキャンバスで反復し、作る準備ができたら Claude Design から Claude Code へ引き渡す。
- **何でないかを知る。** 画像モデルがないためロゴデザインには不向き。手持ちのロゴとアセットを持ち込む。製品全体の形は、Claude が選択肢と出発点を作って白紙を見つめずに済むようにし、そのままで良いもの、あるいは複数版の組み合わせとして良いものを人が選ぶ、というものだ。
- **プロンプトの前に考えを終える。** Parrott はコンピュータから離れた場所でプロンプトを書く。音声入力、スマホのメモアプリ、散歩中のボイスメモ。そうすれば席に着いたとき、Claude はすでに決まったビジョンを実行するだけになる。
- **美学を指示しなければ既定を受け取る。** 「方向づけがなければ、Claude は自分のお気に入りの美学のどれかを選ぶ。たぶん見覚えがあるはずだ。」フォントとカラーを指定する、ムードボードを渡す、フォントとカラーの組み合わせを出させて詰める。
- **10 案もらってリミックスする。** 大半は良くなく、1〜2 案が良い。そして「B 案が好きで、D 案も少し。その 2 つを混ぜた変奏を 5 つちょうだい」と言う。
- **ラストマイルは手で。** 並べ替え、削除、テキスト編集、リサイズ、色変更は直接編集ツールでやるほうがいい。「直接編集はトークンを使わないし、サイズや位置合わせのような細かい判断はどのみち目で見たほうが良い。」
- **本物の文脈を渡す。** GitHub を接続すれば、Claude が既存のコンポーネントや画面を取ってきて出発点にする。デザインが外部情報に依存するときはウェブ検索や MCP 接続も使える。
- **生きたものにする。** Bret Victor の「Stop Drawing Dead Fish」 — 「私たちが描くものはすべて、既定で生きているべきだ」 — を引きつつ、Parrott のお気に入りは既存の枠に収まらない創作物だ。インタラクティブなシミュレーションを含むドキュメント、話しかけてくるスライドデッキ、同時に動画でもある図解、それ自体がエディタであるデザイン。
