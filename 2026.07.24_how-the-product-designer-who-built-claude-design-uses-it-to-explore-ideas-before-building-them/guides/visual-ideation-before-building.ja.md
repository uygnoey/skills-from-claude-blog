# 作る前に視覚で探る

Claude Design がどう生まれ、何のためのもので何のためでないのか、そして作った本人が日々使って
いる 10 の実践。

## 問題: デザインが制約になった

2025 年秋、Nate Parrott は Claude Code for VS Code の唯一のプロダクトデザイナーとして、
エンジニア 2 人と組み、Claude Code のあらゆる機能をターミナルの外の親しみやすい
インターフェースとして描き直す仕事をしていた。9 月末にベータを出荷し、11 月に Opus 4.5 が
届き、Claude Code チームは速く、積極的に出荷し始めた。

「エンジニアたちは以前よりはるかに多く出荷していたが、自分は相変わらずいつものペースでしか
届けられていなかった。追いつく方法を見つける必要があった。」

## 失敗した最初の試み

Claude Code はターミナルで動き、そこではすべてがテキストだ。最初の試みはデザインも同じように
扱った。出力を Claude にコピーし、スクリーンショットを添え、「追加したい機能がここにある。
デザインしてくれないか?」と尋ねる。

結果は良くなかった。その後 1 か月ほど、サイドプロジェクトとしてデザイン出力を良くする方法を
探し続けた。

## 突破口: 媒体としての HTML

やがて答えに行き当たった。Claude は HTML がとても得意だ。そして HTML はウェブサイトのための
形式であるだけではない。「豊かでインタラクティブな視覚媒体でもある。スライドデッキや動画
ファイル、PDF で作れるものは何でも、ウェブページで作れる。」

続いて 2 つの手を打った。

1. **分割ビュー。** Claude に HTML を作らせ、左でチャットし、右で出力を見る。
2. **プロンプトの中のブランド。** プロダクトデザインは、自分が扱う製品とブランドについての
   知識を適用することで動く。そこで Anthropic のブランドの本質 — 製品が使うフォント、
   カラー、アセット、原則 — をプロンプトへ蒸留した。以後、出力は既定でブランドガイドに
   沿うようになった。

デザイナーたちはこの社内プロトタイプを、とくにインタラクティブなプロトタイプ用にすぐ使い
始めた。従来のデザインツールでクリックスループロトタイプを作るには、あらゆる画面のあらゆる
状態をモックし、手で結線しなければならない。ここではアセットを渡して「動くようにして」と言う。
そして出てくる成果物にはどれも、ドキュメントを共有するのと同じように共有できるリンクが付く。

## サイドプロジェクトから本物のプロジェクトへ

はっきりした瞬間は、Anthropic Labs チームのオフサイトでのアイデアピッチだった。「その場の
全員がこれでスライドをでっち上げていた。自分の発表順の直前、会議の最中に作ることも多かった。」
そのセッションが Labs チームを動かし、人員が付いた。

枠組みが広がった。プロダクトのモックアップのための道具であることをやめ、あらゆる視覚
コミュニケーションを作る道具になった。スライドデッキ、ランディングページ、PDF で印刷する
1 枚もの、メール、アニメーション、SNS で共有するビジュアル。Parrott はそれを「プロダクト
デザインの一段上。主な役割が伝えることと考えを形にすることであるビジュアルを、Claude と
一緒に作る」と表現する。

能力はビジョンモデルに追随する。Claude Opus 5 は以前の Opus モデルよりチャート・図・
スクリーンショットを読むのが上手で、発表に耐えるデッキやメモを作る際に Claude Design と
組み合わせると強力だ。

## するつもりのないこと

**ロゴデザイン。** 画像モデルを持たず画像生成のために作られていないので、ロゴには向かない。
「とはいえ、それで人が試すのをやめたわけではない。」より良いやり方は、すでにあるロゴと
アセットを持ち込むことだ。製品の他の部分も同じ仕組みで動く。Claude が選択肢と出発点を作り、
白紙を見つめずに済むようにする。そして人が、単体で良いもの、あるいは複数版の組み合わせとして
良いものを選ぶ。

**プロダクション用ソフトウェア。** プロダクション用ソフトウェアを出荷するなら Claude Code を
使い続けること。Claude Code はコーディングのため。Claude Design はデザイン業務のそれ以外
の部分 — 初期のアイデア出し、コラボレーション、誰かが実装に着手する前に方向性の合意を得ること
— のためだ。

両者は往復する。Claude Code で始めたプロトタイプを Claude Design に同期してキャンバス上で
反復・編集し、作る準備ができたプロトタイプを Claude Design から Claude Code へ引き渡す。

境界が重要な理由はこうだ。「モデルがプロダクション用ソフトウェアを作るのが上手くなるほど、
最も重要な仕事は過程の前のほうへ移る。良いアイデアを持つこと、全員を揃えること、アイデアが
まだ早い段階でフィードバックを集めること。」

## 日々の使い方

いわば主食のデザイン業務だ。初期アイデアのワイヤーフレームを描き、同僚からフィードバックを
集めるためにフローを 15 通り生成する。最近の例:

- **イントロアニメーション。** サインアップ時に流れるアニメーションはツール自体で作られたが、
  直接ではない。「自分はアニメーターではないので、まず Claude Design に専用の動画エディタを
  作らせ、そのエディタでアニメーションを作った。」
- **地下鉄の時刻アプリ。** 動きの物理を詰めるための、調整可能なアニメーションコントロール付き。
- **Instagram 風のカラーコントロール。** 色を言葉で説明する代わりに、スライダーとプリセットで
  アプリの配色を調整する。
- **Claude Design 自体のリデザイン。** 同僚の Helen と Andrew と 3 人で、ツールの中で新しい
  エディタのデザインを試している。そのまま出荷はしない。製品が何になりうるかを探る方法だ。

## 10 の実践

1. **プロンプトの前に考えを終える。** 必要なものを先に伝える。Parrott はデザインの前に
   プロンプトを書くことに多くの時間を使う。音声ボタンで口述したり、ソファでスマホのメモアプリ
   に打ち込んだり、散歩中にボイスメモを録って後で書き起こしを貼ったりする。コンピュータから
   離れているうちに何が欲しいかを決めておけば、席に着いたとき Claude はそのビジョンを正確に
   実行できる。
2. **どう見えるべきかを伝える。** 「方向づけがなければ、Claude は自分のお気に入りの美学の
   どれかを選ぶ。たぶん見覚えがあるはずだ。」フォントとカラーを指定する、インスピレーション用
   のムードボードを渡す、フォントとカラーの組み合わせをブレインストーミングさせてしっくり
   来るまでやり取りする。
3. **繰り返す作業をデザインシステムにする。** ブランドファイルとアセット — ロゴ、スライド
   デッキ、スクリーンショット、タイポグラフィ仕様、そのほか再利用するもの — をアップロード
   すれば、Claude が分析してデザインシステムを生成する。以後、作る成果物はどれも白紙ではなく
   あなたの選択から始まる。
4. **10 案もらって、リミックスする。** 大半は良くない。それでいい。1〜2 案は良い。そして
   「B 案が好きで、D 案も少し。その 2 つを混ぜた変奏を 5 つちょうだい」と言う。
5. **説明できないものは描く。** レイアウトが頭にあって言葉にできないなら、紙に描いて写真を
   アップロードする。
6. **指して、話す。** どの要素のことかを一段落かけて書く代わりに、クリックして話す。端末の
   音声入力を有効にし、「comment」を選んでコメント欄をクリックすると、打ち込んだように言葉が
   入る。
7. **忠実度が重要でないときはワイヤーフレームから。** はるかに速く、Claude をビジュアルでは
   なく高いレベルの構造に集中させられる。多くのアイデアを素早く試す優れた方法だ。
8. **ラストマイルは手で。** 並べ替え、削除、テキスト編集、リサイズ、色変更といった仕上げは、
   プロンプトではなく直接編集ツールで行う。「直接編集はトークンを使わないし、サイズや
   位置合わせのような細かい判断はどのみち目で見たほうが良い。」
9. **本物の文脈を渡す。** 既存のアプリやサイトの機能をデザインするなら GitHub を接続する。
   Claude がコンポーネントや既存画面を取ってきて出発点にし、何度か試せば既存デザインをかなり
   高い忠実度で再現できる。デザインが外部情報に依存するときは、ウェブ検索や MCP 接続も使える。
10. **Claude と並走し続ける。** 完成した結果を待ってから新しい変更や作業を頼む必要はない。
    複数のメッセージをまとめてキューに入れてもいいし、Claude が前のターンを処理している間も
    話し続けていい。

## 生きたものにする

デザイナーなら一度は見ておくべき Bret Victor の講演がある。「Stop Drawing Dead Fish」だ。
紹介文にはこうある。「私たちが描くものはすべて、既定で生きているべきだ。」

Parrott は、このツールであれ他のどんなツールであれ、デザイナーが自分の創作物を生きたものに
する方法を考えることを勧める。彼のお気に入りの創作物は、既存の枠に収まらないものだ。
インタラクティブなシミュレーションを含むドキュメント、話しかけてくるスライドデッキ、同時に
動画でもある図解、それ自体がエディタであるデザイン。コード、とりわけ HTML は創造のための
素晴らしい媒体であり、ようやくデザイナーにとってもそれなりに作りやすいものになった。

Claude Design が今の形になったのは、Anthropic の人たちが彼の想定しなかった使い道を見つけ
続けたからだ。現在は Claude Pro、Max、Team、Enterprise の各プランでベータ提供されている。
「まだ私たちが考えていないどこかへ持っていってほしい。」
