# コンテキストエンジニアリングの新しいルール

Anthropic は Claude 5 世代のモデル向けに、**Claude Code のシステムプロンプトの 80% 以上を削除**した。
コーディング評価で測定可能な性能低下はなかった。ここから引き出せる一般的な教訓はこうだ。以前の世代の
モデルをうまく動かしていたコンテキストエンジニアリングは、新しい世代をうまく動かすものとは違う。そして
その多くは、いまでは邪魔になっている。

## Claude の足かせを外す

従来のやり方は Claude を過剰に制約していた。ルールはシステムプロンプト、CLAUDE.md ファイル、スキルという
3 つの層にわたって積み上がり、ある量を超えると互いに衝突しはじめた。ある層は「適切にドキュメントを残せ」
と言い、別の層は「コメントを追加するな」と言う。両方には従えない。

新しいモデルは、そうした足場がなくてもユーザーが本当に望んでいることを解釈できる。だから足場のうち残るのは
害のある部分だけだ。何の見返りもなく振る舞いを狭める、矛盾した命令である。それらを取り除くのは指針を失う
ことではなく、足かせを外すことだ。

変わったことのもう一つは、コンテキストが置ける場所だ。かつて Claude は、メモリ・情報・指針のすべてを
CLAUDE.md に頼っていた。いまはメモリ、アーティファクト、スキルがあり、Claude はそれらを使ってセッションを
またいでコンテキストを読み込み共有する方法を自分で組み立てられる。CLAUDE.md がすべてを背負わなくてよく
なったのはそのためだ。

## 6 つの転換

**1. ルールを与える → 判断に任せる。** 以前の記述はこうだった。デフォルトではコメントを書かない、複数
段落の docstring や複数行のコメントブロックは決して書かない、短い 1 行まで。新しい記述はこうだ。周囲の
コードのように読めるコードを書く — コメントの密度、命名、イディオムを周囲に合わせる。禁止条項はある基準の
代役にすぎなかった。その基準をそのまま述べればいい。

**2. 例を与える → インターフェースを設計する。** 新しいモデルにとって使用例は単なる説明ではなく**制約**
として働き、例がカバーする探索空間にモデルを縛りつける。教える役割はツール自体に移そう。表現力のある
パラメータと、シグネチャを見ただけで正しい使い方が分かるほど明確に列挙された選択肢がそれを担う。

**3. すべてを前もって置く → プログレッシブディスクロージャ。** 必要になるかもしれないものをすべて
システムプロンプトに載せるのではなく、スキルと遅延読み込みツールを通じてコンテキストを選択的に読み込む。
そうすれば適切な指針が適切なタイミングで届く。

**4. 繰り返す → シンプルなツール説明。** 以前は同じ指示がシステムプロンプトにもツール説明にも入っていた。
これからはツール説明だけに置く。以前のモデルは繰り返しから恩恵を受けたが、いまのモデルはツール説明を確実に
参照する。重複は同期すべき対象が一つ増えるだけだ。

**5. CLAUDE.md 内のメモリ → 自動メモリ。** `#` ホットキーで手動でコンテキストを固定する方式はもう必要
ない。Claude が作業とユーザーに関連するメモリを自動的に保持する。

**6. 単純な仕様 → 豊かなリファレンス。** Markdown の計画書は忠実度の低い選択肢だ。HTML アーティファクト、
コードリファレンス、テストスイート、ルーブリックは同じ意図をはるかに少ない曖昧さで伝えられるし、Claude は
ますます複雑なリファレンスを扱える。

## いま各層が担う役割

**システムプロンプト。** プロダクトのコンテキストだ。このエージェントがどのプロダクトの中でどんな役割を
果たすのかを定める。Claude Code のユーザーが手を入れることはまれだが、独自のエージェントを作るなら相応の
労力を注ぐ価値がある層だ。

**CLAUDE.md。** 軽量に保つ。リポジトリの説明と、教えてもらわなければ発見できない落とし穴に集中する。指示が
複雑になったらファイルを太らせず、別のスキルに移してプログレッシブディスクロージャに任せる。

**スキル。** 必要なときに情報を見つけるための軽量なガイドだ。決定的に重要な領域を除いて過剰に制約せず、
チームやプロダクトに固有の考え方とベストプラクティスを書き込む。長いスキルは複数ファイルに分割する。

**リファレンス。** 深さが入る場所。@メンションで仕様、モックアップ、コードベースを持ち込む。明快さと忠実さ
のため、説明的なテキストよりコードを優先する。

## どこから始めるか

Claude Code で `/doctor`（CLI では `claude doctor`）を実行する。スキル、CLAUDE.md ファイル、システム
プロンプトを Claude 5 世代のモデルに合わせて自動的に適正サイズに整えてくれる。機械的な部分はここまでだ。
手で直すのはその先 — 層と層の矛盾、そしてモデルにもう存在しない制限を回避するために書かれたルールである。

そのうえで測定する。80% という数字には評価が伴っていた。「測定可能な損失なし」は前提にするものではなく、
自分のエージェントについても言えるようにしておきたい主張だ。

記事の言葉を借りれば、私たちがそうしたように、あなたも単純化する必要があるかもしれない。
