## この記事について
一般的なトークン課金のワークロードで Opus 5 より約 40% 安く動くと見積もられる Claude Opus 5.5 が、なぜ長く
コンテキストの多い Claude Code セッションで最も節約になるのかを説明する記事です。2026 年 3〜9 月の Claude Code
利用傾向を共有し、節約の要因を価格、Claude Code ハーネスのキャッシュ活用の改善、ターン数の削減に分けて解説し、
キャッシュ読み取りを守る習慣で締めくくります。

## どんなときに役立つか
- トークン課金の Claude Code の支出が増えており、何に使われているか知りたいとき
- セッションが長い、または無人で動いていて、キャッシュヒット率を高く保ちたいとき
- どのタスクを Opus 5.5 に任せるべきか判断するとき

## 主なポイント
- 傾向(2026 年 3 月→9 月): プロンプトあたりの作業時間は 3.3 倍、モデル呼び出しは 40% 以上増加、中断は 68% 減少。
  ツールサーバーやスキルの利用は約 2 倍、リクエストあたりのコンテキストは 2.6 倍、入力:出力トークン比は
  189:1 から 324:1 に。
- 価格: 入力・出力トークンは 20% 値下げ、キャッシュ読み取りは 60% 値下げ。エージェント型コーディングのコストの
  大半はキャッシュ読み取りなので、コンテキストが増えるほど効果が大きくなります。
- Claude Code ハーネス: キャッシュを外した入力は 50% 超減少。ログインの更新、会話途中の指示追加、ツールの
  オンデマンド読み込みでキャッシュが壊れにくくなり、Opus 5.5 と Fable 5.1 ではセッション中に effort を変えても
  キャッシュはリセットされません。API・クラウド利用者も 1 時間のキャッシュ有効期間を使え、フォークした
  サブエージェントは親のキャッシュから始まります。
- ターン数の削減: Zeta Labs ではターンとツール呼び出しが減り、コストはほぼ半分、最難関タスクの完了数は 2 倍に。
  効果は自由度の高いタスクで最大なので、自分のコードベースで測定しましょう。
- 出力生成は Opus 5 より 30% 以上高速です。
- 習慣: `/usage` でキャッシュ読み取りの割合を確認、モデルはセッション開始時に選ぶ、席を外す前にコンパクト、
  API キーやクラウドプロバイダーでは 1 時間のキャッシュ有効期間を設定。
