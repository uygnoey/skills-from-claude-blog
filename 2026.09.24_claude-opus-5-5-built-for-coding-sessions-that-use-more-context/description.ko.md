## 이 글이 뭔가요
일반적인 토큰 과금 워크로드에서 Opus 5보다 약 40% 저렴할 것으로 추정되는 Claude Opus 5.5가, 왜 길고
컨텍스트가 많은 Claude Code 세션에서 가장 크게 절약되는지 설명하는 글입니다. 2026년 3~9월 Claude Code 사용
추세를 공유하고, 절감 요인을 가격, Claude Code 하네스의 캐시 활용 개선, 더 적은 턴 수로 나눈 뒤, 캐시 읽기를
지키는 습관으로 마무리합니다.

## 언제 유용한가요
- 토큰 과금 Claude Code 비용이 늘고 있어 어디에 쓰이는지 알고 싶을 때
- 세션이 길거나 무인으로 돌아 캐시 적중률을 높게 유지하고 싶을 때
- 어떤 작업을 Opus 5.5에 맡길지 판단할 때

## 핵심 포인트
- 추세(2026년 3월→9월): 프롬프트당 Claude 작업 시간 3.3배, 모델 호출 40% 이상 증가, 중단 68% 감소. 도구
  서버·스킬 사용은 약 2배, 요청당 컨텍스트는 2.6배, 입력:출력 토큰 비율은 189:1에서 324:1로 증가.
- 가격: 입력·출력 토큰 20% 인하, 캐시 읽기 60% 인하. 에이전트 코딩 비용의 대부분이 캐시 읽기라 컨텍스트가
  커질수록 효과가 커집니다.
- Claude Code 하네스: 캐시를 놓친 입력이 50% 넘게 감소. 로그인 갱신, 대화 중 지시 추가, 도구 온디맨드 로딩으로
  캐시가 깨지기 어려워졌고, Opus 5.5·Fable 5.1에서는 세션 중 effort 변경이 캐시를 초기화하지 않습니다. API·
  클라우드 사용자도 1시간 캐시 수명을 쓸 수 있고, 포크된 서브에이전트는 부모의 캐시에서 시작합니다.
- 더 적은 턴: Zeta Labs는 턴과 도구 호출이 줄고 비용은 거의 절반, 가장 어려운 작업 완료 수는 2배였습니다.
  효과는 개방형 작업에서 가장 크니 자신의 코드베이스에서 직접 측정하세요.
- 출력 생성 속도는 Opus 5보다 30% 이상 빠릅니다.
- 습관: `/usage`로 캐시 읽기 비중 확인, 세션 시작 시 모델 선택, 자리를 비우기 전에 컴팩트, API 키·클라우드
  사용 시 1시간 캐시 수명 설정.

## 번들 리소스
- Skill: `protect-cached-reads` — 긴 Claude Code 세션의 캐시 효율을 지키고 Opus 5.5에 맡길 작업을 고르는
  습관. 사용 추세와 가격 수치 레퍼런스 포함.
