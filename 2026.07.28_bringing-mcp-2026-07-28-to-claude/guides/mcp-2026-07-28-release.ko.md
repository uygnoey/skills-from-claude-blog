# MCP 2026-07-28을 Claude로

Model Context Protocol의 다섯 번째 스펙 릴리스인 MCP 2026-07-28이 2026년 7월 28일 공개됐다. 이번 스펙은
MCP를 스테이트리스 코어로 옮기는 한편, 인가를 강화하고 공식 확장을 정식화한다. 지원은 Claude 제품 전반에
순차적으로 적용되고 있다.

## 이 릴리스가 중요한 이유

MCP는 최근 **월 4억 회 SDK 다운로드**를 넘어섰다. 올해 들어 4배 증가한 수치이며, AI 에이전트를 애플리케이션에
연결하는 업계 표준으로 자리 잡았다. 공지는 2026-07-28을 지금까지 가장 중요한 스펙 릴리스 중 하나로 소개한다.

### 스테이트리스 코어

MCP가 양방향 상태 유지 프로토콜에서 **요청/응답 모델**로 옮겨 간다. 이제 서버를 서버리스와 엣지 인프라에
배포할 수 있다. Claude용 MCP 서버를 만드는 경험이 단순해지고, 채택이 늘어남에 따라 사용량을 확장하기도 쉬워진다.

서버 작성자에게 실질적인 질문은 지금 세션별 상태가 어디에 있느냐다. 장기 연결을 전제로 하던 것은 모두 옮겨져야
한다. 요청 안으로, 서버가 조회하는 저장소로, 또는 Task로.

### 표준화된 확장

**MCP Apps**와 **Tasks**가 이제 **버전 관리되는 확장 프레임워크** 아래로 들어온다. 코어 프로토콜을 바꾸지 않고도
인터랙티브 UI나 장시간 실행 작업 같은 기능을 추가할 수 있는 공식 경로가 생긴 것이다. 프레임워크가 버전 관리되므로,
서버는 클라이언트가 모든 것을 지원한다고 가정하는 대신 자신이 구현한 확장 버전을 선언할 수 있다.

### 인가 강화

인가가 이제 **프로덕션 OAuth 2.0 및 OIDC 배포와 정렬**된다. 따라서 MCP 서버는 **Entra**나 **Okta** 같은 엔터프라이즈
아이덴티티 시스템에 우회 처리 없이 연결된다. 이전 스펙의 빈틈을 메우려 붙여 놓은 커스텀 인증 접착 코드가 가장 먼저
지울 대상이다.

## 베타 기간 동안 빌더들이 말한 것

생태계 전반의 기업들이 베타 이후 MCP 커뮤니티와 함께 새 스펙 위에서 개발해 왔다.

**Figma**(Josh Clemm, VP of Engineering)는 더 많은 빌더가 자사 MCP 서버로 생성 결과물을 Figma 캔버스로 가져와,
팀과 함께 탐색하고 변주하며 돋보이는 제품으로 다듬고 있다고 말한다. 사용량이 늘어도 스테이트리스 아키텍처가 함께
확장되며, MCP Apps·Tasks·Enterprise-Managed Auth 덕분에 디자인과 코드를 하나의 연결된 흐름 안에 두는 일을 더
잘할 수 있게 됐다.

**Intuit**(Chris Kasten, Chief Architect 겸 SVP of Engineering, Platform and Development Xceleration Group)은
새 스펙을 지지한다. 스테이트리스 프로토콜 코어와 MCP Apps·Tasks를 포함한 확장 프레임워크 덕분에 자사 기술진과
고객이 엔터프라이즈 규모로 에이전틱 경험을 만들고 연결할 수 있으며, 1억 명의 소비자와 사업자에게 신뢰할 수 있는
금융 인텔리전스 경험을 그들이 일하는 어디서든 제공할 수 있다는 것이다.

**Netlify**(Sean Roberts, VP of Applied AI)는 배포 관점을 분명히 말한다. 스테이트리스 코어는 MCP를 세션 관리를
우회할 필요 없는 일급 HTTP 워크로드로 만든다. 고객들은 Netlify 위의 MCP가 플랫폼의 나머지만큼 단순하기를 원했고,
새 스펙이 그것을 근본에서 가능하게 한다. MCP Apps를 새 확장 프레임워크 위에 올린 것은 생태계 전체의 확장성,
접근성, 역량 면에서 큰 진전이다.

**Paul D'Ambra**(Product Engineer)는 스테이트리스 프로토콜이 자사 서비스를 확장하기 쉽게 만들고, 고객의 MCP
서버에 대한 분석 기능을 추가하기도 쉽게 만든다고 지적한다. 사용자들이 MCP 도구를 어떻게 쓰고 있는지, 그리고
사용자들이 원할 법한데 빠져 있는 도구가 무엇인지 보여 줄 수 있게 된다.

**Andrew Goodman**(VP of AI)은 이를 복잡성의 제거로 본다. 스테이트리스 코어가 팀이 관리해야 할 복잡성을 줄여 주므로,
고객에게 더 많은 기능을 더 빠르게, 규모 있게 내보낼 수 있다.

**Zoom**(Ross Mayfield, Head of Product for AI Platform)은 AI가 의미 있는 일을 해내게 하는 것이 조직의 맥락이라는
전제에서 출발한다. 그래서 Zoom은 회의 인텔리전스를 Claude 같은 AI 플랫폼으로 안전하게 가져오는 MCP 서버를 만들었다.
새 스펙은 표준 HTTP 인프라 위에서 MCP 서버를 배포하고 확장하기를 훨씬 쉽게 만들어, 사용자가 매일 의존하는 워크플로
안에서 그 인텔리전스를 더 빠르고 안정적으로 받게 한다.

## Claude에서의 MCP 진전

Claude의 커넥터 디렉터리에는 이제 **950개가 넘는 MCP 서버**가 등록돼 있고, 매일 수백만 명이 사용한다. 새 프로토콜
확장 지원과 함께 올해 다음 기능들이 출시됐다.

- **MCP Apps**는 서버가 대화 안에 인터랙티브 UI를 직접 렌더링하게 한다. 사용자는 커넥터가 무엇을 하고 있는지 보고,
  탭을 옮기지 않고 그 자리에서 다룰 수 있다.
- **Enterprise-managed auth**는 관리자가 아이덴티티 제공자를 통해 조직 전체에 MCP 커넥터를 프로비저닝하게 한다.
  관리자가 커넥터를 한 번 승인하면 사용자는 기존 IdP 그룹을 통해 접근 권한을 상속받고, 첫 로그인 시 연결된다.
  최종 사용자 입장에서는 설정이 필요 없다.
- **커넥터 개발자를 위한 관측 가능성**은 디렉터리에 게시된 커넥터에 Claude 제품 표면 전반의 성능을 보여 주는
  대시보드를 제공한다. 채택 추이를 추적하고, 오류와 지연을 진단하고, 제품별 사용량을 분해해 볼 수 있다.
- **MCP tunnels(리서치 프리뷰)**는 사설 네트워크 내부의 MCP 서버를 공개 인터넷에 노출하지 않고 Claude에 연결한다.
  인바운드 방화벽 규칙도, 공개 엔드포인트도, 오리진의 IP 허용 목록도 필요 없이 내부 도구를 Claude로 가져올 수 있다.

스테이트리스 코어, 표준화된 확장, 강화된 인가는 개발자가 더 많은 애플리케이션을 더 적은 마찰과 더 일관된 최종 사용자
경험으로 Claude에 가져오도록 돕는다. Anthropic은 MCP를 커뮤니티와 함께하는 오픈 표준으로 계속 투자하고, 프로덕션에서
MCP를 더 접근 가능하고 효과적으로 만드는 Claude 기능에도 계속 투자하겠다고 밝혔다.

## 의존 관계를 따르는 도입 순서

1. **먼저 스테이트리스 코어로 옮긴다.** 배포와 확장에 관한 선택이 여기에 달려 있다.
2. **인가를 조직의 IdP로 다시 겨눈다.** 강화된 OAuth 2.0 / OIDC 정렬을 활용하고, 조직 전체 배포에는
   enterprise-managed auth와 짝지운다.
3. **확장은 제값을 하는 곳에만 더한다.** 인라인 상호작용에는 Apps를, 요청보다 오래 사는 작업에는 Tasks를.
4. **커넥터 디렉터리에 게시한 뒤**, 개발자 관측 대시보드로 채택, 오류, 지연, 제품별 사용량을 지켜본다.
5. **내부 전용 도구라면** 엔드포인트를 공개하는 대신 MCP tunnels를 검토한다.

## 시작하기

스펙과 SDK를 살펴보는 것으로 시작하면 된다. 지원은 곧 Claude 제품 전반에 적용된다. MCP 서버를 Claude의 커넥터
디렉터리에 제출할 계획이라면 디렉터리의 제출 안내를 먼저 읽자. 새 스펙의 전체 내용은 MCP 2026-07-28 릴리스 공지를
참고하면 된다.
