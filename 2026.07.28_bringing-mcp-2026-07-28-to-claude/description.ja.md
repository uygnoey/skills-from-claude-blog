## この記事について
Model Context Protocolの5回目の仕様リリース、MCP 2026-07-28の発表です。2026年7月28日に公開されました。三つの変更がこのリリースを特徴づけます。MCPが双方向のステートフルなプロトコルから**ステートレスなリクエスト/レスポンス型のコア**へ移り、MCP AppsとTasksが**バージョン管理された拡張フレームワーク**として正式化され、**認可が本番運用のOAuth 2.0およびOIDCと整合**することで、サーバーがEntraやOktaのようなエンタープライズのアイデンティティ基盤に回避策なしで接続できるようになります。サポートはClaude製品全体へ順次展開中です。

記事はClaude側の動きにも触れます。コネクタディレクトリに掲載された950を超えるMCPサーバー、会話の中にインタラクティブUIを描くMCP Apps、IdP経由で組織全体にコネクタを配布するエンタープライズ管理の認証、コネクタ開発者向けの可観測性ダッシュボード、そしてプライベートネットワーク内のサーバーへ届くMCPトンネル（リサーチプレビュー）です。

## どんなときに役立つか
- MCPサーバーを設計・改修する際に、ステートレスなコアが状態とデプロイに何をもたらすかを判断するとき。
- サーバーをサーバーレスやエッジのインフラへ移せるかを決めるとき。
- サーバーをエンタープライズのアイデンティティプロバイダーへ接続するとき、あるいは旧仕様の隙間を埋めるために書いた独自の認証コードを削除するとき。
- サーバーにインタラクティブUIや長時間実行の処理を足す際に、コアプロトコルの回避策ではなく正式な道筋を探すとき。
- コネクタを一人ずつではなくIdP経由で組織全体へ展開するとき。
- コネクタをClaudeのコネクタディレクトリへ提出するとき、あるいは公開後にパフォーマンスダッシュボードを使うとき。
- 社内ツールがファイアウォールの内側にあり、公開エンドポイントを晒すのが適切でないとき。

## 主なポイント
- **ステートレスなコア。** リクエスト/レスポンスが双方向のステートフルなプロトコルを置き換えます。サーバーレスやエッジへデプロイでき、Claude向けに作ることも採用の拡大に合わせて拡張することも単純になります。
- **エコシステムが語るデプロイの捉え方:** ステートレスなコアは、回避すべきセッション管理のないファーストクラスのHTTPワークロードにMCPを変えます。
- **バージョン管理された拡張。** MCP AppsとTasksが正式な拡張フレームワークのもとで提供され、インタラクティブUIや長時間実行の処理はコアプロトコルの変更ではなく追加的な能力になります。
- **認可の強化。** 認可が、OAuth 2.0とOIDCが本番で実際にどう配備されているかと噛み合うようになりました。EntraやOktaが回避策なしで動く理由です。
- **標準としての規模。** MCPは最近、月間4億回のSDKダウンロードを突破し、今年に入って4倍に増えました。Claudeのコネクタディレクトリには950を超えるMCPサーバーが掲載されています。
- **MCP Apps** はサーバーがインラインでインタラクティブUIを描画できるようにし、利用者はタブを切り替えずにコネクタの動きを見られます。
- **エンタープライズ管理の認証** はエンドユーザーの設定作業がゼロです。管理者が一度コネクタを認可すれば、利用者は既存のIdPグループでアクセスを継承し、初回ログイン時に接続されます。
- **コネクタの可観測性** は採用状況、エラーとレイテンシ、プロダクト別の利用を示します。壊れているツールだけでなく、欠けているツールを見つけるのにも役立ちます。
- **MCPトンネル（リサーチプレビュー）** は、インバウンドのファイアウォールルールも公開エンドポイントもオリジンのIP許可リストもなしに、プライベートネットワーク内のサーバーへ届きます。
