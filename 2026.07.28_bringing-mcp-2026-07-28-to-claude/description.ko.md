## 이 글이 뭔가요
Model Context Protocol의 다섯 번째 스펙 릴리스인 MCP 2026-07-28 공지입니다. 2026년 7월 28일 공개됐습니다. 세 가지 변화가 이번 릴리스를 정의합니다. MCP가 양방향 상태 유지 프로토콜에서 **스테이트리스 요청/응답 코어**로 옮겨 가고, MCP Apps와 Tasks가 **버전 관리되는 확장 프레임워크**로 정식화되며, **인가가 프로덕션 OAuth 2.0 및 OIDC와 정렬**되어 서버가 Entra나 Okta 같은 엔터프라이즈 아이덴티티 시스템에 우회 처리 없이 연결됩니다. 지원은 Claude 제품 전반에 순차 적용 중입니다.

글은 Claude 쪽 이야기도 다룹니다. 커넥터 디렉터리에 등록된 950개가 넘는 MCP 서버, 대화 안에 인터랙티브 UI를 그리는 MCP Apps, IdP로 조직 전체 커넥터를 프로비저닝하는 enterprise-managed auth, 커넥터 개발자를 위한 관측 대시보드, 그리고 사설 네트워크 안의 서버에 닿는 MCP tunnels(리서치 프리뷰)입니다.

## 언제 유용한가요
- MCP 서버를 새로 설계하거나 리팩터링하면서, 스테이트리스 코어가 상태와 배포에 무엇을 바꾸는지 판단할 때.
- 서버를 서버리스나 엣지 인프라로 옮길 수 있는지 결정할 때.
- 서버를 엔터프라이즈 아이덴티티 제공자에 연결하거나, 이전 스펙의 빈틈을 메우려 붙여 둔 커스텀 인증 코드를 걷어낼 때.
- 서버에 인터랙티브 UI나 장시간 실행 작업을 추가하면서, 코어 프로토콜 우회 대신 공식 경로를 찾을 때.
- 커넥터를 사용자 한 명씩이 아니라 IdP를 통해 조직 전체에 배포할 때.
- 커넥터를 Claude 커넥터 디렉터리에 제출하거나, 게시 후 성능 대시보드를 활용할 때.
- 내부 도구가 방화벽 뒤에 있고 공개 엔드포인트를 노출하는 것이 적절하지 않을 때.

## 핵심 포인트
- **스테이트리스 코어.** 요청/응답이 양방향 상태 유지 프로토콜을 대체합니다. 서버를 서버리스와 엣지에 배포할 수 있어, Claude용으로 만드는 일도 채택에 따라 확장하는 일도 단순해집니다.
- **생태계가 말하는 배포 관점:** 스테이트리스 코어는 MCP를 세션 관리를 우회할 필요 없는 일급 HTTP 워크로드로 만듭니다.
- **버전 관리되는 확장.** MCP Apps와 Tasks가 공식 확장 프레임워크 아래로 들어와, 인터랙티브 UI와 장시간 실행 작업이 코어 프로토콜 변경이 아니라 덧붙이는 기능이 됩니다.
- **인가 강화.** 인가가 OAuth 2.0과 OIDC가 실제 프로덕션에서 배포되는 방식과 맞아떨어집니다. Entra와 Okta가 우회 없이 동작하는 이유입니다.
- **표준의 규모.** MCP는 최근 월 4억 회 SDK 다운로드를 넘었고 올해 4배 증가했습니다. Claude 커넥터 디렉터리에는 950개가 넘는 MCP 서버가 있습니다.
- **MCP Apps**는 서버가 인라인으로 인터랙티브 UI를 렌더링하게 해, 사용자가 탭을 옮기지 않고 커넥터의 동작을 볼 수 있게 합니다.
- **Enterprise-managed auth**는 최종 사용자에게 설정이 필요 없습니다. 관리자가 커넥터를 한 번 승인하면 사용자는 기존 IdP 그룹으로 접근 권한을 상속받고 첫 로그인 시 연결됩니다.
- **커넥터 관측 가능성**은 채택, 오류와 지연, 제품별 사용량을 보여 줍니다. 고장난 도구뿐 아니라 빠진 도구를 찾는 데도 유용합니다.
- **MCP tunnels(리서치 프리뷰)**는 인바운드 방화벽 규칙도, 공개 엔드포인트도, 오리진 IP 허용 목록도 없이 사설 네트워크 안의 서버에 닿습니다.
