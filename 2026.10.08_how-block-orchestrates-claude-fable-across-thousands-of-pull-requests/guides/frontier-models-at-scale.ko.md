# 프런티어 모델을 대규모로 효율적이고 안전하게 운영하기

엔지니어링 조직 전체에 프런티어 모델을 주면서도 비용과 위험을 놓치지 않는 방법에 대한 Block AI
Capabilities 팀의 교훈입니다.

## 1. 접근과 효율
- 기술직이라면 누구에게나 가장 뛰어난 모델에 대한 전면 접근을 주어, 팀이 가능성의 최전선에서 일하게 합니다.
- 효율을 기본값으로 만듭니다: 작업에 맞는 모델을 제안하는 도구(Block의 자동 선택기)를 만들고, 큰 모델과
  작은 모델을 섞는 멀티 에이전트 시스템을 씁니다.
- 프런티어 모델은 큰 문제(마이그레이션 설계, 대규모 오케스트레이션)에 아껴 두고, 코드 변경의 세부는 더
  작은 모델이 채우게 합니다.

## 2. 슬라이더가 아니라 격자로 벤치마크
- xhigh effort의 모델은 같은 모델의 medium과 사실상 다른 모델처럼 동작할 수 있습니다.
- 모든 사용 사례에 대해 모든 모델을 모든 effort 수준으로 벤치마크합니다.
- "이런 작업에는 이 모델을 high로 기본 사용" 같은 명확한 권고를 공개하고, 도구에서 자동화하며, 전문가는
  그 너머를 탐색하게 둡니다.

## 3. 다수 에이전트를 위한 도구
- 단일 대화 중심 인터페이스로는 수십 개의 에이전트가 동시에 일하는 상황을 따라가지 못합니다. Block은 여러
  사람과 많은 에이전트가 채널·스레드를 공유하는 오픈소스 워크스페이스 Buzz를 씁니다.

## 4. 겹겹의 세이프가드
| 계층 | Block의 방식 |
|---|---|
| 사람의 보증 | main 머지, 프로덕션 배포, 피처 플래그 변경은 사람 몫. 에이전트 변경은 보안 검사를 거친 뒤 사람 두 명이 배포를 승인 |
| 기본값부터 안전 | 원격 워크스테이션, 거부 목록 대신 네트워크 허용 목록 |
| 모델 루프 밖 | 작업 인터페이스에 넣은 값싼 검사 — 정규식, 점점 늘어나는 작은 분류기 |
| 의도적 허용 | PR 생성, 코드 리뷰, 로그·분석 DB 조회 |
| 모델 세이프가드 | 모델의 거부 성향과 Anthropic 안전 분류기. Claude가 이중 승인을 "우회"하라는 요청을 거부하는지 Block이 벤치마크 |

## 5. 유지보수 속도 맞추기
PR이 늘면 기술 부채도 빨리 쌓입니다. 코드베이스를 매일 또는 매주 훑어 정리·통합할 곳을 찾는 에이전트를
돌립니다.

## 6. 지식을 조직의 것으로
사람들은 로컬 스킬과 맥락을 쌓습니다(예: 프런트엔드 개발자가 아닌 사람도 웹 프런트엔드에서 일하게 해 주는
스킬). 사람들이 배운 것을 문서화해 공유 시스템에 넣어, 모든 에이전트 실행이 최선의 맥락을 갖게 합니다.
