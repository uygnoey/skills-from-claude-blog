## この記事について
Block(Square、Cash App)の AI Capabilities 責任者 Bradley Axen へのインタビューです。Block のモデル評価
方法、Claude Fable 5 が数千の PR にまたがる全社コード移行をオーケストレーションするやり方、社員を効率的な
モデル利用へ導く方法、技術職全員がフロンティアモデルを使える環境で頼りにしているセーフガードを扱います。

## どんなときに役立つか
- 多数のリポジトリにまたがり数百〜数千の PR を要する移行を計画するとき。
- ある種類のエージェント作業にどのモデルと effort レベルを使うか決めるとき。
- 大規模組織でコードを書くエージェントのガードレールを設計するとき。

## 主なポイント
- 階層型オーケストレーション:人間が舵を取り、Fable が上流の設計(データモデル、API 仕様、アルゴリズム)
  を担い、ファイル編集とテスト実行を行うより小さなモデル(Opus、Sonnet)を最大数十個指揮します。初期結果
  では品質を落とさずにトークンの多くがワーカーモデルへ移り、1つの移行で Fable がオーケストレーションした
  PR を千件マージすることもあります。
- Block はこれを、人とエージェントがチャンネルとスレッドを共有するオープンソースのワークスペース Buzz で
  動かしています。
- エージェントが約100万行のコードベースを毎日または毎週巡回し、整理・統合すべき技術的負債を探します。
- 効率:技術職にはフロンティアモデルへのフルアクセスを与えつつ、モデル選択を助ける自動セレクターを構築中。
  すべてのユースケースを全モデル × 全 effort レベルでベンチマークします — スライダーではなくグリッドです。
- セーフガード:main へのマージ、本番デプロイ、フィーチャーフラグは人間が担当。エージェントの変更は
  セキュリティチェックを通過し、デプロイには2人の承認が必要です。リモートワークステーション、ネットワーク
  の許可リスト、モデルループ外の安価なチェック(正規表現、小さな分類器)。PR 作成、コードレビュー、ログや
  分析 DB の照会はあえて許可しています。Claude は二重承認の回避依頼を拒否し、Block はそれもベンチマーク
  しています。
- 組織の成熟とは、学んだ文脈を個人ではなくシステムのレベルで記憶することです。
