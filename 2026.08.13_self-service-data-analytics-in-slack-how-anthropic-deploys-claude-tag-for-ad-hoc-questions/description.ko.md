## 이 글이 뭔가요
Anthropic이 Slack 안에서 Claude Tag를 어떻게 운영해 직원들이 즉석 데이터 질문을 던지고 거버넌스가 적용된 데이터 정의에 근거한 답을 받는지 정리한 현장 보고서다. 시맨틱 레이어, 스킬 파일, 평가 스위트를 통해 약 95% 정확도에 도달한 앞선 작업을 이어받아, **정확한 답을 얻는 것과 넓게 배포하는 것은 서로 다른 문제**라고 주장한다. 글은 다섯 가지 배포 교훈을 중심으로 구성된다. 스킬 파일을 지속적으로 갱신할 것, 테이블 접근을 넘어선 분석 스킬을 부여할 것, 웨어하우스뿐 아니라 비즈니스 맥락에 연결할 것, 서비스 계정 권한을 신중히 설계할 것, 그리고 모든 답변을 계측할 것.

관통하는 논지는 최신성·권한·관측 가능성이라는 배포 측 속성이야말로, 정확한 에이전트가 전사에 공개된 뒤에도 계속 정확하고 계속 쓰이는지를 결정한다는 것이다.

## 언제 유용한가요
- 분석 에이전트가 이미 평가에서 좋은 점수를 내고 있고, 이를 비분석가 앞에 어떻게 내놓을지 결정할 때.
- 출시 시점에는 맞던 답이 흔들리기 시작해, 스킬 드리프트인지 커버되지 않은 데이터 니즈인지 판단해야 할 때.
- 서비스 계정의 웨어하우스 접근 범위를 정하면서, 채널 멤버십이 실제로 무엇을 부여하는지에 대한 방어 가능한 모델이 필요할 때.
- 첫날부터 채택률과 정확도를 모두 측정하려면 무엇을 로깅해야 하는지 알고 싶을 때.

## 핵심 포인트
- **스킬 파일은 배포물이 아니라 서빙 콘텐츠다.** 런타임은 마운트된 리포지토리에서 대화마다 스킬 파일을 다시 읽으므로 에이전트는 항상 현재 정의를 쓴다. 데이터 모델은 끊임없이 바뀐다. 컬럼명 변경, 지표 수정, 테이블 폐기가 계속 일어난다.
- **분석 스킬은 데이터 접근만큼 중요하다.** 예측(추세 적합, 계절성 가정), 코호트·리텐션 분석(표준 정의, 리텐션 곡선), 퍼널 분석(표준 단계 정의), 차트(시각화 관례), 분석 글쓰기(구조, 유보 표현, 신뢰 수준). 이는 기존 분석가 관행의 문서화이며, 문서화가 일관성을 만든다.
- **비즈니스 맥락이 숫자를 설명으로 바꾼다.** 문서·논의·이벤트 같은 사내 지식 인덱스에 연결하면, 지표가 움직인 시점에 무슨 일이 있었는지 검색할 수 있다. 장애 보고서, 기능 플래그 변경, 경쟁사 발표 등이다. "가입이 12% 감소했다"와 그 이유를 설명하는 답의 차이가 여기서 갈린다.
- **서비스 계정 권한을 신중히 설계하라.** 거버넌스 데이터로만 범위를 한정하고, PII를 컬럼 단위로 분류해 에이전트 접근을 차단하며, 연결 경로를 스킬 파일에 문서화하고, 채널 멤버십을 접근 권한 부여로 취급하며, 감사 추적과 비용 귀속을 위해 모든 쿼리에 레이블을 붙인다.
- **기억할 프레이밍:** Claude의 채널 접근을 *거버넌스가 적용된 웨어하우스의 공유 읽기 복제본*으로 다룰 것.
- **모든 답변을 계측하라.** 어떤 스킬 파일이 어떤 버전으로 로드됐는지, 사용자 반응(👍/👎)과 정정 내용, 접근한 테이블의 데이터 품질 경고를 남긴다.
- **채택률이 가장 실행 가능한 지표다.** 하락은 스킬 드리프트 또는 커버되지 않은 데이터 니즈를 뜻한다.
- **스레드가 협업 공간이 된다.** 여러 팀원이 맥락을 보태는 동안 Claude가 분석을 맡아, 문제와 해결 과정을 되짚어볼 수 있는 기록이 남는다.
- **구성된 루프가 반복 업무를 처리한다.** 스탠드업 전 주간 사전 리포트, 테스트·실험 모니터링, 파이프라인·대시보드 관측, 들어오는 데이터 질문의 분류.
- **선제적 응답.** 적절히 구성하면 명시적 멘션 없이도 채널 질문의 75% 이상에 답할 수 있다.
- **구현 순서.** 권한이 먼저, 그다음 배포 구성과 최신성 검증, 첫날부터 텔레메트리, 데이터 경로가 안정되면 지식 인덱스, 그리고 실제 사용자 질문을 반영한 분석 스킬을 마지막에.
