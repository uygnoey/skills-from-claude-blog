# 서브에이전트에서 단일 에이전트 루프로

서브에이전트를 메인 에이전트 루프로 접어 넣는 방법에 대한 Anthropic 지침을 방법론 중심으로 정리했습니다.

## 1. 왜 중요한가
큰 조직은 팀마다 에이전트를 만들고 그 위에 중앙 오케스트레이터를 얹는 경우가 많습니다. 그러면
에이전트 사이의 컨텍스트 손실, 서브에이전트 난립, 상충하는 규칙이 뒤섞인 "프랑켄프롬프트", 아무도
책임지지 않는 국소적 평가, 추가 지연이 생깁니다. 스킬과 도구를 점진적으로 공개하는 단일 루프는
공유 컨텍스트를 유지하고, 비대화를 막고, 더 유능해진 모델을 활용합니다.

## 2. 서브에이전트가 여전히 맞는 경우
- 단일 루프에서 컨텍스트 비대화로 인한 성능 저하가 측정될 때.
- 새롭고 버려도 되는 컨텍스트 윈도로 병렬 처리해야 하는 작업.
- 하나의 시스템 프롬프트에서 도구 선택이 어렵거나 지시가 상충할 때.
멀티 에이전트로 간다면 가장 단순한 패턴부터 시작하고, 문제 유형이 아니라 컨텍스트 기준으로 나눕니다.

## 3. 목표 아키텍처
모델과 컨텍스트 윈도 하나, 턴·비용 예산과 쓰기 게이트가 있는 열린 도구 루프, 원시 결과를 같은 모델에
돌려주는 병렬 도구 호출 묶음, 컨텍스트 안에서 쓰고 결과에 따라 고치는 계획. 절차는 스킬에, 강제
제한과 대화 중 조회는 도구에 두고, 코드는 값싸고 거의 항상 필요한 로딩과 도구 안의 기계적 작업에만 씁니다.

## 4. 마이그레이션 단계
1. **작업 완료 평가** - 중앙 팀의 공유 엔드투엔드 세트와 스킬별 세트. 골든 예시 10개로 시작.
   루브릭 채점, 라우팅 정확도, 이후 스킬·도구 선택 정확도.
2. **도메인 에이전트 합치기** - 서로의 출력을 잇거나, 데이터를 공유하거나, 함께 호출되는 것부터.
   가장 많이 쓰이는 것 먼저.
3. **유지할 서브에이전트는 도구로 호출** - 공유 응답 스키마, 메인 에이전트가 검증하고 대화를 유지.
   서브에이전트가 사용자와 직접 대화해야 할 때만 완전 핸드오프.
4. **한 번에 하나씩 접기** - 프롬프트는 스킬로, API 호출은 MCP 도구로. 뒤집힌 과제를 비교하고 각
   과제를 두 번 이상 실행. 접은 버전의 점수가 더 나쁠 때만 서브에이전트로 남깁니다.

## 5. 소유 모델
| 자산 | 소유자 | 기준 |
|---|---|---|
| 시스템 프롬프트, 엔드투엔드 평가 | 작은 중앙 팀 | 새 스킬·도구·평가를 모두 검토 |
| 스킬 | 팀 DRI | 명확히 구분되고 잘 만든 것, 평가와 함께 배포 |
| MCP 도구 | 도메인 팀 | 사용자 의도 단위로 묶기, 약 30~50개 이하, 지연 로딩 도구 검색 |
| 지식 베이스 | 도메인 팀 | 조회 도구 뒤나 스킬 참조 파일로 |

## 6. 도구
`/claude-api build-eval`, `/claude-api prompt-audit`, `/claude-api hillclimb`,
`/claude-api cost-optimize`, `/skill-creator`, `/skill-doctor`, 그리고 모의 시스템 데모가 포함된
마이그레이션 키트.

## 7. 원칙
측정하고, 한 번에 하나만 바꾸고, 버티는 것만 남깁니다.
