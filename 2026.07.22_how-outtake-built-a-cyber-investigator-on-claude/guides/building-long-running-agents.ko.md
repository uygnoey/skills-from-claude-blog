# 장시간 실행 에이전트 만들기

Outtake가 자율 사이버 조사관 Recon Agent를 어떻게 만들었는지, 그리고 세션이 몇 시간씩 이어지기 시작했을 때 무엇이 버텼는지.

## 1. 문제

Outtake는 2023년 Alex Dhillon이 창업했다. 그는 이전에 Palantir의 문샷 팀에 있었다. 이 회사는 디지털 트러스트 공격 체인 전체를 하나의 방어로 통합하며, 2025년 한 해에만 2천만 건 이상의 잠재적 사이버 공격을 스캔했다.

Dhillon은 상황을 공격자 시점에서 제시한다.

> "악의적 행위자의 모자를 써보면, 지금은 사실 공격을 벌이기에 아주 좋은 시절입니다. 평균적인 공격은 AI 덕분에 더 빨리 실행될 뿐 아니라, AI 덕분에 더 깊은 접근권까지 확보합니다."

공격은 세 단계로 진행된다. 공개 데이터를 수집하고, 미끼로 쓸 사칭물을 만들고, 내부 시스템을 침해한다. 기존 도구는 각 단계를 따로 다루는데, 바로 그것이 공백이다. 세 단계가 하나의 적대적 네트워크에 속하기 때문이다.

## 2. Recon Agent가 하는 일

**복제된 로그인 페이지 하나**에서 출발해 증거를 수집·분류하고, 연결된 인프라 — 예컨대 "고객 지원"을 자처하는 가짜 Telegram 계정 — 로 단서를 따라가며, 적대적 네트워크를 그래프로 지도화하고, 행위자 프로필과 공격 타임라인이 담긴 조사 보고서를 만든다.

코드를 읽고 쓰고 실행하며, 탈취된 자격증명이 어디로 가는지 추적하기 위해 악성 로그인 페이지와 직접 상호작용한다.

| 지표 | 값 |
| --- | --- |
| 세션 실행 시간 중앙값 | 16분 |
| 통상 범위 | 한 시간 이상까지 |
| 관측된 최장 | 2시간 |

## 3. 개발의 네 단계

### 1단계 — 먼저 전문가가 되라

팀은 실제 사이버 조사를 직접 수행했고, 고객과 디자인 파트너에게서 도메인 전문성을 끌어내 "좋은 것"이 무엇인지 정의했다.

> "장시간 실행 에이전트를 만들 때 가장 중요한 것은 *좋은 것이란 어떤 모습인가? 에이전트는 무엇을 해야 하는가?* 를 정말로 이해하는 일입니다." — Jack Hayford, 엔지니어링 리드

### 2단계 — Claude Code에서 프로토타입을 만들라

기존 에이전트 프레임워크로는 부족했다.

> "모든 조사는 서로 다르고 깊이 기술적입니다. 에이전트에게는 코딩 근육과 역량이 필요했고, Claude Code는 강력한 초기 하네스였습니다."

여기서 정해진 핵심 설계 원칙은 이것이다. **오케스트레이션은 촘촘히 제약하되** — 항상 X, Y, Z를 수행 — **판단이 필요한 상황에서는 즉흥을 허용하라.**

### 3단계 — 프로덕션급 하네스로 졸업하라

> "Claude Code가 도입한 패턴이 정말 마음에 들었지만, 더 낮은 수준의 프리미티브에 대한 추가 접근이 필요했습니다."

팀은 프로덕션을 위해 **Claude Agent SDK**로 이전했고, 에이전트 루프를 다시 만들지 않으면서 메모리·컨텍스트·파일시스템에 대한 더 촘촘한 제어를 얻었다.

### 4단계 — eval이 이끄는 촘촘한 반복 루프를 만들라

자동화된 평가 스위트 덕분에 팀은 대대적인 변경을 안전하게 할 수 있었다. 별도의 코딩 에이전트가 조사에서 나온 제안을 읽고, 새 도구를 작성하고, 테스트 시나리오를 만든다. 사람은 최종 결과만 평가한다.

> "이런 길고 복잡한 에이전트를 만들 때는 피드백 루프가 자동화되는 것이 매우 중요합니다."

## 4. 장시간 실행 에이전트에 대한 네 가지 배움

### 도구: 파일시스템과 bash면 충분하다

파일시스템은 컨텍스트 압축을 견디는 기억을 준다. 파일시스템에 bash를 더하면 에이전트가 장애물에 창의적으로 대응할 수 있다.

> "그처럼 강력하고 열린 도구와 역량을 에이전트에게 건네주는 것은 커다란 단계적 변화입니다. 네트워크 문제 같은 것으로 도구가 실패했는데 에이전트가 그냥 적절한 우회로를 찾아 계속 진행한 사례를 많이 봤습니다."

### 프롬프트는 제안이다

시스템 프롬프트는 유연성을 주지만, 장시간 실행 에이전트에서는 지속력이 없다.

> "시간이 지나며 복잡해지는 이런 장시간 실행 에이전트를 만들다 보면, 프롬프트는 제안입니다. 그 프롬프트의 모든 단어가 결국 무시될 겁니다."

대응은 아키텍처적이다. 행동 요구사항을 프롬프트에서 빼내 **오케스트레이션 계층의 하드코딩된 가드레일**로 옮긴다. 이는 높은 판단이 필요한 작업을 위한 컨텍스트 공간도 아껴준다.

### eval은 신뢰성만이 아니라 속도를 위한 것이다

30분짜리 트랜스크립트를 손으로 검토하는 것은 확장되지 않는다. eval은 성찰을 구조화된 채점 항목으로 자동화하고 개발 사이클을 극적으로 앞당긴다.

> "아무리 공식적이지 않고 '완벽'하지 않더라도, 아주 처음부터 어떤 형태로든 eval을 만들어두면 그 에이전트를 더 빨리 만들게 됩니다."

### 에이전트를 보호하기

프롬프트 인젝션은 실재하는 위협이다. Outtake는 프롬프트 인젝션 공격에 강하다는 점도 고려해 Claude를 선택했지만, 방어 자체는 아키텍처적이다.

> "Recon Agent를 만들면서 보안은 우리에게 큰 주제였습니다. 파일시스템과 bash를 주고 적대적 환경으로 보내고 있으니까요."

전략은 이렇다. 에이전트가 탈취될 수 있다고 가정하고, 주변 시스템을 피해가 봉쇄되도록 설계한다. Outtake는 에이전트가 인터넷에 손을 뻗는 바로 그 지점에서 신뢰 수준을 채점하며, 에이전트가 건드리려는 대상을 평가하는 체크포인트를 둔다. "이 페이지는 사칭인가? 멀웨어인가? 지금 에이전트에게 프롬프트 인젝션을 시도하고 있는가?"

## 5. 베스트 프랙티스 요약

**"좋은 것"이 어떤 모습인지 알고 있는가?**
먼저 그 일을 직접 해보라. 고객과 디자인 파트너에게서 도메인 전문성을 끌어내라. 모든 반복에 적용할 고정된 기준을 세워라.

**각각의 복잡성은 값을 치르고 얻은 것인가?**
동작하는 가장 단순한 버전을 찾아라. 점진적으로 자동화하라. 결과가 정당화할 때만 복잡성을 더하라.

**하네스가 작업량에 맞는가?**
Claude Code에서 가정을 검증하라. 더 낮은 수준의 제어가 필요할 때 Agent SDK로 졸업하라. 에이전트 루프를 직접 다시 만들지 마라.

**에이전트를 어디서 제약해야 하는가?**
가드레일은 오케스트레이션 계층에 하드코딩하라. 낮은 수준의 판단에는 제약을 두지 마라. 즉흥의 여지가 최고의 결과를 낳는다.
