## この記事について
2023 年に Alex Dhillon（以前は Palantir のムーンショットチーム）が創業した Outtake は、**Recon Agent** という自律型のサイバー調査官を構築した。最初は Claude Code でプロトタイプを作り、本番では Claude Agent SDK へ移行している。攻撃ネットワーク全体にまたがるデジタル脅威を検知・調査・解体し、2025 年だけで 2,000 万件を超える潜在的なサイバー攻撃をスキャンした。

Dhillon は問題を攻撃者の側から提示する。「悪意ある者の帽子をかぶってみれば、いまは実のところ攻撃を仕掛けるには絶好の時期です。平均的な攻撃は AI のおかげで実行が速くなっただけでなく、AI のおかげでより深いアクセスまで手に入れます。」攻撃は三つの段階で進む——公開データの武器化、おとりとしてのなりすましの構築、内部システムの侵害。従来のツールは各段階を別々に扱う。Recon Agent はそうではなく、敵対的ネットワーク全体を地図化する。複製されたログインページ一つから証拠を収集・分類し、「カスタマーサポート」を名乗る偽の Telegram アカウントのような接続されたインフラへ手がかりをたどり、攻撃者プロファイルと攻撃タイムラインを含む調査報告を作成する。コードを読み、書き、実行し、盗まれた認証情報の行き先を追うために悪意あるログインページと直接やりとりする。セッション実行時間の中央値は 16 分。1 時間に及ぶことも珍しくなく、観測された最長は 2 時間だった。

記事の大半は、エンジニアリングリードの Jack Hayford による工学的な教訓である。四段階の開発プロセスと、長時間稼働エージェントについて高い代償を払って得た四つの学び——ツールについて、なぜプロンプトが効かなくなるのか、速度の道具としての eval、そして意図的に敵対的環境へ送り込むエージェントをどう守るか。

## どんなときに役立つか
- セッションが数十分から数時間に及ぶエージェントを構築するとき。コンテキスト圧縮とドリフトが理論ではなく現実である状況。
- Claude Code にとどまるか Claude Agent SDK へ進むかを判断し、移行して何が得られるかを見極めるとき。
- システムプロンプトの文言をどう変えても、エージェントがその指示を無視し続けるとき。
- エージェントにどのツールが必要か、専用ツールがファイルシステムと bash に勝るかを決めるとき。
- 30 分のトランスクリプトを手で読むことが規模に耐えず、エージェントへの変更が効いたのか判断できないとき。
- エージェントを、プロンプトインジェクションを狙って作られたページを含む、能動的に敵対的な環境で動かさねばならないとき。

## 主なポイント
- **作る前にまず専門家になる。** チームは自ら実際の調査を行い、顧客とデザインパートナーからドメイン知識を引き出した。Hayford はこう語る。「長時間稼働エージェントを作るうえで最も重要なのは、*良いとはどういう状態か？ エージェントは何をすべきなのか？* を本当に理解することです。」
- **Claude Code でプロトタイプし、意図的に卒業する。** 従来のエージェントフレームワークにはコーディング能力が足りなかった。「どの調査も異なり、深く技術的です。エージェントにはコーディングの筋力と能力が必要で、Claude Code は強力な初期ハーネスでした。」本番にはより低レベルのプリミティブが必要だった。「Claude Code が導入したパターンはとても気に入っていましたが、より低レベルのプリミティブへの追加のアクセスが必要でした。」そこでチームは、エージェントループを作り直すことなくメモリ・コンテキスト・ファイルシステムをより厳密に制御するために Agent SDK へ移行した。
- **判断ではなくオーケストレーションを制約する。** 常に起きること（X、次に Y、次に Z）は厳密に定め、判断を要する箇所には即興の余地を残す。
- **ファイルシステムと bash は驚くほど遠くまで届く。** ファイルシステムはコンテキスト圧縮を生き延びる記憶を与え、bash はエージェントが障害を迂回することを可能にする。「ネットワークの不調か何かでツールが失敗したのに、エージェントが適切な回避策を見つけてそのまま進んだ例をいくつも見てきました。」
- **プロンプトは提案である。** 「時とともに複雑になっていくこの種の長時間稼働エージェントを作っていると、プロンプトは提案になります。そのプロンプトの一語一語が、いずれおそらく無視されるでしょう。」振る舞いの要件はプロンプトから出て、オーケストレーション層のハードコードされたガードレールへ移る。これは高度な判断を要する仕事のためにコンテキストを温存することにもなる。
- **eval は信頼性のためだけでなく速度のためにある。** 30 分のトランスクリプトを手で読むのは規模に耐えない。eval は振り返りを構造化された採点項目へ変える。「どれだけ公式でなくとも『完璧』でなくとも、ごく最初から何らかの形の eval を作っておけば、そのエージェントをより速く作れるようになります。」
- **二つ目のエージェントがツールの空白を埋める。** Recon Agent が調査を終え、持っていなかったツールがあればもっとうまくやれたと報告すると、別のコーディングエージェントがその提案を読み、新しいツールを書き、それを試すテストシナリオを構築する。人間は最終結果だけを評価する。
- **エージェントは乗っ取られうると想定し、被害を封じ込める。** 「Recon Agent を作るうえでセキュリティは私たちにとって大きな論点です。ファイルシステムと bash を与えて、敵対的環境へ送り込んでいるのですから。」Outtake はエージェントがインターネットへ手を伸ばすまさにその地点で信頼度を採点し、チェックポイントがこう問う。「このページはなりすましか？ マルウェアか？ いままさにエージェントにプロンプトインジェクションを試みているか？」
