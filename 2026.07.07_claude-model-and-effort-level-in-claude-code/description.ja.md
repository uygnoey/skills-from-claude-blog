## この記事について
Claude Codeチームの Lydia Hallie が、「答えをよくする」ように見える二つの設定 — モデルとエフォートレベル — が実際には何を変えるのかを解説する。モデル設定は、あなたのリクエストをどの凍結された重みのセットが処理するかを入れ替え、出力トークン1個あたりのコストを決める。エフォートレベルはプロンプトと並んでリクエストの一部としてモデルに送られ、Claudeがタスクを完了と見なす前にどれだけ徹底し、どれだけ確信している必要があるかを設定する。どれだけ長く考えるか、何個のファイルを読むか、どれだけ検証するか、複数ステップのタスクをあなたに確認するまでどこまで押し進めるかがそこに含まれる。

記事はその仕組み — トークン化、重み、1トークンずつの生成ループ、コンテキストによる方向づけがなぜ「教える」ことにならないのか、ハルシネーションがなぜ検索の失敗ではなく重みがもっともらしい列を生成した結果なのか — をたどり、それを実務的なルールに変える。結果が的を外したら、まず自分が与えたコンテキストを確認する。コンテキストが明確だったうえで間違えたなら、*十分に頑張らなかったのか*(エフォートを上げる)、*十分に知らなかったのか*(より大きいモデルを選ぶ)を問う。

## どんなときに役立つか
- Claude Codeのセッションが誤った、あるいは浅い結果を返し、反射的につまみに手が伸びるとき。
- タスクごとに決めるのではなく、チームや領域のための常設のエフォート設定の好みを決めるとき。
- 長く続く定型作業の区間を、品質を落とさずに小さいモデルへ下げられるか判断するとき。
- プロンプトのコンテキストがなぜモデルの知っていることを変えないのかを同僚に説明するとき。
- コストを考えるとき。あるタスクの形において「トークンあたりより有能」と「全体のトークンがより少ない」のどちらが勝つのか。
- 出力が望むより長く、`max_tokens` が正しいレバーなのか迷っているとき(たいていは違う)。

## 主なポイント
- **モデル選択は固定された重みのセット**、つまりモデル全体の能力レンジを選ぶことだ。コンテキストは予測を方向づけるだけで、重みに何かを加えはしない。
- **エフォートは単なる思考時間ではない。** 読むファイル、使うツール、あなたに確認を返すまでのステップ数を含め、全体の作業量を制御する。
- **どの種類の出力も同じ種類のトークンだ。** 思考、ツール呼び出し、あなたへのテキストはすべて同じループから出て同じレートで課金される。しかも思考はそのターンの間コンテキストに残るので、Claudeがコードを書く段に進むと入力になる。
- **エフォートはリクエストとともに届く。** モデルは各エフォートレベルを理解するよう学習しており、その振る舞いは凍結された重みに焼き込まれている。同じプロンプトでも、高エフォートはより高い確信の答えに達するためにおよそ7倍のトークンを生成しうる。
- **計画は盲目的に実行されず、書き換えられる。** 三つの仮説のデバッグ計画のステップ1でバグが見つかれば、Claudeは通常そう述べて残りを飛ばす。高いエフォートが単純なタスクの使用量を人為的に膨らませることはない。「考えすぎ」は有効性を損なうため学習時に注意深く見られている。
- **つまみより先にコンテキストを確認する。** 必要ないはずのタスクでエフォートを上げているなら、直すべき場所はたいてい上流だ。プロンプト、`CLAUDE.md`、ツール、スキル、あるいはタスクの切り方である。
- **診断。** ファイルを飛ばした、テストを走らせなかった、リファクタリングを投げ出した → エフォートを上げる。コンテキストがあり、明らかに試みたうえで自信たっぷりに間違えた → より大きいモデル。
- **大きいほうが既定の答えではない。** 正確に記述できる定型作業は小さいモデルの領分だ。大きいモデルは曖昧さ、微妙なバグ、不慣れなドメイン、アーキテクチャの判断でこそ値段に見合う。
- **スペシャリスト/エキスパート/ジェネラリスト。** Fableはほとんど誰も見たことのない問題を見てきたスペシャリスト、Opusはエキスパート、Sonnetはとても優秀なジェネラリストであり、エフォートは彼らの誰であれどれだけの時間を費やすかを決める。モデルはおおよそ*どれだけ有能か*、エフォートはおおよそ*どれだけ徹底するか*だ。
- **コストはタスクの形で反転する。** 同じエフォートの定型作業では、小さいモデルが品質を落とさずコストを節約する。より難しい複数ステップの作業では、大きいモデルが少ないステップで基準に達するため、タスクあたりの総コストが低く出ることがあり、小さいモデルがどんなエフォートでも達成できないタスクを完了できる。
- **エフォートはトークン消費の形を決めるが、上限は課さない。** 唯一のハードキャップは `max_tokens` で、ストリーミングの途中で切り落とす。タスクの予算や簡潔さの依頼は、モデルが従うよう訓練されたガイダンスであって壁ではない。
