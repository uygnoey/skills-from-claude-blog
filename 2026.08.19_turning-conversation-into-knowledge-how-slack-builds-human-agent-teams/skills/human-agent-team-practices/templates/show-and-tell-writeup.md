# Template: "what I did and how" write-up

For the show-and-tell practice (practice area 5). The pattern described in the
source is simple: one person documents their setup, others copy the format, and
a personal workflow becomes a team template. Keep it short — this is a document
people skim and then copy, not a specification.

Post it in the company-wide, public-by-default show-and-tell channel.

---

## <One-line title: the task, not the tool>

**Who this is for:** <role or situation — e.g. "PMs who write weekly status updates">

**Time it used to take / takes now:** <before → after, honestly>

### The problem

<Two or three sentences. What was repetitive, slow, or kept getting dropped.>

### What I set up

<The concrete configuration. Which agent, what it has access to, where it runs,
what it produces. Include the actual instructions or prompt if there is one —
someone should be able to reproduce this without asking you.>

### How I use it

<The loop, in order. What the agent produces, when, and what you do with it.
Say explicitly where you review and where you would not let it run unattended.>

### What didn't work

<The dead ends. This is often the most valuable section, and the one people
leave out.>

### Copy this if…

<When this generalizes and when it doesn't. Which parts are specific to your
team.>

---

## Notes on using this template

- **Lead with the task, not the tool.** People search for their problem.
- **Include the failures.** A write-up with no dead ends is not reproducible.
- **Keep it public.** The value comes from a technique in one function reshaping
  a different one — that only happens if the write-up is in a channel outside
  your own team.
- **Expect it to be copied and changed.** A good write-up becomes someone else's
  starting point, and eventually a team template or a skill.
