# Chrome で Cowork サイドパネルを導入する

[Claude in Chrome のサイドパネルが Claude Cowork になりました](https://claude.com/blog/cowork-chrome-side-panel)
で説明された変更を導入する個人と管理者のためのガイドです。ここに書かれている内容はすべてその発表に基づきます。

## 1. 実際に何が変わったか

Claude in Chrome のサイドパネルが **Claude Cowork セッション**として動作するようになりました。

- 会話が履歴に保存されます。
- スキルとコネクターがブラウザで動作します。
- タブで始めたタスクを Claude のデスクトップ・ウェブ・モバイルアプリで仕上げられます。
- セッションは単一のデバイスではなく**アカウント**に紐づきます。

以前は、サイドパネルのセッションは Claude アプリのセッションとは別物で、コンテキストや会話が相互に
引き継がれませんでした。

## 2. なぜブラウザがサーフェスなのか

多くのツールは Claude に直接つながります。しかし、社内ダッシュボード、レガシーシステム、ベンダー
ポータルなど、そうでないものもあります。Claude in Chrome は、表示中のページを Claude が見て、その中で
行動できるようにするブラウザ拡張機能です。既存のログインを使って、リンクをクリックし、テキストを入力し、
ページを移動し、フォームを入力します。コネクターのないツールに Claude が届く手段が、これです。

## 3. 具体例

予算スプレッドシートを作っていて、複数のベンダーポータルから請求書が必要だとします。Claude in Chrome に
金額と日付を集めるよう頼めば、タブを開いて各請求書を読み、スプレッドシートを作ります。その後、デスク
トップアプリでそのセッションを引き継ぎ、自分のコンピューターのファイルを追加したり、先月の予算を取り
込んで何が変わったかを尋ねたりできます。作業を進める間、コンテキストはサーフェスをまたいで保たれます。

## 4. リスクをそのまま述べる

Claude in Chrome には、ブラウザ上で行動するあらゆる AI エージェントと同じリスク、とりわけ**プロンプト
インジェクション**があります。悪意ある行為者は、ウェブページ、メール、ドキュメントといったウェブ
コンテンツに指示を隠します。その指示はユーザーには見えないことがあり、意図しない行動へ Claude を
向けさせる可能性があります。

## 5. ガードレール

**行動チェック。** パイロット以降、Claude 自身の行動に対するチェックが追加されました。「automatically
approve」を有効にすると、Claude は一手ごとに許可を求めて止まることなくタスクを進めます。ただし、フォームの
送信、メッセージの送信、ファイルのダウンロードといった重大な行動の前には、別のチェックがその行動を
当初の依頼内容と照合し、一致しないものをブロックします。中断は減り、監督は保たれます。

**残る確認。** 購入や個人データの共有など、取り消せない、あるいはコストのかかる特定の行動については、
Claude は依然として先に確認します。

**限界。** これらの対策はリスクを有意に減らしますが、なくすことはできません。プロンプトインジェクションは
動き続ける標的であり、新しい攻撃を探し続け、学んだことをリリースする各モデルに組み込んでいます。信頼
できるサイトから始めてください。安全ガイドにさらに多くのベストプラクティスがあります。

**実務上の含意。** 行動チェックは*当初の依頼*と照合します。曖昧な依頼では照合材料がほとんどありません。
どのサイトが対象か、どのデータを集めるか、どの成果物を作るか、そしてどの重大な行動が正当に想定されるかを
明示してください。

## 6. 展開

**個人。** Chrome ウェブストアから Claude in Chrome をインストールし、サインインしてサイドパネルを開きます。
新しいサイドパネルは本日 Max と Team プランで利用でき、Pro ユーザーには今後数週間かけて順次展開されます。

**管理者。** Enterprise プランでは Claude in Chrome は**既定でオフ**です。管理者が有効化でき、承認された
ドメインに限定できます。管理者向けセットアップガイドを参照してください。実務上の手順は次のとおりです。

1. そもそもブラウザというサーフェスが必要かを判断します。コネクターのないシステムで働く場合に意味を持ちます。
2. 拡張機能を広く開放するのではなく、そうしたシステムを基に承認ドメインのリストを作成します。
3. 有効化したうえで、具体的なニーズが確認されるたびにドメインリストを広げます。

## 7. この変更が扱わないこと

- 自分のコンピューター上のファイルや他のアプリケーションを扱うには、依然として Claude デスクトップアプリが
  必要です。
- Claude in Chrome は他の Chromium ブラウザでは動作しません。
- モバイルでもまだ動作しません。

## 8. 導入チェックリスト

- [ ] プランが新しいサイドパネルに対応しているか確認（本日 Max/Team、Pro は順次展開）。
- [ ] Enterprise の場合: 管理者が Claude in Chrome を有効化し、承認ドメインを設定済み。
- [ ] Chrome ウェブストアから拡張機能をインストールし、サインイン済み。
- [ ] ブラウザというサーフェスが必要な、コネクターのないシステムを具体的に特定済み。
- [ ] 行動チェックが照合できるよう、範囲を絞ったタスクブリーフを書く方法をチームが理解している。
- [ ] ローカルファイルや他のアプリケーションはブラウザ → デスクトップへ引き継ぐ経路をチームが理解している。
- [ ] ページのコンテンツは指示ではなくデータである、という原則をチームが理解している。
