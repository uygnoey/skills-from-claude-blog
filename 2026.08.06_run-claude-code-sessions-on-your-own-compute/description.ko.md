## 이 글이 뭔가요
제품 공지 글입니다. Claude Code의 **셀프 호스팅 환경(self-hosted environments)** 이 퍼블릭 베타에 들어갔습니다. 에이전트 세션을 Anthropic이 운영하는 인프라가 아니라 조직이 직접 준비한 머신 — 자사 네트워크 안, 내부 서비스·툴체인·보안 통제 바로 옆 — 에서 실행할 수 있습니다. 웹, 모바일, 데스크톱, 루틴 중 어디서 시작한 세션이든 모두 같은 환경으로 라우팅됩니다.

글은 이것이 기본 권장안이 **아니라는** 점을 분명히 합니다. 대부분의 엔터프라이즈에는 운영 부담이 없는 호스팅 제공 방식을 여전히 권장하며, 셀프 호스팅은 네트워크·툴링·컴플라이언스 요구사항 때문에 에이전트 실행을 자사 인프라에 두는 것이 필수인 팀을 위한 선택지이고, 인력 투입 약속이 따라옵니다.

## 언제 유용한가요
- 에이전트 세션이 퍼블릭 인터넷에 노출되지 않은 내부 서비스·데이터베이스·패키지 레지스트리에 접근해야 할 때.
- 모든 세션이 사내 컴파일러, SDK, 내부 CLI가 이미 설치된 상태로 시작해야 할 때.
- 소스 코드와 빌드 산출물이 조직이 통제하는 인프라에 남아 있어야 할 때.
- 호스팅과 셀프 호스팅 사이에서 결정해야 하고, 플랫폼 팀을 투입하기 전에 트레이드오프 — 특히 **자사 인프라에 남지 않는 것이 무엇인지** — 를 분명히 확인해야 할 때.

## 핵심 포인트
- **퍼블릭 베타, Team·Enterprise 플랜 한정.** 기본은 비활성이며, ZDR을 사용하는 조직에서는 사용할 수 없습니다.
- **무엇이 남고 무엇이 남지 않는가.** 리포지토리 체크아웃, 빌드 산출물, 시크릿, 세션이 생성·수정한 파일은 직접 프로비저닝한 인프라에 남습니다. 반면 대화 자체 — 프롬프트, 응답, 그리고 Claude가 읽은 코드가 포함될 수 있는 툴 결과 — 는 추론을 위해 Anthropic으로 전송되며, 어느 표면에서든 세션을 이어받을 수 있도록 세션 트랜스크립트가 저장됩니다.
- **러너(runner)가 실행 단위입니다.** 장시간 살아 있는 러너 프로세스를 배포하면, 각 러너가 세션을 받아 세션마다 Claude Code 프로세스를 시작합니다.
- **러너 모드는 두 가지.** *Fixed*: 정해진 수의 러너를 계속 띄워 두고 세션을 분산합니다. *On-demand*: 오케스트레이터가 대기열을 감시하다가 세션이 들어오면 러너를 띄우고 작업이 끝나면 내려, 용량이 수요를 따라가게 합니다.
- **격리는 러너 단위가 아니라 세션 단위.** 러너 하나가 여러 세션을 처리할 수 있지만 세션마다 자체 체크아웃을 가지므로 개발자·계정 간 작업이 분리됩니다.
- **환경 하나, 모든 표면.** 한 번 구성하면 지원되는 모든 표면의 세션이 그 환경으로 들어옵니다.
- **Remote Control과는 다릅니다.** Remote Control은 개발자 본인 머신에서 돌아가는 세션을 휴대폰이나 브라우저로 이어서 쓰는 기능으로, 그 머신이 멈추면 세션도 끝나고 `claude`를 실행한 사용자에게 묶입니다. 셀프 호스팅 환경은 플랫폼 팀이 운영하는 공유 인프라에서 돌아가고 누구나 사용할 수 있습니다.
- **주인이 있어야 합니다.** 플랫폼, 개발자 경험(DevEx), 개발 생산성 팀 중 한 곳이 셋업과 지속 운영 — 러너 이미지 빌드·유지보수, 러너 업데이트, on-demand 모드를 쓴다면 오케스트레이터 운영 — 을 맡는다고 계획하세요.
