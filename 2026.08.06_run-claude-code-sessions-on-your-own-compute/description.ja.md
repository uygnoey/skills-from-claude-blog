## この記事について
プロダクト告知です。Claude Code の**セルフホスト環境（self-hosted environments）**がパブリックベータになりました。エージェントのセッションを Anthropic 側のインフラではなく、組織が自ら用意したマシン — 自社ネットワークの内側、社内サービス・ツールチェーン・セキュリティ統制のすぐ隣 — で実行できます。Web、モバイル、デスクトップ、ルーティンのいずれから開始したセッションも、同じ環境にルーティングされます。

記事はこれが既定の推奨では**ない**ことを明言しています。ほとんどの企業には運用がシンプルなホステッド提供を引き続き推奨しており、セルフホストはネットワーク・ツール・コンプライアンス要件によってエージェント実行を自社インフラに置くことが必須となるチーム向けの選択肢で、人員面のコミットメントが伴います。

## どんなときに役立つか
- エージェントのセッションが、公開インターネットに晒していない社内サービス・データベース・パッケージレジストリに到達する必要があるとき。
- すべてのセッションを、社内のコンパイラ・SDK・内製 CLI が導入済みの状態で開始したいとき。
- ソースコードとビルド成果物を、組織が管理するインフラ上に留めなければならないとき。
- ホステッドとセルフホストのどちらを選ぶか判断する必要があり、プラットフォームチームを投入する前にトレードオフ — とりわけ**自社インフラに残らないものは何か** — をはっきりさせたいとき。

## 主なポイント
- **パブリックベータ、Team・Enterprise プラン限定。** 既定では無効で、ZDR を利用する組織では使えません。
- **手元に残るもの／残らないもの。** リポジトリのチェックアウト、ビルド成果物、シークレット、セッションが作成・変更したファイルは、自分でプロビジョニングしたインフラ上に留まります。一方、会話そのもの — プロンプト、応答、そして Claude が読んだコードを含みうるツール結果 — は推論のため Anthropic に送信され、どの表面からでもセッションを引き継げるようトランスクリプトが保存されます。
- **ランナー（runner）が実行単位です。** 長時間稼働するランナープロセスをデプロイすると、各ランナーがセッションを受け取り、セッションごとに Claude Code のプロセスを起動します。
- **ランナーのモードは 2 種類。** *Fixed*: 一定数のランナーを常時稼働させ、セッションを分散します。*On-demand*: オーケストレーターがキューを監視し、セッションが来たらランナーを起動、作業完了時に停止して、キャパシティを需要に追従させます。
- **分離はランナー単位ではなくセッション単位。** 1 つのランナーが複数セッションを処理できますが、セッションごとに専用のチェックアウトを持つため、開発者間・アカウント間で作業が分離されます。
- **環境は 1 つ、表面はすべて。** 一度構成すれば、サポートされるすべての表面のセッションがその環境に入ります。
- **Remote Control とは別物です。** Remote Control は開発者自身のマシンで動いているセッションをスマートフォンやブラウザから継続する機能で、そのマシンが止まればセッションも終わり、`claude` を実行したユーザーに紐づきます。セルフホスト環境はプラットフォームチームが運用する共有インフラ上で動作し、どのユーザーでも利用できます。
- **担当チームが必要です。** プラットフォーム、開発者体験（DevEx）、開発生産性のいずれかのチームがセットアップと継続運用 — ランナーイメージの構築・保守、ランナーの更新、on-demand モードならオーケストレーターの運用 — を担うことを前提に計画してください。
