## この記事について
Datadog のエンジニアは、限定的な変更、大規模リファクタリング、主要システムの置き換え、まったく新しいシステムの構築という四つのカテゴリーで Claude Code を本番業務に使っている。それが規模を増すにつれ、制約点が移動した。Datadog のエンジニアリング担当 VP である Sesh Nalla は、エンジニアリングの仕事の感触の変化をこう語る。「もうコードを書いているのではなく、仕事のかたちを作っているのです。エージェントが何を見るべきか、どんなツールを持つべきか、成功とは何か、失敗をどう検知するかを決めている……全員がマネジメントの階段を三段飛ばしで昇進させられたようなもので、彼らはエンジニアなのでそんなことは望んでいませんでした。」

Datadog が築いた構造的な答えが **Temper** であり、記事はこれをエージェントのための「万能工作機械（universal machine tool）」と呼ぶ。エージェントは制御ロジックをアプリケーションコードとして出力するのではなく、**仕様（specification）** を出力する。そして LLM の外側にある決定論的カーネルが、実行前に各仕様を四つの独立した層で検証する。記号推論、網羅的状態探索、シード付き障害注入を伴う決定論的シミュレーション、そしてランダム化プロパティテストである。すべての capability は、振る舞い・データ・認可という三つの契約で表現される。

記事は Temper を可能にした三つの先行プロジェクト（Courier、BitsEvolve、Helix）をたどり、続いて Claude Code が数日でその大部分を作り上げた Kafka 相当のストリーミングシステム Helix のために Temper が「ダークファクトリー」を回す様子を示す。締めくくりは Datadog チームのベストプラクティスである。

## どんなときに役立つか
- エージェントがチームのレビュー速度を超えてコードを生成し、生成ではなくレビューが出荷の制約になったとき。
- エージェントが実際に何を出力すべきかを決めるとき——任意のコードか、決定論的カーネルが検証できる仕様か。
- 制御ロジックがルート、データベース制約、サービスコード、バックグラウンドジョブ、ドキュメントに散らばり、システムの状態機械が何であるか誰も言えないとき。
- 毎回 CI サイクルを丸ごと回さずに、エージェントが運用上の振る舞いを安全に変更する必要があるとき。
- 自律的なビルド・運用ループを構築し、人間が依然として調整すべき箇所を決めるとき。
- 生成された成果物が、人が頭の中に収められる大きさを超えていないか判断するとき。

## 主なポイント
- **ボトルネックは生成ではなく検証だと想定する。** エージェントはすでに、どのチームもレビューしきれない速さでコードを生み出す。生成されたものと証明されたものの隔たりに障害モードが積み上がるので、投資はスループットではなくそこへ向ける。
- **エージェントは制御ロジックについてコードではなく仕様を出力する。** 任意のコードについては、記事の枠組みは証明同伴（proof-carrying）である。コンパイルと証明は LLM の外に置く。仕様を決定論的カーネルに渡すことで、検証された成果物がそのまま実行される成果物になる。
- **四つの独立した検証層。** 記号推論が各ガードの充足可能性と各不変条件の帰納性を証明し、網羅的状態探索が到達可能なすべての状態を訪れ、決定論的シミュレーションがシード付き障害注入とともに本番コードを走らせ、ランダム化プロパティテストがおよそ 1,000 本の擬似乱数アクション列を実行する。
- **すべての capability は三つの契約を持つ。** 振る舞い（状態、遷移、事前条件、安全性プロパティ）、データ契約（エンティティ型、プロパティ、アクションを機械可読な形で）、認可（デフォルト拒否、スコープに基づく承認と保留中の決定、ホットロード）。
- **三つのプロジェクトが Temper を可能にした。** Courier（2024）は分散キューイングシステムで、「難しかったのは部品を作ることではなく、部品どうしの相互作用を観測可能・テスト可能・検証可能にすることだった」。BitsEvolve（2025 年 9 月）は閉ループの進化的最適化で、「ソフトウェアの一部が生き物のように培養されうるという最初の兆し」だった。Helix では Kafka 相当のシステムが数日で立ち上がり、ボトルネックが再び移動した——人間向けに作られた道具で人間がリリースを調整する地点へ。
- **Helix のダークファクトリーで Temper は三つの役割を果たす。** マネージドエージェントのためのエージェント制御プレーン（セッション、ロール、作業キュー、ライフサイクル）、エージェントが SDLC ツール（Git、CI、デプロイ）を橋渡しできるようにするツールビルダー層、そしてデータプレーンを取り巻くライフサイクル面としての Helix 制御 API。
- **なぜ単なる CRUD アプリではないのか。** Claude Code は CRUD アプリをうまく作るが、そこでは運用モード——たいていは状態機械——が暗黙のまま、ルート・制約・サービスコード・ジョブ・ドキュメントに散らばる。Temper はその状態機械を明示的でデータ駆動なものにする。「エージェントは任意のコードではなく、正確な記述を生み出します……エージェントはそれを安全に動的に変更でき、CI を通さずにホットリロードできます。」
- **すべての成果物を人が理解できる大きさに保つ。** 生成された成果物を人が頭に収められないなら、出発点に戻ってしまっている。
- **この先にあるもの。** 「こうして作られたソフトウェアは、フィードバックと選択と適応を通じて育て、培い、進化させられる有機体のように感じられ始めます。」
