# ライフサイエンスに AI 研究ワークベンチを導入する

Claude Science プロダクトガイドから抽出した、実践的な導入ガイドです。

## この記事が扱う課題

バイオファーマ／メドテックのリーダー 280 名を対象としたデロイトの 2026 Life Sciences Outlook では、78% が今年 AI が大きな変化を牽引する中心的役割を果たすと見込んでいる一方、日常のワークフローに AI ツールを完全に実装できていると答えたのはわずか 14%、さらに 40% は現在進行中でした。化学・物理・生物・計算分野の研究者へのインタビューに基づく Anthropic 自身の社内調査では、科学者の 91% が研究にもっと AI を使いたいと答え、79% が信頼性と再現性を導入の最大の障壁に挙げました。

このギャップは構造的なものです。生物学者の一日は文献、実験設計、データ整形、解析、図の作成、執筆にまたがりますが、ツールは PubMed、Jupyter、R、クラスタの端末、科学データのレンダラ、表計算に散らばっています。先行しているラボは計算資源が最も多いラボでもバイオインフォマティクスチームが最大のラボでもなく、**科学者の問いと説明可能な結果との距離を縮めた**ラボです。

## ステップ 1 — 展開の前にサーフェスを決める

Claude Science は科学者のために作られたサーフェスです。他のサーフェスは、発見の周辺にある文書業務・ソフトウェア業務・エンタープライズ業務を担います。多くの組織は複数を併用しており、信頼できる境界線は**成果物**です。

| 成果物 | サーフェス |
|---|---|
| 解析・図・結果 | **Claude Science** — macOS/Linux のローカルアプリ。SSH・SLURM・クラウド計算へディスパッチ |
| 素早い回答や下書き | **Claude Chat** — ブラウザ、デスクトップ、モバイル |
| フォルダとアプリをまたぐ文書 | **Claude Cowork** — ローカルファイルと接続システムを横断するデスクトップアプリ |
| Office 内での作成・レッドライン | **Claude for Microsoft 365** — アドインと M365 コネクタ |
| 他チームへ出荷されるソフトウェア | **Claude Code** — ターミナルと IDE |
| システム統合（ELN, LIMS, CTMS, 安全性, RWE） | **Claude Platform** — API（Bedrock、Vertex AI、Foundry 経由を含む） |
| ホストされた長時間実行エージェント | **Claude Managed Agents** — スコープ付き権限と完全な実行トレース |

最初のインストールの前に各機能部門のリードとこの議論を済ませておけば、メディカルライティング・レギュラトリー・科学計算の各チームが「何をいつ受け取るのか」を把握できます。

## ステップ 2 — どこで動くのかを理解する

Claude Science は macOS と Linux 向けのスタンドアロンアプリケーションで、**UI をブラウザに持つローカルデーモン**として動作します。Jupyter ノートブックと同じモデルですが、運転しているのはエージェントです。データのある場所ならどこにでもインストールします。ノート PC、ラボの Linux マシン、HPC ログインノード、自社テナントのクラウド VM。データ・計算環境・エージェントはそのマシンに留まり、デーモンがリモートで動いている場合、科学者は SSH トンネル経由でノート PC のブラウザから接続します。

より大きなハードウェアが必要なジョブは、同じセッションからラボの GPU マシン、SSH ホスト、SLURM クラスタ（SLURM は自動検出され、バッチディレクティブは自動生成されます）、ユーザーが用意したサーバーレス GPU アカウントへディスパッチされます。

エージェントは FASTQ ファイル、AnnData オブジェクト、Seurat オブジェクトなど任意のローカルフォルダに向けられ、S3・GCS・GitHub・機関の文献アクセスにネイティブ接続します。Conda と pip の環境はスペシャリストごとに管理され、セッション・カーネル・成果物は再起動をまたいで保持されます。

## ステップ 3 — 解析が説明可能になる理由を押さえる

成果物がレビューに耐えるのは、次の 5 つの設計上の選択によるものです。

1. **永続カーネル。** データセットは Python または R のカーネルに一度読み込まれ、以後は読み直しではなく探索の対象になります。さらにエージェントは自分のプロットも見ます。生成されたすべての図がエージェントのコンテキストに戻されるため、自分の出力に対して QC を行えます。
2. **すべての成果物に付く 4 層のプロベナンス。** 何をしたかの人間可読な説明、それを生成した正確な再現可能コード、そこに至った会話と推論、使用した全パッケージとバージョンのスナップショット。
3. **バックグラウンドレビューア。** 主エージェントが作業している間、別のレビューアエージェントがセッションのトランスクリプトを読み、証拠にたどれない主張を該当する文の位置にインラインで指摘します。既定で毎セッション実行されます。
4. **行動の前にプラン、見える権限。** 各タスクは承認待ちのステップバイステップのプランとして提示され、編集可能なチェックリストとして表示され続けます。新しいウェブサイトへのアクセス、フォルダのオープン、コード実行はそれぞれ承認カードを出し（今回のみ／このプロジェクトで／常に）、1 つの画面から確認・取り消しができます。その下には既定拒否のネットワーク egress を備えた OS レベルのサンドボックスと、13 種類のアクションを制御する人間承認ブローカーがあります。
5. **組み込みのバイオセキュリティ保護。** バイオセキュリティ規則はすべてのエージェントのシステムプロンプトに無条件で含まれ、ターンごとのバイオ・トラジェクトリ分類器がバイナリ内で動作し無効化できません。公開前に外部レッドチーミングと Anthropic Safeguards のレビューを完了しています。

## ステップ 4 — 基盤を整える

ローカルで動作するため、Foundation フェーズはクラウドテナントの構築ではなく、**正しいデータと計算資源のすぐ隣に置くこと**が主題になります。

- **デーモンホストのパターンを決め**、科学者がブラウザからそのホストに到達できることを確認します。
- **研究 IT にレビューしてもらう対象**: OS レベルのサンドボックス、既定拒否のネットワーク egress 許可リスト、コード実行・ファイルアクセス・リモート計算を制御する人間承認ブローカー。
- **アカウント設定**は他のサーフェスと同じ SSO と SCIM の作業に 1 ステップ加わります。管理者が Claude Science を有効化するまで、組織の誰もダウンロードもサインインもできません。Team プランでは管理設定 → capabilities。Enterprise プランでは Claude Science 権限を含むロールを作成してパイロットグループに割り当て、**その後**に機能を有効化することで、初日からアクセスをパイロットに限定できます。
- **ガバナンスは並行して。** NIH の管理対象データ、患者レベルデータ、ラボのマシンから出せないスポンサー IP を扱うグループでは、ローカルデーモンモデルこそが SaaS 製品では不可能な環境での導入を成立させます。ただし最初の科学者が管理対象データのフォルダを指す前に、品質・IT セキュリティ・データプライバシーがインストールの footprint、ネットワーク許可リスト、計算ディスパッチ先をレビューすべきです。
- **パイロットチームの選定**: すでに AI を推進している意欲的なリードがいて、解析比重が高く形の標準的な業務。計算生物学とバイオインフォマティクスのグループが自然な出発点で、同僚が自分では実行できなかった解析を回すのを見れば、ウェットラボの科学者と PI もすぐ後に続きます。

> **ヒント:** 最初のセッションが決め手です。ツールを開き、FASTQ ファイルのフォルダを指し、プランを承認して、コードと環境が下に記録されたクラスタリング済み UMAP を得た科学者は戻ってきます。手の届く場所にデータがない状態で開いた科学者は、そのまま閉じます。インストールは必ず実データの隣に落としてください。

## ステップ 5 — 定義した基準でパイロットを回す

この段階ではチャンピオンが実際のラボデータで実際の解析を行い、事前に定義した基準で測定します。

- **サイクルタイム** — 同じデータセットクラスで、以前はどれだけかかり、今はどれだけかかるか。
- **keep rate** — 科学者や PI が手作業でやり直さずに結果を信頼する頻度。
- **コールド再現率** — 1 週目の成果物のプロベナンスバンドルを 4 週目に別の科学者に渡し、何の助けもなく再実行できるか確認する。

**最も強い定性的シグナルは、チャンピオンが自分のスキルを保存し始めること**です。バイオインフォマティシャンがラボ内部の正規化パイプラインをラップして以後のすべてのセッションが継承するようにし、グループリードが LIMS API をラップする。これらのスキルがラボのカタログとなり、組織全体で共有できるようになります。

隣接サーフェスは通常このフェーズで立ち上がります。メディカルライティングとレギュラトリーは Cowork と Microsoft 365 アドインを、科学計算は下流の本番パイプライン向けに Claude Code を求めます。これらは科学パイロットの完了を待たせず、並行トラックとして進めてください。

> **ヒント:** パイロットチームとの週次チェックインを設定してください。コネクタが扱えないデータベーススキーマ、クラスタスケジューラの癖、ニッチなファイル形式に対応しないレンダラといったエッジケースは早く表面化し、カタログはまさにそれに応じて拡張できるよう設計されています。

## ステップ 6 — ガバナンスを先に固めてスケールする

パイロットで機能したスキルとスペシャリストを他のグループに展開し、研究 IT はラボ単位のインストールから管理されたデプロイパターンへ移行します。グループごとの標準デーモンホスト、検証済みネットワーク許可リスト、パイロットを種にしたキュレーション済みスキルカタログ、定義された計算ディスパッチ先の集合です。

計算生物学は構造を大きく共有しているため、スキルはグループをまたいで複利で積み上がります。腫瘍領域で作られたシングルセルのスキルは、免疫領域のスキルのほとんどを既に満たしています。新入メンバーは初日からゼロから作るのではなく、ラボにエンコードされたパイプラインから始められます。

スケールの**前に**決めるべきこと:

- カタログの各スキルを誰が所有するか、
- 作成者のグループを越えて共有する前にスキルをどう QC するか、
- 規制提出や論文につながる解析のプロベナンスバンドルをどう保持するか、
- グループが新しい外部データベースを要求したときにネットワーク許可リストをどうレビューするか。

> **ヒント:** 規制提出や論文につながる解析では、4 層のプロベナンスバンドルを管理記録として扱ってください。説明・コード・会話・環境スナップショットを合わせたものが、レビューア、監査人、ジャーナルが見たいものです。どこに、どれだけの期間保管するかを合意しておきましょう。

## フェーズ要約

| フェーズ | アクション | 見えてくるもの |
|---|---|---|
| **Foundation** | ローカルインストール・サンドボックス・ネットワーク許可リストに対する IT とデータガバナンスのレビュー。デーモンホストのパターン決定。計算生物学またはバイオインフォマティクスで 2〜3 のチャンピオングループを特定。SSO/SCIM とプランの確認。 | チャンピオンからユースケースが返ってくる。「これは 3 週間かかっていた仕事だ」という最初の瞬間。 |
| **Pilot** | チャンピオンが実際のラボデータで実解析を実施。週次チェックイン。サイクルタイム・keep rate・コールド再現率を測定。隣接する文書系機能のために Cowork と M365 を並行で立ち上げ。 | 測定可能な時間削減。チャンピオンが独自スキルやスペシャリストを保存。計算系リードの後にウェットラボ科学者と PI が参加。 |
| **Scale** | 管理されたデーモンホストパターン。キュレーション済みの組織スキルカタログ。検証済み許可リストと計算ディスパッチ先。規制・論文向け解析のプロベナンス保持ポリシーの合意。次の波のグループをオンボード。 | 治療領域をまたいだスキル共有。新入メンバーがエンコード済みパイプラインで立ち上がる。バイオインフォマティクスコアへの「これ回してもらえますか」依頼の減少。 |

## 現場の例

- **Novo Nordisk** は Claude を基盤とした生成 AI プラットフォーム NovoScribe を構築し、治験総括報告書、機器検証プロトコル、患者向け資料の作成を自動化しました。以前は 10 週間以上かかっていた臨床文書が、いまはおよそ 10 分でレビュー可能な初稿に到達します。「Claude のおかげで CSR の執筆時間を 90% 削減でき、文書を直接人の手に渡してレビューと承認を受けられるようになりました。」— Waheed Jowiya, Digitalization Strategy Director, Novo Nordisk
- **Garvan Institute of Medical Research** は研究・運営・管理の全般で Claude を採用し、20 名を超えるソフトウェアエンジニアとデータサイエンティストが、創薬研究、遺伝子バリアントを解釈するマルチエージェントシステムによる希少疾患診断、ゲノミクスプロジェクトのデータ解析にエージェント型開発ツールを使用しています。「Claude Code は、科学者としてもリーダーとしても私の働き方を完全に変えました。」— Daniel MacArthur, Professor, Garvan Institute
- **Sanofi** は社内アプリケーション Concierge に Claude を全社導入し、バリューチェーン全体で従業員の大多数が日常的に利用しています。

## 先に伝えるべき既知の制約

ガイドは境界を明示しています。これを早い段階で示すことが、答えの出ていないコンプライアンス上の問いでパイロットが止まるのを防ぎます。

- 研究用途のみであり、**臨床・診断の意思決定向けには設計されていません**。
- GxP に対する**バリデーション済みシステムではありません。** 研究・解析・下書き支援の役割で導入し、バリデート済み記録・申請・論文に入る前に有資格のレビューアがすべての出力を承認してください。
- **リリース時点で HIPAA 対応ではありません。** 対応はリリース後のロードマップ項目です。
- NIH のアクセス制限データセットは通常、解析環境そのものが NIST SP 800-171 の統制を満たすことを要求しますが、本製品はまだその基準に対する評価を受けていません。
- **Windows は非対応**で、エンドポイントへのインストールは署名済みのユーザー空間デーモンとブラウザ UI のみ、カーネルコンポーネントはありません。
- **Amazon Bedrock、Google Vertex AI、Microsoft Foundry 経由では提供されません。**
- **Zero Data Retention は適用されません。** セッション・成果物・プロベナンスバンドルの保存が機能に必要なステートフル製品だからです。ZDR は承認済み顧客向けに Claude Platform と Claude Code で利用できます。
- 利用は**トークン集約的**で、ヘビーユーザーは Max ティアの上限が必要になる場合があります。別途ライセンスや無料枠はなく、既存プランの利用量から差し引かれます。
- 公開データベースや第三者リソースは独自のライセンスに従い、商用利用の適合性確認は組織の責任です。
- ロードマップ項目は変更される可能性があり、コミットメントを意味しません。
