# 프로덕션에서 auto mode 운영하기: Nuro, Gusto, Garner Health의 패턴

출처: https://claude.com/blog/auto-mode-in-production (2026년 8월 7일)

## auto mode가 해결하는 트레이드오프

auto mode는 이제 Claude Code의 기본 설정입니다. 에이전트가 실행하려는 모든 명령을 승인하라고 요구하는 대신, 분류기(classifier)가 각 동작을 평가해 잠재적으로 유해해 보이는 것을 차단합니다.

이 설계는 에이전틱 코딩에서 흔한 트레이드오프를 해소합니다.

- **모든 명령을 검토하면** 사람이 루프 안에 남습니다. 하지만 세션이 몇 시간씩 이어지거나 병렬로 늘어나면 그 감독 자체가 병목이 됩니다.
- **권한 검사를 아예 건너뛰면** 더 빠릅니다. 그리고 바로 그 경로로 프롬프트 인젝션, 범위 이탈, 이따금 발생하는 프로덕션 리소스 삭제가 통과합니다.

내부 평가에서 분류기는 개발자가 직접 권한 프롬프트를 클릭해 넘길 때보다 더 많은 위험 동작을 잡아냈고, 외부 레드티밍에서도 성능이 유지됐습니다. 세션이 덜 멈추기 때문에, 전체 Claude Code 사용 기준으로 Claude는 이전 기본값 대비 중단 사이 **9배 더 오래** 작업합니다.

## Nuro — 더 오래 도는 자율 에이전트

범용 레벨 4 자율주행 기술을 개발하는 피지컬 AI 기업 Nuro는 2025년 말 Claude Code를 도입했고, 3월에는 사내에서 가장 많이 쓰이는 에이전틱 코딩 도구가 됐습니다.

**auto mode 이전의 문제.** 스태프 소프트웨어 엔지니어 Kai Zhou는 사내 대체물을 프로토타이핑했습니다. 대기 중인 각 동작을 작은 모델에 보내 90% 정도의 일상적인 작업은 자동 승인하고, 민감한 것은 Slack으로 보내 사람이 검토하게 하는 훅이었습니다. 이는 실제 긴장을 반영한 것이었습니다. 엔지니어들은 승인 프롬프트를 지켜보는 일을 싫어했지만, 회사의 보안·법무 관점에서 권한 검사를 통째로 건너뛰는 것은 승인하기에 너무 위험했습니다. auto mode가 출시되자 Kai는 이 사이드 프로젝트를 접었습니다.

**지금의 운영 방식.**

- 자기가 작성하는 모든 코드에 auto mode를 사용합니다. "제 코딩 작업의 100%에 auto mode를 씁니다. 대개 auto mode 세션을 3~4개 병렬로 열어 두고 필요할 때만 들여다봅니다."
- **예외는 다른 팀과 맞닿는 작업입니다.** Claude Code가 자신을 대신해 PR을 리뷰할 때는 인터랙티브 모드로 돌아가 하나씩 검토한 뒤 내보냅니다.
- **제약 없이 도는 것도 아닙니다.** Nuro는 스킬을 적극 활용하고, 엔지니어들은 재귀 삭제 같은 가장 위험한 명령을 설정에서 아예 deny로 막습니다. 분류기는 그 가드레일 안에서 판단합니다.

**더 큰 이득은 엔지니어가 퇴근한 뒤에도 계속 도는 작업입니다.** Kai의 팀은 자율주행 스택의 평가 지표를 개선해 나가는 장시간 리서치 에이전트를 auto mode로 돌립니다. 에이전트가 스스로 반복 개선할 수 있는 명확하고 측정 가능한 신호가 있는 작업들입니다. 밤사이 에이전트는 평가 스위트가 표시한 false negative를 분석하고, 제안서를 작성하고, 실험을 돌리고, 결과를 바탕으로 계속 반복합니다. 이 접근은 명확한 평가 방법이 있는 모든 작업으로 확장됩니다. 지표 자체가 나아지고 있는지 후퇴하고 있는지 에이전트에게 알려 주기 때문입니다. Nuro의 다른 팀은 특정 바이너리의 메모리 사용량을 줄이는 데 이를 활용합니다.

> "얼마 전에 밤 10시에 에이전트를 시작했는데 새벽 5시까지 계속 돌았고, 아침에 PR 세 개를 줬습니다. 꽤 인상적이라고 생각합니다. 이런 워크로드는 auto mode에서만 가능합니다."

## Gusto — 더 빠르고 안전하게 PR 내기

선도적인 SMB 기술 기업 Gusto에서 auto mode 전환은 선제적인 보안 업그레이드로 시작됐습니다.

**AI Dev Tools 팀의 Martin Emde.** 그는 권한 피로가 팀을 늦추는 것을 지켜봤습니다. auto mode는 통제나 보안을 희생하지 않고 같은 속도를 제공했고, 엔지니어링 전반에 도입이 자리 잡은 뒤 전체 권한 부담이 눈에 띄게 줄었습니다.

- 12월 이후 2,425개의 Claude Code 세션을 auto mode를 주력으로 실행했습니다.
- 예전에는 폴더 접근 승인에서 멈추던 크로스 레포 작업이 이제 중단 없이 돕니다.
- GitHub, Slack, Jira에서 일일 노트를 취합하는 것 같은 무인 작업이 스스로 실행됩니다.
- 2026년 5월 중순 이후 **세션 트랜스크립트의 약 10%에 auto mode 차단이 포함**됐습니다. 정당한 작업을 지연시키지 않으면서 분류기가 실제로 일하고 있다는 근거입니다.

> "auto mode는 속도와 통제 사이에서 더 안전한 균형을 줬습니다. 반복되는 프롬프트를 없애고 안전을 해치지 않으면서 생산성을 높일 수 있었습니다. auto mode가 적절한 시점에 차단하는 것이 보이기 때문에 빠르게 움직일 자신감이 생깁니다."

**AIT Cloud Engineering 팀의 Chad Kunsman.** 그는 반대 방향에서 같은 결론에 도달했습니다. 엔드포인트 조사, 로그 감사, 커넥터 관리, 여러 MCP 서버에 걸친 문서 인제스트 같은 그의 작업은 야간 마라톤이 아니라 20분 단위의 짧은 작업입니다. 그는 더 긴 실행을 원한 것이 아니라, 잘못된 프롬프트나 프롬프트 인젝션이 빠져나갈 위험 없이 bypass permissions의 손 놓는 속도를 원했습니다.

> "프롬프트 인젝션에 대한 보호, 그리고 내가 하는 일이 실제로 요청한 것과 맞는지 확인해 준다는 점을 감안하면, bypass permissions보다 나은 선택이고 권한 프롬프트보다 훨씬 빠릅니다."

분류기가 개입하는 드문 경우에도 정확하다고 그는 말합니다. "저를 멈춰 세웠을 때 이유가 납득됐고 설명도 해줬습니다. 원래 요청에서 벗어나고 있었고, 그래서 확인을 요청한 것이었습니다. 전혀 엉뚱하지 않았습니다."

**그가 빠져나오는 지점.** 세션이 프로덕션 인프라(Terraform, AWS, 라이브 API에 대한 직접 POST 호출)에 깊이 들어가면 accept edits로 전환해 도구 호출을 하나씩 직접 확인합니다. "절약하는 시간과, 에이전트가 실수할 법한 지점과, 그 실수가 얼마나 치명적일지를 저울질해야 합니다. 결국 무슨 일이 일어나든 책임은 여전히 본인에게 있습니다."

이 판단은 더 넓은 다층 방어 구성 안에서 이뤄집니다. Gusto는 MCP 트래픽을 도구 가드와 프롬프트 검사를 갖춘 거버넌스 프록시 계층으로 라우팅해, auto mode가 판단하기 전에 에이전트가 이미 좁게 제한된 권한으로 동작하게 합니다.

## Garner Health — 소프트웨어 개발 수명주기(SDLC) 가속

헬스케어 기술 기업 Garner Health는 2월에 전 직능 550명 직원 전체에게 Claude Code를 배포했습니다. Salesforce, Zendesk, Snowflake를 포함한 핵심 시스템에 연결돼 있고, 직원들은 업무 중 가장 반복적인 부분을 자동화하는 데 주당 약 2시간을 쓰도록 권장받습니다.

**auto mode 이전에는** 이 규모에 오버헤드가 따랐습니다. 플랫폼 엔지니어링 매니저 Evan Magnussen은 권한 관리를 승인 명령 목록을 손으로 관리하고 파이프 명령이 거부되는 것을 지켜보는 지루한 반복이라고 설명합니다.

**지금은** Evan과 동료 대부분이 코드베이스 조사부터 MCP를 통한 외부 통합 관리까지 모든 세션에서 auto mode를 사용합니다.

> "auto mode 덕분에야 비로소 가능해진, 엔지니어링 조직 전체를 위한 표준 소프트웨어 개발 수명주기를 구축했습니다. 직원들은 어깨의 짐을 던 것으로 받아들입니다. 몇 시간씩 에이전트를 지켜볼 필요가 없어졌으니까요."

**이 수명주기는 표준화된 스킬 플러그인으로 돌아갑니다.** 에이전트가 작업을 맡고, 접근 가능한 컨텍스트를 탐색하고, 컨텍스트 파일을 저장소에 커밋하고, Evan이 "antagonistic research"라고 부르는 자기 가정 압박 검증을 수행한 뒤 구현으로 넘어갑니다. 스스로 찾을 수 없는 컨텍스트가 필요할 때만 사람을 기다립니다. Evan은 리서치 비중이 큰 단계들이 auto mode 이전에는 불가능했다고 말합니다.

**튜닝.** 기본 상태에서 분류기는 튜닝이 거의 필요 없었습니다. Evan의 유일한 조정은 Nuro의 Kai와 같습니다. Slack 메시지나 이메일 발송처럼 다른 사람과 소통하는 동작은 auto mode가 승인하지 않도록 설정했습니다. "다른 사람과 소통할 때 Claude가 제 대신 그냥 행동해 버리는 것은 개인적으로 좋아하지 않습니다." 핵심 지식재산을 다루는 팀들은 — auto mode 이전에는 권한 건너뛰기에 가장 회의적이었던 팀들이 — 자기 업무에 맞게 분류기에 주입되는 프롬프트를 더 허용적이거나 덜 허용적으로 조정하는 법을 익혔습니다.

**다른 기업을 위한 조언.** 적극적으로 받아들이되, 엔지니어에게 권한을 주면서도 안전한 배포를 보장할 수 있도록 제대로 된 통제 수단을 만들라는 것입니다. "모두에게 각자 워크플로를 만들라고 하면서 텔레메트리가 없다면 그건 매우 위험할 것입니다. 텔레메트리가 있고, 비교적 표준화된 워크플로를 구축해 두었기 때문에 훨씬 더 확신을 가질 수 있습니다."

## 따라 할 만한 패턴

1. **먼저 설정에 하드 가드레일을 세운다.** 분류기는 여러분이 정한 한계 안에서 판단할 뿐, 그 한계를 대신하지 않습니다.
2. **분류기가 보기 전에 도구를 제한한다.** 도구 가드와 프롬프트 검사를 갖춘 거버넌스 MCP 프록시가 있으면 에이전트는 이미 좁게 제한된 권한을 쥐고 있습니다.
3. **기본으로 좁은 튜닝 하나를 적용한다.** 다른 사람과 소통하는 동작은 자동 승인하지 않습니다. 세 팀 중 두 팀이 독립적으로 같은 결론에 도달했습니다.
4. **어떤 세션이 빠져나올지 미리 정한다.** 내 경계를 벗어나는 작업, 그리고 프로덕션 인프라입니다.
5. **작업 형태를 무인 실행에 맞춘다.** 명확하고 측정 가능한 평가 신호가 있어야 에이전트가 밤새 반복할 수 있습니다. 산출물은 병합된 변경이 아니라 검토용 완성 PR입니다.
6. **워크플로를 표준화한 뒤 계측한다.** 텔레메트리는 후속 과제가 아니라 전사 배포를 정당화하는 전제 조건입니다.
7. **차단율을 지켜본다.** 세션의 약 10%에 차단이 포함된다면, 정당한 작업을 막지 않으면서 분류기가 실제로 일하고 있다는 신호로 읽힙니다.
