## この記事について
Claude Code の **auto モード**を本番の日常既定として運用している 3 社の事例です。**Nuro**、**Gusto**、**Garner Health**。auto モードはコマンドごとの承認プロンプトの代わりに、各操作を評価して有害になりうるものをブロックする分類器（classifier）を使います。記事はこれを、エージェンティックコーディングにおける速度と安全のトレードオフに対する答えとして位置づけます。すべてのコマンドをレビューすれば人が判断のループに残りますが、セッションが数時間に及んだり並列に増えたりすると、その監督自体がボトルネックになります。逆にパーミッション確認を丸ごと省くと、プロンプトインジェクション、スコープの逸脱、本番リソースの削除がそのまま通ってしまいます。

Claude Code 全体の利用で見ると、Claude は従来の既定に比べて中断と中断の間に **9 倍長く**動作します。

## どんなときに役立つか
- auto モードをチームや全社の既定にするかを判断する際に、機能説明ではなく具体的な運用パターンが必要なとき。
- auto モードを取り囲むガードレール（deny ルール、分類器のチューニング、MCP のプロキシ、テレメトリ）を設計するとき。
- 実務者が意図的に auto モードから*抜ける*場面を知りたいとき。
- 長時間・夜間のエージェントを作るにあたり、無人実行に本当に向くタスクの形を探しているとき。

## 主なポイント
- **auto モードはガードレールの代わりではなく、その内側で動きます。** Nuro のエンジニアは再帰削除のような最も危険なコマンドを設定で明示的に deny し、分類器はその枠の中で判断します。Gusto は MCP トラフィックを、ツールガードとプロンプト検査を備えたガバナンス付きプロキシ層に通し、auto モードが判断する前にエージェントが厳しく絞られた権限で動くようにしています。
- **効いているのは 1 ステップの速さではなく、無人で走り続けられる時間です。** Nuro は自動運転スタックの評価指標を少しずつ改善していく夜間リサーチエージェントを走らせています。あるエンジニアは午後 10 時にエージェントを起動し、朝には 3 本の PR を受け取りました。このパターンは、エージェントが自力で反復できる明確な評価シグナルがあるタスク全般に一般化でき、Nuro の別チームは特定バイナリのメモリ使用量削減に使いました。
- **短いセッションにも効きます。** Gusto のあるクラウドエンジニアは 20 分程度の短い作業（エンドポイント調査、ログ監査、コネクタ管理、複数 MCP サーバー越しのドキュメント取り込み）を行っており、長時間実行のためではなく、プロンプトインジェクションへの防御と意図の一致確認のために bypass permissions ではなく auto モードを選びました。
- **分類器は実際に仕事をしています。** Gusto 自身の分析では、2026 年 5 月中旬以降のセッションのトランスクリプトの約 10% に auto モードの拒否が含まれていました。あるエンジニアは 12 月以降 2,425 セッションを auto モードで走らせています。
- **それでも実務者は意図的に抜けます。** Nuro の Kai は、Claude Code が自分の代わりにプルリクエストをレビューするときはインタラクティブモードに戻します。Gusto の Chad は Terraform、AWS、稼働中 API への直接 POST を扱うときは accept edits に切り替えます。「結局、何が起きても責任を負うのは自分だ」というわけです。
- **チューニングは最小限だが的を射ています。** Garner Health の唯一の調整は Nuro と同じで、Slack メッセージやメールの送信のように他人とコミュニケーションする操作を auto モードが承認しないよう設定しています。
- **auto モードが標準化された SDLC の前提になることもあります。** Garner Health は全従業員 550 名に Claude Code を展開し、Salesforce、Zendesk、Snowflake に接続したうえで、標準化されたスキルのプラグインとして開発ライフサイクルを回しています。文脈を探索し、コンテキストファイルをリポジトリにコミットし、自らの前提を突き崩す「antagonistic research」を行い、それから実装へ進む。自力で見つけられない文脈が必要なときだけ人を待ちます。リサーチ比重の高い工程は auto モード以前には不可能でした。
- **テレメトリこそが実現条件です。** 企業向けの Garner の助言は、まずワークフローとテレメトリを整えること。「全員それぞれ好きにワークフローを作れと言って、テレメトリがなかったら、それはとても危険でしょう」。
