## 이 글이 뭔가요
Claude Code에서 베타로 제공되는 새 프로젝트 경험을 알리는 글입니다(2026년 9월 17일). 목표를 설명하면
코디네이터가 여러 스레드에 걸쳐 작업을 관리하므로, 사용자가 직접 작업을 나누고 인계하고 결과를 병합할
필요가 없습니다.

## 언제 유용한가요
- 여러 저장소나 병렬 하위 작업에 걸친 장기·다단계 작업을 할 때.
- 개별 프롬프트가 아니라 결과("결제 p75 지연 시간 줄이기" 등)를 위임하고 싶을 때.
- 프로젝트를 어떻게 구성·조정하고 사용량을 관리할지 정할 때.

## 핵심 포인트
- 목표와 저장소(또는 컨텍스트)로 시작하고 환경, 커넥터, 플러그인, 지시문, 모델을 설정합니다.
- 코디네이터에게 비서실장에게 하듯 브리핑하면, 새 스레드나 기존 스레드로 작업을 배분합니다.
- 각 스레드는 자체 브랜치와 저장소 사본을 가진 Claude Code 클라우드 세션입니다. PR을 열고 테스트를
  돌리며, 겹치는 변경은 일반 머지 충돌로 해결합니다. 서브에이전트, 루프, 워크플로도 쓸 수 있습니다.
- 스레드 간 공유 메모리와 파일·아티팩트 라이브러리가 있고, 확인 빈도·스레드 생성·업데이트 상세도를
  조정할 수 있습니다.
- 휴대폰에서도 조정할 수 있고, 자리를 비워도 작업이 계속됩니다.
- 병렬 스레드로 사용량 한도에 더 빨리 도달할 수 있어, 프로젝트별 사용량과 역할별 모델·노력 수준을
  설정할 수 있습니다.
- 먼저 일부 Pro/Max 클라우드 세션 사용자 대상 베타이며, 로컬 스레드는 "곧" 제공될 예정입니다.
