## この記事について
Claude Code でベータ提供される新しいプロジェクト体験の発表記事です(2026年9月17日)。目標を伝えると
コーディネーターが複数のスレッドにまたがって作業を管理するため、タスクの分割、引き継ぎ、結果のマージを
自分で行う必要がなくなります。

## どんなときに役立つか
- 複数のリポジトリや並列サブタスクにまたがる長期・多段階の作業をするとき。
- 個々のプロンプトではなく成果(例:「チェックアウトの p75 レイテンシを下げる」)を委任したいとき。
- プロジェクトの設定・舵取りと使用量の管理方法を決めるとき。

## 主なポイント
- 目標とリポジトリ(またはコンテキスト)から始め、環境、コネクタ、プラグイン、指示、モデルを設定します。
- コーディネーターには首席補佐官に頼むように説明し、新規または既存のスレッドにタスクを振り分けさせます。
- 各スレッドは独自のブランチとリポジトリのコピーを持つ Claude Code クラウドセッションです。PR を作成して
  テストを実行し、重複する変更は通常のマージコンフリクトとして解決します。サブエージェント、ループ、
  ワークフローも使えます。
- スレッド間の共有メモリと、ファイル・成果物のライブラリがあり、チェックイン頻度、スレッド作成、
  更新の詳しさを調整できます。
- スマートフォンからも舵取りでき、席を外しても作業は続きます。
- 並列スレッドにより使用量の上限に早く達することがあり、プロジェクト別の使用量と役割別のモデル・
  エフォートを設定できます。
- まず一部の Pro/Max クラウドセッション利用者向けベータで、ローカルスレッドは「まもなく」提供予定です。
