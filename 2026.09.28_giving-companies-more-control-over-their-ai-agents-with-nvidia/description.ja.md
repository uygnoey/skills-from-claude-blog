## この記事について
NVIDIA の Open Agent Safety Platform 発表に合わせて、Anthropic と NVIDIA がエージェントスタックにセキュリティと
制御の層を加える方法を紹介した発表記事です。Claude Managed Agents はすでにサンドボックスで作業を実行しており、
セルフホスト型サンドボックスで実行を自社の境界内に置き、NVIDIA OpenShell がそのサンドボックス内でエージェントが
アクセスできる範囲と行動をポリシーで制御します。

## どんなときに役立つか
- エージェントがリポジトリのクローン、Web サイトの閲覧、ツール出力の解析、パッケージのインストールを行うとき
- コードとデータを企業・規制の境界内にとどめる必要があるとき
- エージェントに必要な最小権限を定義し、証明したいとき

## 主なポイント
- サンドボックスに入る信頼できないコンテンツには、プロンプトインジェクションや実行されるコードが含まれ得ます。
- 「頭脳」と「手」を分離します。ハーネス、セッション状態、認証情報はサンドボックス外の永続的なインフラに置き、
  サンドボックスは実行用ツールとしてのみ使います。
- セルフホスト型サンドボックス：エージェントループ（オーケストレーション、コンテキスト管理、エラー回復）は
  Anthropic のインフラに残り、各セッションのツール呼び出しは自社インフラまたはマネージドサンドボックス
  プロバイダーで実行されます。
- NVIDIA OpenShell はルールが許可しない限りすべてをブロックし、ツール使用ごとに検査し、ファイル・ネットワーク・
  データにルールを適用します。ルールはエージェントの外で強制され、すべての許可・拒否が記録されます。
- 狭い権限から始めてログを確認し、Claude でルールを絞り込みます。OpenShell の policy prover は数学的証明で
  エージェントが到達できる範囲を確認します。
- 事例：Clay の Sculptor（外部ファイルストアのマウント、パッケージの即時インストール）、Rogo（規制業界向けの
  隔離 microVM）。
- Managed Agents はパブリックベータ、OpenShell は Apache 2.0 のオープンソースです。
