# 本番エージェントのための機能選択

2026-08-20 をもって、コンピュータ使用（computer use）、Skills API、Files API が
Claude Platform で一般提供（GA）となり、コンピュータ使用には新しいブラウザ使用
（browser use）ツールが加わった。本ガイドは、それらをどう選び分けるかを扱う。

## このリリースが答える三つの問い

実務をこなすエージェントには、モデルのほかに通常三つが必要になる。

1. **API のないソフトウェアを操作する手段。** → コンピュータ使用、ウェブでは
   ブラウザ使用ツール。
2. **チームの専門性を実行に持ち込む手段。** → Skills API。
3. **複数ターンにわたって文書を保持し、完成した成果物を返す手段。** → Files API。

すでに一般提供されていたコード実行とウェブ検索も、同じループに収まる。

## ソフトウェアを操作する

**コンピュータ使用**は、見えているソフトウェアを操作するエージェントを作る。
スクリーンショットを与えられると、エージェントはキーボードの前にいる人と同じように
クリックし、入力し、スクロールする。それこそが、自動化を前提に作られていない
アプリケーションでも動作する理由だ。

今回新たに加わった**ブラウザ使用ツール**は、これをウェブへ拡張する。スクリーン
ショットに加えてエージェントがページの構造を読み、画面上の位置ではなく特定の
フィールドやボタンを対象に動作する。

判断の順序:

| 状況 | 選択 |
| --- | --- |
| 実際の API がある | API を使う — 安く、速く、決定論的 |
| ウェブアプリケーション、API なし | ブラウザ使用ツール |
| デスクトップなど非ブラウザ画面、API なし | コンピュータ使用 |

両ツールとも、モデル呼び出しごとに1アクションではなく**1ターンで複数アクション**を
実行するようになり、より少ない呼び出しと短い時間でタスクが完了する。

**なぜピクセルより構造か。** 名前のある要素を対象にすれば、レイアウトの変化、解像度
の違い、コントロールを数ピクセル動かす再レンダリングに耐えられる。ウェブでは構造
ベースの経路が信頼性の向上そのものであり、複数アクションのターンを手放す必要もない。

## 専門性を持ち込む

**スキル**とは、指示・スクリプト・テンプレートを収めたフォルダであり、タスクが必要
としたときにのみ Claude が読み込む。Skills API を使えば、自分のスキルをアップロード
してバージョン管理し、任意のリクエストに添付できる。スキルは Claude のコード実行
サンドボックスで動くため、自前でホストするものはない。

この形から三つのことが導かれる。

- **オンデマンドで読み込まれる。** 符号化した専門性が、毎リクエストのプロンプト
  スペースを奪い合う必要がない。
- **バージョン管理される。** 手順が、呼び出す側のアプリケーションコードとは別に
  独自の変更履歴を持つ。前四半期に誰かが編集したプロンプト文字列と、バージョンの
  付いた成果物との違いである。
- **スキルがカスタマイズ面になる。** Box の事例が最も分かりやすい。ワークフローごと
  に専用エージェントをゼロから作るのではなく、一つの Box Agent に、各社の与信
  メソドロジーと承認済みメモ形式を収めたスキルを添える。

## 文書を保持する

**Files API** は、エージェントが読み書きする文書のストレージだ。PDF やスプレッド
シートを一度アップロードし、以降のリクエストでは送り直す代わりに ID で参照し、
エージェントが作成したファイルをダウンロードする。GA では、ファイルの自動失効、
5倍に引き上げられたレート制限、組織あたり 1 TB のストレージが加わった。

設計を変えるのは ID 参照である。複数ターンのワークフローが毎リクエストで同じ元
文書を再送しなくなり、成果物はレスポンステキストから切り出すものではなく、取得する
成果物になる。

## 組み合わせたループ

発表にある例 — 保険金請求エージェント:

1. Files API から受付文書を読む。
2. チームの申請手順を符号化したスキルに従う。
3. ブラウザ使用ツールで保険会社のウェブポータル上の提出を完了する。
4. 確認書をファイルとして保存し直す。

自分のエージェントも、同じ四つの問いを順に辿ってスコープを決めればよい。何を読むか、
誰の手順に従うか、どのソフトウェアを操作する必要があるか、何を返すか。

## 報告された結果

- **API のない医療・保険システム。** 新しいコンピュータ使用ツールで、あるチームの
  最長の請求ワークフローが32分から13分になり、テストしたすべてのワークフローで
  タスクあたりコストが約30%低下し、完了率は100%に達した。プロンプトの変更は一切
  なかった。
- **Box。** 銀行の与信メソドロジーと承認済みメモ形式をスキルが収め、Box Agent が
  それを Box にすでにある財務諸表やディール文書に適用して、アナリストレビュー用の
  出典に基づく与信メモを作成する。

二つ目の事例の境界に注目したい。出力は*アナリストレビュー用*である。誤りがそのまま
コンプライアンス事案になる領域では、エージェントの仕事はレビュー可能な成果物までだ。

## 提供状況

| 環境 | 状態 |
| --- | --- |
| Claude Platform | コンピュータ使用、ブラウザ使用ツール、Skills API、Files API |
| Microsoft Foundry | Skills API と Files API |
| Google Cloud Vertex AI | 更新版のコンピュータ使用およびブラウザ使用ツールは近日提供 |

コンピュータ使用は、Anthropic の BAA のもとで HIPAA 規制対象ワークロードに利用でき
るようになった。既存のベータ統合は移行中もそのまま動作する。開始にあたっては、
コンピュータ使用、ブラウザ使用ツール、Skills API、Files API のプラットフォーム
ドキュメントを参照のこと。
