## この記事について
**Claude Code の既定のパーミッションモードが auto モードになる**という発表です。2026 年 8 月 14 日以降、Pro・Max・Team プランの新規セッションは auto モードで開始します。ツール呼び出しごとに承認を求める代わりに、auto モードはすべてのツール呼び出しを分類器（classifier）に通し、取り消しできない・破壊的・ユーザーの環境の外に向かう操作をブロックします。分類器が何かを止めたとき、Claude はたいてい自力でより安全な方法を見つけるか、ユーザーに直接確認します。前に進めない場合（3 回連続のブロック、または 1 セッションで 20 回）、Claude Code は手動承認に切り替わります。

記事では変更の根拠となった安全性データも公開しています。社内レッドチーミング、Apollo Research による第三者レッドチーミング、Trajectory Labs によるプロンプトインジェクション評価、有償テスター 1,053 名を対象とした対照実験、そして安全パイプラインがフラグを立てた実運用セッションの分析です。分類器のトークンオーバーヘッドは Pro・Max・Team プランでは課金されなくなりました。Claude Enterprise、Claude API、AWS 上の Claude Platform、Amazon Bedrock、Google Cloud の Agent Platform、Microsoft Foundry では当面オプトインのままです。

## どんなときに役立つか
- auto モードを既定にするか、別の既定を固定するかを判断するとき。
- 管理者が、変更がユーザーに届く前に組織全体の展開、あるいは意図的なオプトアウトを計画するとき。
- 社内でこの変更を説明するために、数値・方法論・その限界を含む安全性の根拠が必要なとき。
- auto モードでどのパーミッションルールが引き続き効き、どれが保留されるかを知りたいとき。

## 主なポイント
- **手動レビューは習慣化する。** ユーザーはパーミッションプロンプトの 97% を承認し、拒否は 3% のみ。一方、Claude が計画を提示した場合の拒否率は 39% です。2026 年 6 月時点で、アクティブな CLI ユーザーの 49.5% が Bash の allow ルールを手書きしており、62% が `bypassPermissions` または Bash の「今後確認しない」を使い、インタラクティブセッションの 25% が bypass permissions モードで開始しています。
- **対照実験。** 有償テスター 1,053 名のうち、人間が危険なコマンドを止めたのは 13.6%（1,053 件中 143 件）、auto モードは 89%（1,053 件中 937 件）をブロックしました。直接比較では、auto モードは人間が承認した 800 件をブロックし、人間が auto モードの許可を止めたのは 6 件だけでした。セッションが長くなるほど人間の検出率は下がり（序盤 約 17%、プロンプト 50 回以降 約 5%）、auto モードは横ばいでした。
- **実運用セッション。** 2026 年 5〜6 月にフラグが立ったセッションのうち、ユーザーが明示的に依頼していない本番相当（深刻度 7 以上）の有害な操作を含んでいたのは、手動承認セッションで 6.3%、auto モードセッションで 2.4% でした。
- **Apollo Research のレッドチーミング**により、分類器の見逃し率は 12% から 7% に低下し、その強化はアクセスできないホールドアウト攻撃セットにも一般化しました。
- **プロンプトインジェクション。** Trajectory Labs の評価（72 シナリオ × 10 回）では、auto モードで動作する Fable 5・Opus 5・Sonnet 5 に対する 720 回の試行はすべて失敗しました。Codex の Auto-review モードの GPT-5.6 Sol では 5.83%、Full Access モードでは 19.03% が成功しました。
- **パーミッションルールは引き続き分類器より先に適用されます。** ただし任意コード実行を許すほど広範な allow ルール（例: `Bash(python:*)`）は分類器を素通りさせてしまうため、auto モード中は保留されます。設定ファイル自体は変更されません。
- **最近の強化**: データ持ち出しに対するハードデナイ（設定でルールを追加可能）、シークレットと機微情報を区別する明示的なルールと、git push や PR の宛先が公開・非公開・信頼済みのどれかを確認する仕組み、破壊的な git コマンドの前の git status 確認、外部コンテンツに対する API 側のプロンプトインジェクション検査。
- **本番での成果**: Teams・Enterprise の導入企業では、auto モード利用者の PR 数が約 25% 多くなっています。Adobe、Nuro、Gusto、Garner Health が本番既定として利用しています。
- **操作方法**: CLI では `Shift+Tab`、デスクトップアプリではモードのドロップダウンで切り替え。managed settings の `defaultMode` で組織既定を固定、`disableAutoMode` で完全に無効化できます。
- **記事が示す限界**: auto モードは分類システムに依存しており、リスクをなくすものではありません。本番インフラへの重大な変更については、Claude の操作を自分で確認することが推奨されています。
